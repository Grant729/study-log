## 5. R07（下一套）

### 5.1 核心目标
R06 已把 #4 的**直接形态**打穿（6 处全对）。R07 主攻 R06 暴露的三个新洞：

1. **#26 条件计数**：LEFT JOIN 后统计"满足条件的记录数"，必须 `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`；用 `WHERE` 会把零组删掉。
2. **#27 子查询方向**："没有/从未" → `NOT EXISTS`，别再写成 `EXISTS`。
3. **#25 / #28 概念**：三级模式（视图=外模式）与 1:1 转换（外码 + `UNIQUE NOT NULL`）。
4. 附带：NULL 系列保持（#23 已修，防复发）。

### 5.2 题目设计（R06 已用过的外壳，R07 换新）
1. **LEFT JOIN + 计数**：数订单、数评论、数选修、数就诊——每次逼用户在 `COUNT(*)` / `COUNT(列)` 之间选。
2. **LEFT JOIN + HAVING COUNT**：`HAVING COUNT(*) > 1` vs `HAVING COUNT(列) > 1`，结果不同。
3. **`SUM(CASE WHEN ... THEN 1 ELSE 0 END)`**：什么时候必须用它而不是 `COUNT`。
4. **NULL 系列**：`NOT IN + NULL`、`IN + NULL`、`SUM` 空集、`= NULL` vs `IS NULL`、`NOT EXISTS` 对比。
5. **综合题**：纯文字业务描述（新案例，可埋干扰信息）→ ER → 关系模式（主码/外码）→ 建表 SQL；**必须包含一个"主键需要额外区分属性"的 M:N 表**（复现 #24）。
6. **继续换题型**：避免连续两套同一套路。可加入：
   - 给结果反推 SQL（"哪个查询能得到这个结果"）
   - 多表数据推演（给数据表，问查询结果）

## 8. 已实测的 MySQL 行为（可直接引用，别再怀疑）

| 行为 | 实测结论 |
|---|---|
| `A LEFT JOIN B`，B 为空表 | 仍返回 A 的全部行（右边 NULL） |
| LEFT JOIN 后 `COUNT(*)`，A 没匹配 | 得到 **1**（不是 0） |
| 同一查询改用 `COUNT(B.列)` | 得到 **0** |
| 过滤条件写 `ON` vs `WHERE` | 结果不同；写 WHERE 会丢左表独有行（退化为内连接） |
| `WHERE 列 = NULL` | 0 行 |
| `WHERE 列 IS NULL` | 正确返回 NULL 行 |
| `NOT IN (子查询含 NULL)` | **0 行**（不是"排除 NULL 后剩下的"） |
| `IN (子查询含 NULL)` | 能匹配的返回，没匹配的因 UNKNOWN 被丢 |
| `NOT EXISTS` | NULL-safe，结果正确 |
| `SUM(列)` 空集 | 返回 **NULL**，不是 0 |
| `COUNT(列)` 遇 NULL | 不数 |
| 触发器 + `ROLLBACK` | 触发器的 UPDATE 一起回滚 |
| 触发器 + `COMMIT` | 一起提交 |
| MySQL `FULL OUTER JOIN` | **语法错误**；用 `LEFT JOIN ... UNION ... RIGHT JOIN` |
| `NATURAL JOIN` | 自动按同名列连接并去掉重复列 |
| `LIMIT m, n` | 跳过 m 行、取 n 行（m 从 0 数） |
| `VIEW` + `GROUP BY/聚合` | 不可 UPDATE |
| `UNIQUE` 列 | 允许多个 NULL |
| 外键列 | 允许 NULL（除非 NOT NULL） |
| `DELETE FROM 表` | 删行，表结构保留 |
| `DROP TABLE` | 删表（连结构） |
| 存储过程 `OUT` | 调用用 `@变量` 接，再 `SELECT @变量` |
| `CREATE TRIGGER/PROCEDURE ... BEGIN ... END` | Jupyter 里无需 DELIMITER |
| `USE 库名` | jupysql 跨 cell 保持 |
