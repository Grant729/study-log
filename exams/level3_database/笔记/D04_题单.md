## 题 11【实操】建库三步（创建 → 验证 → 删除）

## 题 12【实操】ALTER TABLE 装修五连里的三新招

**【目的】** D3 题 14 用过 ADD COLUMN / ADD CONSTRAINT，今天补 MODIFY / CHANGE / DROP COLUMN。
**【前置】** 无（课程表是新建的）。
**【要求】** 新建**一个**代码格，从上到下：

```sql
DROP TABLE IF EXISTS 课程;
CREATE TABLE 课程 (课程号 CHAR(3) PRIMARY KEY, 课程名 VARCHAR(30) NOT NULL, 学分 INT);
INSERT INTO 课程 VALUES
('C01','数据库系统概论',4),
('C02','信息检索',3),
('C03','Python程序设计',3);
ALTER TABLE 课程 ADD COLUMN 授课教师 VARCHAR(20) DEFAULT '待定';
ALTER TABLE 课程 MODIFY 学分 DECIMAL(3,1);
ALTER TABLE 课程 CHANGE 授课教师 教师姓名 VARCHAR(20);
DESCRIBE 课程;
SELECT * FROM 课程;
ALTER TABLE 课程 DROP COLUMN 教师姓名;
DESCRIBE 课程;
```

**【提示】** 注意 CHANGE 那行：**改名的同时类型必须照写一遍**。最后两行是"恢复现场"。
**【验收】** 第一个 `DESCRIBE` 显示 **4 列**（学分类型变成 `decimal(3,1)`，多了教师姓名列）；`SELECT` 里教师姓名列全是"待定"、学分显示 4.0/3.0/3.0；最后的 `DESCRIBE` 回到 **3 列**。

<details><summary>👉 点开对照答案与解析</summary>

真实输出（本机已实测）：

```
DESCRIBE 课程（ALTER 三连后）：
课程号    char(3)        NO  PRI
课程名    varchar(30)    NO
学分      decimal(3,1)   YES      ← MODIFY 生效：INT → DECIMAL(3,1)
教师姓名  varchar(20)    YES      ← ADD COLUMN + CHANGE 改名生效

SELECT * FROM 课程：
C01  数据库系统概论  4.0  待定   ← 旧行自动填默认值"待定"
C02  信息检索        3.0  待定
C03  Python程序设计  3.0  待定

最后 DESCRIBE（DROP COLUMN 后）：3 列（教师姓名列没了）
```

解析：ADD COLUMN 给已有 3 行**自动补上默认值**；MODIFY 只改类型；CHANGE 改了名（类型 VARCHAR(20) 照写）；DROP COLUMN 收尾恢复。三招都亲眼见过=记住了。

</details>

## 题 13【实操】视图三连：建 → 经视图改数据 → 删

**【目的】** 亲手验证"简单视图可更新、改动落基表"——这是判断题高频考点。
**【前置】** 读者表数据现状：张三5、李四8、王五3、赵六2（题 11/12 没动它）。
**【要求】** 新建**一个**代码格：

```sql
CREATE VIEW 高借阅读者 AS SELECT * FROM 读者 WHERE 借阅次数 > 3;
SELECT * FROM 高借阅读者;
UPDATE 高借阅读者 SET 借阅次数 = 10 WHERE 读者编号 = '001';
SELECT * FROM 读者 WHERE 读者编号 = '001';
UPDATE 读者 SET 借阅次数 = 5 WHERE 读者编号 = '001';
DROP VIEW 高借阅读者;
```

**【提示】** 关键是第 4 条：查的是**基表**读者——如果张三变成了 10，说明"改视图=改基表"。
**【验收】** 第 2 条出张三5、李四8；第 4 条出**张三 10**；第 5 条恢复成 5（现场还原，很重要）。

<details><summary>👉 点开对照答案与解析</summary>

真实输出（本机已实测）：

```
SELECT * FROM 高借阅读者：        001 张三 5 / 002 李四 8
UPDATE 高借阅读者 → 1 rows affected.
SELECT * FROM 读者 WHERE 001：    001 张三 10   ← 基表被改了！
恢复 UPDATE 读者 → 1 rows affected.（回到 5）
DROP VIEW → 0 rows affected.
```

解析：视图是"预设菜单"，UPDATE 视图 = 让后厨改食材 = 改基表。**最后两行必须做**：把张三恢复成 5、把视图删掉——练习不残留。

</details>

## 题 14【实操】索引：建两个 → 看目录 → 故意犯规 → 删干净

**【目的】** 亲手建索引、看索引、触发唯一索引执法（1062）。
**【前置】** 图书表数据现状：B001~B004（书名全不同）；读者表：4 人（姓名全不同）。
**【要求】** 两个代码格：

**格 1（建 + 看）：**

```sql
CREATE INDEX idx_书名 ON 图书(书名);
CREATE UNIQUE INDEX uq_读者姓名 ON 读者(读者姓名);
SHOW INDEX FROM 图书;
```

观察：图书表有两个索引——主键自带的 **PRIMARY** + 你刚建的 **idx_书名**。

**格 2（故意犯规 + 收尾）：**

```sql
INSERT INTO 读者 VALUES ('009','张三',1);
DROP INDEX idx_书名 ON 图书;
DROP INDEX uq_读者姓名 ON 读者;
```

**【提示】** 格 2 第一条故意插重复姓名"张三"——**报错是目的**。
**【验收】** 格 1 的 SHOW INDEX 显示两个索引；格 2 第一条报 **1062**（唯一索引执法），后两条删除成功。

<details><summary>👉 点开对照答案与解析</summary>

真实输出（本机已实测）：

```
SHOW INDEX FROM 图书 两行：
图书  PRIMARY  图书编号   ← 主键自带
图书  idx_书名 书名      ← 你建的

格 2 第一条报错：
(1062, "Duplicate entry '张三' for key '读者.uq_读者姓名'")
→ 唯一索引在执法：张三已存在，不许再来一个

DROP INDEX ×2 → 0 rows affected.（现场还原，索引删干净）
```

解析：1062 和主键重复是同一个错误码——底层都是唯一性检查。删索引要写 `ON 表名`，这是 DROP INDEX 和 DROP TABLE/VIEW 的差别。

</details>

## 回 6【实操】ALTER + CHECK 换汤（D3 题 14 的变形）

**【目的】** D3 题 14 给图书表加过 CHECK，今天换汤成给**读者表**加。
**【前置】** 读者表数据现状：4 人（借阅次数 5/8/3/2）。
**【要求】** 新建**一个**代码格：

```sql
ALTER TABLE 读者 ADD CONSTRAINT chk_借阅 CHECK (借阅次数 >= 0);
INSERT INTO 读者 VALUES ('009','测试',-1);
ALTER TABLE 读者 DROP CHECK chk_借阅;
```

**【提示】** 中间一条故意犯规——**报错是目的**；第三条 `DROP CHECK 约束名` 是收尾（约束名就是 ADD 时起的 chk_借阅）。
**【验收】** 第一条成功；第二条报 **3819**（chk_借阅 执法）；第三条成功，读者表回到 4 人。

<details><summary>👉 点开对照答案与解析</summary>

真实输出（本机已实测）：

```
ALTER TABLE 读者 ADD CONSTRAINT → 4 rows affected.（检查现有 4 行是否合规）
INSERT 借阅次数 -1 → (3819, "Check constraint 'chk_借阅' is violated.")
ALTER TABLE 读者 DROP CHECK chk_借阅 → 0 rows affected.（家规撤销，现场还原）
```

解析：与 D3 题 14 同构——`ADD CONSTRAINT 名 CHECK (条件)` 补家规、故意犯规验证、`DROP CHECK 名` 撤销。换汤（读者表）不换药（ALTER+CHECK 三步曲）。

</details>
