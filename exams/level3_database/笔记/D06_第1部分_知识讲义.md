## 单元一：为什么需要"连接"

### 图书馆的两大名册问题

想象你有两本名册：

- **读者名册**：`读者` 表
  - 读者编号、读者姓名、借阅次数

- **借阅记录册**：`借阅` 表
  - 借阅号、读者编号、图书编号、借阅日期

**问题来了**：你想查"张三借了哪本书"，只查读者表？没借阅记录！只查借阅表？不知道借阅的是谁！

**解决方案**：把两本名册**拼接**起来——这就是**连接（JOIN）**。

### 三种基本连接

连接的精髓：**从两个（或更多）表里"对号入座"，找到"既在这个表，又在那个表"的那些行**。

| 类型 | 关键字 | 作用 | 形象比喻 |
|---|---|---|---|
| **内连接** | `INNER JOIN` | 只保留**两边都有匹配**的行（交集） | 张三和李四都借过书，才能查出来 |
| **左连接** | `LEFT JOIN` | 保留**左边表（左表）所有行**，右边没匹配的填 NULL | 所有读者都要查，没借书的也显示，借书记录填 NULL |
| **右连接** | `RIGHT JOIN` | 保留**右边表（右表）所有行**，左边没匹配的填 NULL | 所有借阅记录都要查，没读者的也显示，读者编号填 NULL |

## 单元二：内连接实战——逐步升级

### 2.1 基础内连接（等值连接）

先看两表结构（**就是库里现成的结构**）：

```sql
-- 读者表
CREATE TABLE 读者 (
  读者编号 CHAR(3) PRIMARY KEY,
  读者姓名 VARCHAR(20) NOT NULL,
  借阅次数 INT DEFAULT 0
);

-- 借阅表
CREATE TABLE 借阅 (
  借阅号 INT PRIMARY KEY AUTO_INCREMENT,
  读者编号 CHAR(3) NOT NULL,
  图书编号 CHAR(4) NOT NULL,
  借阅日期 DATE DEFAULT (CURRENT_DATE),
  应还日期 DATE NOT NULL,
  归还日期 DATE,
  FOREIGN KEY (读者编号) REFERENCES 读者(读者编号),
  FOREIGN KEY (图书编号) REFERENCES 图书(图书编号)
);
```

⚠️ **先记牢列名**：读者表里姓的那一列叫 **`读者姓名`**，不叫 `姓名`。写成 `姓名` 会直接报 `Unknown column '姓名'`。

**最简单的连接**：找出"谁借了哪本书"

```sql
SELECT 读者.读者编号, 读者.读者姓名, 借阅.图书编号
FROM 读者
INNER JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号;
```

真实输出（5 行）：

```
读者编号 | 读者姓名 | 图书编号
--------|---------|----------
001     | 张三    | B001
002     | 李四    | B002
003     | 王五    | B003
004     | 赵六    | B004
004     | 赵六    | B001
```

读法：
1. 先拿读者表（FROM 读者）
2. 再拿借阅表（INNER JOIN 借阅）
3. ON 后面写**匹配条件**：读者.读者编号 = 借阅.读者编号
4. 结果：只保留两表都有的匹配行

⚠️ **第一个大坑**：`读者编号` 这两张表**都有**，写 `SELECT 读者编号` 会报错 `Column '读者编号' in field list is ambiguous`（列名有歧义）。**必须写清是哪张表的**：`读者.读者编号`。

**记忆口诀**：**内连接 = 找交集**。

### 2.2 连接多个表

查"谁借了哪本书，书名是什么"（连接三表）：

```sql
SELECT 读者.读者编号, 读者.读者姓名, 借阅.图书编号, 图书.书名, 借阅.应还日期
FROM 读者
INNER JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号
INNER JOIN 图书 ON 借阅.图书编号 = 图书.图书编号;
```

读法：从读者开始，连借阅，再连图书，**每连一个表就多写一个 ON 条件**。

真实输出：

```
读者编号 | 读者姓名 | 图书编号 | 书名         | 应还日期
--------|---------|----------|--------------|----------
001     | 张三    | B001     | 数据库系统概论 | 2026-11-15
002     | 李四    | B002     | R语言实战     | 2026-11-15
003     | 王五    | B003     | Python编程    | 2026-11-20
004     | 赵六    | B004     | 信息检索导论   | 2026-11-20
004     | 赵六    | B001     | 数据库系统概论 | 2026-11-25
```

### 2.3 三种连接的对比

**内连接**（交集）：
```sql
SELECT * FROM 读者 INNER JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号;
```
- 结果：只显示"借了书"的读者（借阅记录存在）

**左连接**（保留左边全部）：
```sql
SELECT * FROM 读者 LEFT JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号;
```
- 结果：所有读者都显示，没借书的读者，借阅部分是 NULL

**右连接**（保留右边全部）：
```sql
SELECT * FROM 读者 RIGHT JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号;
```
- 结果：所有借阅记录都显示，没读者的借阅记录，读者编号是 NULL

> 🔎 **实测提醒**：在你现在的库上跑上面三条，**结果会一模一样（都是 5 行）**。因为 4 个读者**全都借过书**，5 条借阅记录**的读者也都存在**——两边都没有"落单"的行，三种连接自然没差别。
> 想亲眼看到区别，可以临时插一个没借过书的读者：`INSERT INTO 读者 VALUES ('005','钱七',0);`，再跑这三条对比，看完 `DELETE FROM 读者 WHERE 读者编号='005';` 删掉。

**考试爱考**：判断题——"左连接的结果集**一定**比内连接大"（**错**）。左连接 = 内连接的结果 **+** 左表独有的行，所以它**不小于**内连接，但**可能相等**——左表每一行都有匹配时，"独有的行"是 0 行。看到"一定"先找反例。（想考"对"的话，题干会写"**不小于**"。）

### 2.4 只取前几行：MySQL 用 `LIMIT`，**没有 `TOP`**

有时候排完序还要"**只留前几行**"，比如"借阅次数前两名的读者是谁"。

⚠️ **这是最容易踩的坑**：很多教材和网上的例子写 `SELECT TOP 2 ...`——那是 **SQL Server** 的语法，**MySQL 里一跑就报语法错误**。

| 数据库 | 限制行数的写法 |
|---|---|
| **MySQL（你考试用的就是这个）** | `LIMIT 2` |
| SQL Server | `SELECT TOP 2 ...` |
| Oracle | `WHERE ROWNUM <= 2` |

MySQL 的正确写法——**`LIMIT` 写在整条语句的最后，紧跟在 `ORDER BY` 后面**：

```sql
SELECT 读者编号, 读者姓名, 借阅次数
FROM 读者
ORDER BY 借阅次数 DESC
LIMIT 2;
```

真实输出：

```
读者编号 | 读者姓名 | 借阅次数
--------|---------|----------
002     | 李四    | 8
001     | 张三    | 5
```

**两个高频考点**：

- `LIMIT n` = 只要前 n 行。
- `LIMIT 起始位置, 行数` = 跳过前几行再取。**起始位置从 0 开始数**。所以"第 2、3 名"要写 `LIMIT 1, 2`（跳过第 1 行，再取 2 行）：
  ```sql
  SELECT 读者编号, 读者姓名, 借阅次数 FROM 读者 ORDER BY 借阅次数 DESC LIMIT 1, 2;
  -- → 001 张三 5 / 003 王五 3
  ```

⚠️ **`LIMIT` 必须排在 `ORDER BY` 后面**。写成 `LIMIT 2 ORDER BY ...` 直接语法错误——因为"取行"是在"排序"之后才发生的（见单元四的执行顺序）。

**记忆口诀**：**MySQL 只认 `LIMIT`；`TOP` 是 SQL Server 的。**

## 单元三：自连接——同一张表当两张用

### 3.1 什么情况下需要它

单元二里，连接的两头是**两张不同的表**（读者 ↔ 借阅）。自连接连接的，是**同一张表**。

先看一个普通查询解决不了的问题：

> **每个读者的借阅次数排第几？**

卡点在哪：`SELECT * FROM 读者` 一次只看得见**当前这一行**。可"排名"这件事，必须拿**我这一行**去跟**表里其他所有行**比——李四 8 次排第一，不是因为李四自己，而是因为**别人都没他多**。

**一句话判据**：当一行的答案要**从同一张表的其他行里找**时 → 把这张表**复印一份**，让两份互相比较。

### 3.2 怎么复印：起别名

```sql
FROM 读者 AS A
JOIN 读者 AS B ON ...
```

- 同一张表出现两次，**必须各起一个别名**，否则 MySQL 报错 `Not unique table/alias`。
- 起了名之后，`A.借阅次数` 和 `B.借阅次数` 就变成了**两个互相独立的列**，可以拿来比较。
- 别名不必是 A/B，起有意义的名字更好读，比如 `读者 AS 我`、`读者 AS 别人`。

**关键**：自连接的语法和普通内连接**一模一样**，唯一的区别是 FROM 和 JOIN 后面跟的是**同一张表**。别被"自"这个字吓到。

### 3.3 第一步：把"谁比谁借得多"全列出来

让 A 扮演"借得少"的，B 扮演"借得多"的，ON 的条件就是"B 比 A 多"：

```sql
SELECT A.读者姓名 AS 借得少的人, A.借阅次数 AS 少的次数,
       B.读者姓名 AS 借得多的人, B.借阅次数 AS 多的次数
FROM 读者 AS A
JOIN 读者 AS B ON A.借阅次数 < B.借阅次数
ORDER BY B.借阅次数 DESC, A.借阅次数 DESC;
```

真实输出（6 行）：

```
借得少的人 | 少的次数 | 借得多的人 | 多的次数
----------|---------|-----------|----------
张三      | 5       | 李四      | 8
王五      | 3       | 李四      | 8
赵六      | 2       | 李四      | 8
王五      | 3       | 张三      | 5
赵六      | 2       | 张三      | 5
赵六      | 2       | 王五      | 3
```

**怎么读**：4 个读者两两配对，能分出高低的组合正好 **6 对**（4 × 3 ÷ 2）。每一行读作"**A 比 B 少**"。

**和普通连接对照着记**：

| | 左边 | 右边 | ON 在干什么 |
|---|---|---|---|
| 普通连接 | 读者 一行 | 借阅 一行 | 把两个表的行"**对上号**" |
| 自连接 | 读者 一行（副本 A） | 读者 一行（副本 B） | 让两行"**比大小**" |

### 3.4 第二步：数"比我多的有几个人"→ 排名就出来了

在 3.3 的基础上，对每个"我"，数一数"别人"里有几个比我多：

```sql
SELECT A.读者姓名, A.借阅次数,
       COUNT(B.读者编号) AS 比我多的人数
FROM 读者 AS A
LEFT JOIN 读者 AS B ON B.借阅次数 > A.借阅次数
GROUP BY A.读者编号, A.读者姓名, A.借阅次数
ORDER BY A.借阅次数 DESC;
```

真实输出：

```
读者姓名 | 借阅次数 | 比我多的人数
--------|---------|------------
李四    | 8       | 0
张三    | 5       | 1
王五    | 3       | 2
赵六    | 2       | 3
```

**"比我多的人数"就是排名件数**：李四 0 → 第 1 名；张三 1 → 第 2 名；王五 2 → 第 3 名；赵六 3 → 第 4 名。

⚠️ **这里必须用 `LEFT JOIN`，不能用 `JOIN`**。李四"比我多的人数"是 **0**，如果用内连接，李四会因为找不到"比他多的行"而**整行消失**——排名第一的人反而查不出来。用左连接才能保住他、数出 0。

### 3.5 拿它解一道真题："借阅次数第二多的读者"

**写法一：自连接**——"比我多的正好 1 个"

```sql
SELECT A.读者编号, A.读者姓名, A.借阅次数
FROM 读者 AS A
JOIN 读者 AS B ON B.借阅次数 > A.借阅次数
GROUP BY A.读者编号, A.读者姓名, A.借阅次数
HAVING COUNT(*) = 1;
```
→ `001 张三 5`

（这里可以放心用内连接：我们要的就是"**有人**比我多"且正好一个，不存在"没人比我多"的第一名。）

**写法二：子查询**——更好写，但只适合"最大 / 第二大"这种固定名次

```sql
SELECT 读者编号, 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 = (
    SELECT MAX(借阅次数) FROM 读者
    WHERE 借阅次数 < (SELECT MAX(借阅次数) FROM 读者)
);
```
→ `001 张三 5`

读法（**从里往外**）：
1. 里层 `SELECT MAX(借阅次数)` = **8**（最多）
2. 中层"**在比 8 小的里面**取最大" = **5**（第二多）
3. 外层"借阅次数等于 5 的读者" = 张三

⚠️ **绝对不要写 `MAX(借阅次数) - 1`**！它默认了"第二名正好比第一名少 1"。只要有人次数相同、或者差距不是 1，答案就全错。在真实数据上 8 − 1 = 7，**一个读者都查不到（空结果）**。

**两种写法怎么选**：

| 需求 | 用哪个 |
|---|---|
| 只要"最多 / 第二多"这种**固定名次** | 子查询（写得短） |
| 要"**排名**""比我多的有几个""第 n 名" | 自连接（通用） |

### 3.6 另一种经典场景：查上下级

表里如果有一列**指向本表的另一行**（例如 `员工.上级编号 → 员工.员工编号`），自连接就是唯一解法：

```sql
-- 假设有表 员工(员工编号, 姓名, 上级编号)
SELECT 员工.姓名 AS 员工姓名, 上级.姓名 AS 上级姓名
FROM 员工
JOIN 员工 AS 上级 ON 员工.上级编号 = 上级.员工编号;
```

一个表，两个角色：一份叫"员工"、一份叫"上级"。

**判据**：连接条件里出现"**本表的普通列 = 本表的主键**"（`上级编号 = 员工编号`）→ 这就是自连接。

**考试爱考**：自连接**必须起别名**，否则 MySQL 分不清哪列来自哪一份。

## 单元四：连接的执行顺序

一条 `SELECT ... FROM 表1 JOIN 表2 ON 条件` 的完整执行顺序：

```
1. FROM（拿表1）
2. JOIN（拿表2）
3. ON（匹配条件）
4. WHERE（过滤行）
5. SELECT（挑列）
6. ORDER BY（排序）
```

**关键考点**：**WHERE 里不能有列别名**，因为 WHERE 在 SELECT 之前执行；**ORDER BY 里可以用别名**。

（`LIMIT` 是这条流水线的**最后一步**，排在 ORDER BY 之后——所以它必须写在语句末尾。）
