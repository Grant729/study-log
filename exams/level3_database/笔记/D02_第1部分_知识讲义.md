## 单元一 · 先建立对照：SQL 是"点菜"，关系代数是"配方"

- **SQL**：你跟服务员说"给我来一份借阅量大于 5 的读者名单"——说**要什么**，不用管后厨怎么做。
- **关系代数**：后厨的**配方公式**——`σ`（挑行）、`π`（挑列）、`⋈`（拼接）……一串符号精确描述数据怎么变出来。

考试的关系：**关系代数是理论考题（背符号含义），SQL 是实操考题（写代码）**。两者是同一件事的两种语言，一一对应：

| 关系代数 | 符号 | 作用 | SQL 对应 |
|---|---|---|---|
| 选择 | **σ**（sigma） | **挑行** | `WHERE` |
| 投影 | **π**（pi） | **挑列** | `SELECT 列名` |
| 并 | **∪** | 两张表竖着拼、去重 | `UNION` |
| 交 | **∩** | 两张表都有的行 | 内连接可代替（D6 学） |
| 差 | **−** | 在 A 不在 B 的行 | `NOT IN` |
| 笛卡儿积 | **×** | 两表全配对 | `FROM A, B`（不带条件） |
| 连接 | **⋈** | 按条件横着拼 | `JOIN ... ON`（D6 学） |
| 除 | **÷** | 找"满足全部条件"的 | （最难，记含义即可） |

记忆口诀（按顺序背）：**并交差积 · 选投连除**。

## 单元二 · 八个运算逐个讲（每个都配比喻）

### 1. 选择 σ —— 体检刷人（挑行）
`σ_借阅量>100(读者)` = 从读者表里**只留下借阅量 > 100 的那些行**。
比喻：军训体检，身高不达标的整**行**（这个人）刷掉。**行被过滤，列一个不少**。

### 2. 投影 π —— 只留两栏（挑列）
`π_姓名,学院(读者)` = 只要"姓名、学院"两**列**，其余栏目撕掉。
**考点**：投影出来的结果**行可能会变少**——因为重复的行会被合并（比如两个人同名同院，只留一行）。这是判断题最爱出的点：**投影会去重**。

### 3. 并 ∪ —— 两叠名单拼一起（去重）
`A ∪ B` = A 表和 B 表**竖着摞起来**，重复的行只留一份。
**前提条件（必考）**：两张表必须**列数相同、对应列类型相同**——"两份表格格式一样才能摞"。SQL 里就是 `UNION`。

### 4. 交 ∩ —— 两份名单都出现的人
`A ∩ B` = **既在 A 又在 B** 的行。比喻：抽奖名单和优秀读者名单的交集 = 又中奖又优秀的人。
MySQL 没有单独的 INTERSECT 关键词（考试理论知道含义即可）。

### 5. 差 − —— 在 A 不在 B
`A − B` = 在 A 表里、但不在 B 表里的行。比喻：**报名名单减去到场名单 = 放鸽子名单**。
注意：**A−B 和 B−A 结果不一样**（谁减谁很关键）。

### 6. 笛卡儿积 × —— 全配对
`A × B` = A 的**每一行和 B 的每一行都配一次**。3 行 × 4 行 = **12 行**（行数相乘，必考）。
比喻：两种口味的冰激凌 × 三种蛋筒 = 六种组合。SQL 里 `FROM A, B` 不带连接条件就是它。

### 7. 连接 ⋈ —— 按条件横着拼
把两张表**按某个共同条件横着拼成一张宽表**。
- **等值连接**：`ON A.编号 = B.编号`，两表的共同列**都保留**（会出现两列编号）
- **自然连接**：等值连接**再删掉重复的那一列**——区别就这一条，必考
（D6 会有整整一天的 SQL 实操课，这里懂概念即可。）

### 8. 除 ÷ —— 找"全能选手"（最难，记含义）
`借阅记录 ÷ 图书表` = "**借过所有书的读者**"。
比喻：**考过所有科目的学生**。考试只会考含义判断（"下列哪个运算能查出借过全部图书的读者"→ 选除），不考手算。

## 单元三 · 实操范例：UNION（并）逐词解析

今天唯一的实操新语法是 `UNION`。范例场景：两张图书表合成一张（做题时你要换成"读者_大一/读者_大二"）。

```sql
DROP TABLE IF EXISTS 图书A;        -- 防重复运行报错：有这张表就先删掉
CREATE TABLE 图书A(书号 CHAR(8), 书名 VARCHAR(50));
INSERT INTO 图书A VALUES ('B001','数据库系统概论'),('B002','SQL必知必会');

DROP TABLE IF EXISTS 图书B;
CREATE TABLE 图书B(书号 CHAR(8), 书名 VARCHAR(50));
INSERT INTO 图书B VALUES ('B002','SQL必知必会'),('B003','大数据技术原理');

SELECT * FROM 图书A UNION SELECT * FROM 图书B;
```

**逐词解析：**

- `DROP TABLE IF EXISTS 图书A;` —— 三个词："删除表 / 如果它存在 / 名叫图书A"。**新手神器**：练习时反复运行同一段建表代码，第二遍就会撞"表已存在"报错，加上这句就永远不撞。`IF EXISTS` 可以配 DROP TABLE、DROP DATABASE 一起用。
- `CREATE TABLE 图书A(书号 CHAR(8), 书名 VARCHAR(50));` —— 和 D1 学的完全一样：列名 + 类型，今天偷懒不加约束也合法（约束是可选的"规矩"）。
- `SELECT * FROM 图书A UNION SELECT * FROM 图书B;` —— 拆开看就是**两条独立查询，中间用 UNION 焊接**。规则：
  - 两边的列**数量必须一样**、类型要能对应（和 ∪ 的前提条件一个道理）
  - 结果**自动去重**——注意范例里 'B002','SQL必知必会' 两张表都有，但结果里只出现一次
  - 想保留重复行就写 `UNION ALL`（考试可能考这个区别）

**和 D1 知识的对照**（顺手回炉）：`σ_借阅次数>=5(读者)` 翻译成 SQL 就是 `WHERE 借阅次数 >= 5`；`π_读者姓名(读者)` 就是 `SELECT 读者姓名`。关系代数的每个运算都有 SQL 实现，考试爱考这个对照。

## 单元四 · 考试怎么考（先给你打个底）

- 选择题高频：**"下列哪个运算是对行的筛选"→ σ**；"对列的筛选"→ **π**；"求两张表共有行"→ **∩**；"笛卡儿积的行数"→ **行数相乘**；"∪ 的前提"→ **列数相同**
- 判断题高频：**"投影不减少行数"→ 错**（会去重）；"自然连接和等值连接完全一样"→ 错（差在去重复列）；"∪ 自动去重"→ 对
- 除运算只考含义选择题，不考手算
