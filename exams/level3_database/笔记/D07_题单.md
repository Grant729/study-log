# ② 理论题检测（模块 5b · 分组与筛组）

## 题 1【判断】GROUP BY 的作用

`GROUP BY 出版社` 的作用是：按"出版社"这一列把行分成几组，再对每一组分别用聚合函数计算。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** GROUP BY = 先分堆、再对每堆聚合（讲义单元一）。像食堂分餐：先按班级排队，再每队数人数。

</details>

---

## 题 2【单选】分组后 SELECT 能放什么

`GROUP BY 出版社` 之后，`SELECT` 里**可以**放的是（ ）。

A. 表里任意一列
B. `GROUP BY` 里的列 + 聚合函数
C. 只能放聚合函数
D. 只能放 `GROUP BY` 里的列

<details><summary>👉 点开对照答案与解析</summary>

**B。** 分组后 SELECT 只有"安全区"：分组列（出版社）+ 聚合函数（COUNT/SUM/AVG/MAX/MIN）。放别的普通列（如书名）会报 1055——因为一组里有多行，MySQL 不知道该显示哪一行的书名。

</details>

---

## 题 3【判断】WHERE 里能写聚合函数吗

在 `WHERE` 子句里可以用聚合函数（如 `WHERE COUNT(*) > 2`）。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**错。** WHERE 在分组**之前**执行，那时"组"还没分出来，聚合函数无从算起。写 `WHERE COUNT(*) > 2` 直接报 1111（Invalid use of group function）。聚合函数只能出现在 SELECT / HAVING / ORDER BY 里。

</details>

---

## 题 4【单选】筛"总馆藏量大于 5 的出版社"

要查出"总馆藏量大于 5 的出版社"，正确写法用（ ）。

A. `WHERE SUM(馆藏量) > 5`
B. `GROUP BY 出版社 HAVING SUM(馆藏量) > 5`
C. `HAVING 馆藏量 > 5`
D. `WHERE 馆藏量 > 5 GROUP BY 出版社`

<details><summary>👉 点开对照答案与解析</summary>

**B。** "总馆藏量"是分组后每组的 SUM，属于"筛组"→ 用 HAVING，且 HAVING 里要写聚合函数 `SUM(馆藏量)`。A 错在 WHERE 里不能写聚合函数；C 错在 HAVING 里写的是普通列（筛组要用聚合函数）；D 的 WHERE 只能筛"单行的馆藏量"，筛不出"总馆藏>5"这个组级条件。

</details>

---

## 题 5【判断】执行顺序

一条带分组的查询，执行顺序是 `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 完整版再补 LIMIT 在最后：`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`（讲义单元五）。WHERE 在 GROUP BY 前、HAVING 在 GROUP BY 后，这就是"WHERE 不能筛组、HAVING 能"的根本原因。

</details>

---

## 题 6【单选】聚合函数不能出现在哪

聚合函数（如 COUNT、SUM）**不能**出现在（ ）。

A. SELECT 子句
B. HAVING 子句
C. ORDER BY 子句
D. WHERE 子句

<details><summary>👉 点开对照答案与解析</summary>

**D。** 聚合函数能进 SELECT、HAVING、ORDER BY，唯独不能进 WHERE（WHERE 执行时还没分组）。这是"WHERE vs HAVING"的姊妹考点。

</details>

---

## 题 7【判断】GROUP BY 也能去重

`SELECT 出版社 FROM 图书 GROUP BY 出版社` 和 `SELECT DISTINCT 出版社 FROM 图书` 结果一样，都能去重。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 分组本身就是"相同的归一堆、每堆出一条"，等价于去重（讲义单元六）。但日常去重优先用 DISTINCT（专词专用），GROUP BY 去重只是副作用——考试问"哪个也能去重"时知道 GROUP BY 也算。

</details>

---

## 题 8【单选】分组键的识别

要查"每个读者借了几本书"，`GROUP BY` 后面应该写（ ）。

A. `GROUP BY 借阅号`
B. `GROUP BY 读者编号`
C. `GROUP BY 图书编号`
D. `GROUP BY 借阅日期`

<details><summary>👉 点开对照答案与解析</summary>

**B。** "每个读者"→ 按读者分组，分组键是 `读者编号`。A 的借阅号是借阅表主键（每行唯一，分组后每组 1 行，没意义）；C 是按书分组、D 是按日期分组，都不是"每个读者"。

</details>

---

## 题 9【判断】分组后放普通列会报错

`SELECT 出版社, 书名, COUNT(*) FROM 图书 GROUP BY 出版社` 在 MySQL 8.0.23 会报错。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 报 1055。你的库开着 `ONLY_FULL_GROUP_BY` 模式（默认开），`书名` 既不在 GROUP BY 里也不是聚合函数，MySQL 拒绝执行。这个模式是"好事"——逼你写正确的分组查询。

</details>

---

## 题 10【判断】WHERE 与 GROUP BY 的先后

一条查询里同时有 WHERE 和 GROUP BY 时，WHERE 先执行（先筛行），GROUP BY 后执行（再分组）。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 执行顺序 FROM → WHERE → GROUP BY。所以 WHERE 只能筛"原始的行"，筛不掉"分好组之后的组"——筛组是 HAVING 的活。呼应题 5。

</details>

# ③ 代码实操（换汤不换药：讲义按出版社分组，这里按读者/借阅分组）

## 实操题 1：每个读者借了几本书

**要求**：查出每个读者借了几本书，显示读者编号、借阅本数，按读者编号从小到大排。

**预期输出**：
```
读者编号 | 借阅本数
--------|---------
001     | 1
002     | 1
003     | 1
004     | 2
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者编号, COUNT(*) AS 借阅本数
FROM 借阅
GROUP BY 读者编号
ORDER BY 读者编号;
```

**要点**：分组键是"每个读者"→ `读者编号`；"借了几本"→ `COUNT(*)`。004 赵六借了 2 本，所以他那组是 2。

</details>

---

## 实操题 2：每个读者的最晚应还日期

**要求**：查出每个读者最晚的应还日期，显示读者编号、最晚应还，按读者编号从小到大排。

**预期输出**：
```
读者编号 | 最晚应还
--------|----------
001     | 2026-11-15
002     | 2026-11-15
003     | 2026-11-20
004     | 2026-11-25
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者编号, MAX(应还日期) AS 最晚应还
FROM 借阅
GROUP BY 读者编号
ORDER BY 读者编号;
```

**要点**：分组后每组的"最晚"→ `MAX(应还日期)`。004 有两条（11-20、11-25），MAX 取 11-25；其余读者各借 1 本，MAX 就是他们自己那本的日期。

</details>

---

## 实操题 3：先筛行，再分组

**要求**：查出"应还日期不晚于 2026-11-20"的借阅里，每个读者借了几本。显示读者编号、本数，按读者编号排。

**预期输出**：
```
读者编号 | 本数
--------|------
001     | 1
002     | 1
003     | 1
004     | 1
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者编号, COUNT(*) AS 本数
FROM 借阅
WHERE 应还日期 <= '2026-11-20'
GROUP BY 读者编号
ORDER BY 读者编号;
```

**要点**：`WHERE 应还日期 <= '2026-11-20'` 先筛行——004 那条 11-25 的记录被刷掉，004 只剩 1 本；**再**分组。对比实操题 1：004 从"2 本"变成"1 本"，正是 WHERE 筛行的效果。

</details>

---

## 实操题 4：HAVING 筛组——借了至少 2 本的读者

**要求**：查出借阅本数 ≥ 2 的读者，显示读者编号、借阅本数。

**预期输出**：
```
读者编号 | 借阅本数
--------|---------
004     | 2
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者编号, COUNT(*) AS 借阅本数
FROM 借阅
GROUP BY 读者编号
HAVING COUNT(*) >= 2;
```

**要点**：先分组算出每人本数，再用 `HAVING COUNT(*) >= 2` 把"本数 < 2"的**组**整组刷掉，只剩 004。注意这里用 HAVING 而不是 WHERE——因为"借阅本数"是分组后才有的数，WHERE 里写 `COUNT(*)` 会报 1111。

</details>

---

## 实操题 5：综合——读者姓名 + 借阅本数（JOIN + GROUP BY）

**要求**：查出每个读者的姓名和他借了几本书，没借过书的也要显示（借阅本数显示 0）。按借阅本数从多到少排。

**提示**：这一步要同时用到 D6 的 JOIN 和今天的 GROUP BY。

**预期输出**：
```
读者姓名 | 借阅本数
--------|---------
赵六    | 2
张三    | 1
李四    | 1
王五    | 1
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者.读者姓名, COUNT(借阅.借阅号) AS 借阅本数
FROM 读者
LEFT JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号
GROUP BY 读者.读者编号, 读者.读者姓名
ORDER BY 借阅本数 DESC;
```

**要点**：
- `LEFT JOIN` 保住"没借过书的读者"（他们借阅号是 NULL，`COUNT(借阅号)` 不数 NULL，所以是 0）。
- `GROUP BY 读者.读者编号, 读者.读者姓名` —— 分组键写全两列，因为 SELECT 里出现了姓名（安全区规则）。
- 你库里 4 个读者都借过书，所以没人显示 0；想亲眼看到 0，先临时 `INSERT INTO 读者 VALUES ('005','钱七',0);` 跑完再 `DELETE`。

</details>

# ④ 回炉题（D6 第1轮：连接查询 + D3 第2轮：约束/去重）

> D6 昨天刚学，按 D+1 规则今天第一次回炉；D3 的 CHECK/CASCADE/DISTINCT 是第二轮。

## 回 1【判断】内连接的结果

内连接（INNER JOIN）的结果集是两个表的交集。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 内连接只保留两边都有匹配的行（交集）。口诀：**内连接 = 找交集**。

</details>

---

## 回 2【判断】左连接一定大于内连接

左连接（LEFT JOIN）的结果集一定比内连接大。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**错。** 左连接是"**不小于**"内连接，不是"一定大于"——左表每行都有匹配时，两者**相等**。你昨天 D6 题 3 亲手抓出过这个坑，今天再巩固一次：**看到"一定"先找反例**（反例就是"没有落单行"，你库里读者个个都借过书，两种连接结果一样，都是 5 行）。

</details>

---

## 回 3【判断】自连接要不要别名

自连接（同一张表连自己）必须给表起别名。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 同一张表在 FROM 和 JOIN 后面各出现一次，不起别名 MySQL 分不清，直接报 `Not unique table/alias`。判据：连接条件里出现"本表的普通列 = 本表的主键"，就是自连接。

</details>

---

## 回 4【单选】CHECK 属于哪类完整性

`CHECK` 约束属于（ ）。

A. 实体完整性　B. 参照完整性　C. 用户定义完整性　D. 安全性

<details><summary>👉 点开对照答案与解析</summary>

**C。** CHECK 是业务自定的规矩（如馆藏量 ≥ 0），属于用户定义完整性。口诀：**主键管实体、外键管参照、其余（NOT NULL/UNIQUE/CHECK/DEFAULT）都是用户定义**。

</details>

## 回 5【单选】级联删除

删除读者时，其借阅记录也自动删除，建表时外键写的是（ ）。

A. `ON DELETE RESTRICT`　B. `ON DELETE CASCADE`　C. `ON DELETE SET NULL`　D. `ON DELETE SET DEFAULT`

<details><summary>👉 点开对照答案与解析</summary>

**B。** CASCADE = 级联：父删子也删。A 是默认方案（拒绝删）、C 是置空、D 是置默认值。D3 你亲手做过"删赵六、借阅记录自动蒸发"的实验，就是 CASCADE 在执法。

</details>

---

## 回 6【判断】DISTINCT 的位置

`DISTINCT` 关键字必须紧跟 `SELECT` 关键字后面。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** DISTINCT 只能紧跟 SELECT，后面才是列名：`SELECT DISTINCT 出版社 FROM 图书`。放别处都是语法错误。

</details>
