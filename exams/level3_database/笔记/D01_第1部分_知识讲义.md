## 单元一 · 数据库是什么？（模块 1 理论）

### 1.1 数据库、数据库管理系统、数据库系统

先分清三个词，考试最爱偷换概念：

| 词 | 是什么 | 比喻 |
|---|---|---|
| **数据库 DB** | 一堆**有组织的数据**本身 | 仓库里的**货** |
| **数据库管理系统 DBMS** | 管理数据的**软件**（MySQL 就是 DBMS） | 仓库的**管理员**（你跟他说话，他帮你搬货） |
| **数据库系统 DBS** | DB + DBMS + 应用程序 + 人（DBA、用户）的**整体** | **整个仓库+管理员+进出货流程+人** |

记法：**DB 是货，DBMS 是管理员，DBS 是整座仓库**。题目问"MySQL 是什么"→ 答 **DBMS**（不是 DB！）。

### 1.2 三级模式结构（必考）

同一个数据库，从三个不同角度看：

| 层级 | 另一个名字 | 看的是什么 | 个数 |
|---|---|---|---|
| **外模式** | 子模式 / 用户模式 | 每个用户看到的**局部视图**（你只能看到跟你有关的数据） | **多个** |
| **模式** | 逻辑模式 | 全体数据的**逻辑结构**（所有表长什么样） | **一个** |
| **内模式** | 存储模式 | 数据在磁盘上**怎么存**（文件、索引） | **一个** |

图书馆比喻：**内模式** = 书库里书架实际怎么摆；**模式** = 图书馆的总书目（所有书都登记在内）；**外模式** = 你在检索机上查到的属于你的借阅清单。
口诀：**外多个、内一个、中间模式独一个**。

### 1.3 两级映像与数据独立性（必考，最爱出陷阱）

数据库的好处是"**数据变了，程序不用改**"，靠的就是两级映像：

- **逻辑独立性**：模式（逻辑结构）变了，比如表里加一列 → 应用程序不用改。
  → 靠**外模式/模式映像**。记法：改"逻辑"靠"外-模"。
- **物理独立性**：内模式（存储方式）变了，比如换硬盘 → 模式不用改。
  → 靠**模式/内模式映像**。记法：改"存储"靠"模-内"。

⚠️ 陷阱：题目常把对应关系写反（"模式/内模式映像保证逻辑独立性"就是**错**的）。背口诀：**改逻辑靠外模，改存储靠内模**。

### 1.4 数据模型的类别与代表产品（必背配对）

数据模型 = 描述数据的方式，历史上有四代：

| 模型 | 数据结构 | 代表产品 | 比喻 |
|---|---|---|---|
| **层次模型** | **树**（一个爹多个娃） | **IMS**（IBM，最早商用） | 公司组织架构图 |
| **网状模型** | **图**（多对多随便连） | **DBTG / IDMS** | 城市地铁线路图 |
| **关系模型** | **二维表**（现在的主流） | **Oracle、MySQL、SQL Server** | Excel 表格 |
| **NoSQL** | 分四类（见下） | Redis / MongoDB / HBase / Neo4j | 各有绝活的工具 |

NoSQL 四大类（必背）：

| 类型 | 代表产品 | 比喻 |
|---|---|---|
| 键值型 | **Redis** | 储物柜：号码牌→箱子，取放最快 |
| 文档型 | **MongoDB** | 文件袋：每个袋里装一份自由格式文档 |
| 列族型 | **HBase** | 按竖列分类的大账本，适合海量数据 |
| 图型 | **Neo4j** | 社交关系网：人=节点，朋友关系=连线 |

口诀：**键 Redis、文 Mongo、列 HBase、图 Neo**。

## 单元二 · 关系模型的术语（模块 2 理论）

关系模型把数据看成**二维表**，术语对照一张花名册：

| 术语 | 含义 | 花名册里的对应 |
|---|---|---|
| 关系 | 一张表 | 整张花名册 |
| 元组 | 一行（一条记录） | 一个学生 |
| 属性 | 一列（一个字段） | "学号""姓名"这种栏目 |
| 域 | 一列的取值范围 | 成绩只能是 0~100 |
| 候选码 | 能唯一确定一行的**最小**属性集 | 学号（或身份证号） |
| 主键 PRIMARY KEY | 从候选码里选定的那个 | 就用学号当唯一标识 |

⚠️ 数据模型**三要素**（也是必考）：**数据结构 + 数据操作 + 完整性约束**。别和"ER 模型三要素（实体、属性、联系）"搞混——两拨东西，后面 D12 会再见到后者。

## 单元三 · SQL 第一课：建库 → 建表 → 插数据 → 查数据（实操）

### 3.0 先学会"读"SQL

SQL 是一句句**英语祈使句**：动词开头（CREATE=创建、INSERT=插入、SELECT=选取），分号 `;` 结尾。语法关键字习惯写**大写**（不强制），表名列名用中文也完全合法。

### 3.1 建库 + 进库

```sql
CREATE DATABASE exam_practice;   -- 创建数据库（= 开一个新仓库）
USE exam_practice;               -- 使用它（= 走进这个仓库）
```

逐词：`CREATE`（创建）`DATABASE`（数据库）`exam_practice`（库名，你自己起）`;`（句号）。
`USE` = "接下来所有操作都发生在这个库里"——**不写 USE，表就建错地方了**。

### 3.2 建表（范例：图书表）

```sql
CREATE TABLE 图书(
  书号 CHAR(8) PRIMARY KEY,        -- 定长8位编号，主键
  书名 VARCHAR(50) NOT NULL,       -- 书名最长50字，不能为空
  作者 VARCHAR(20),                -- 作者，允许空
  价格 DECIMAL(6,2) DEFAULT 0,     -- 价格：共6位、2位小数，默认0
  库存 INT DEFAULT 0               -- 库存：整数，默认0
);
```

**逐词解析：**

- `CREATE TABLE 图书(...)` —— 固定句式"创建一张名叫图书的表"，括号里是**列清单**，每列占一行、逗号分隔（**最后一列后面没有逗号**，新手最常在这报错）。
- `书号 CHAR(8)` —— 列名"书号"，类型 `CHAR(8)` = **定长** 8 个字符（不满 8 位也占满 8 位）。`VARCHAR(50)` = **可变长**最多 50 字符（存几个占几个）。记法：**CHAR 死板、VARCHAR 灵活**，短编号用 CHAR，文本用 VARCHAR。
- `PRIMARY KEY` —— 主键约束 = "这一列的值**唯一且不空**，是每行的身份证号"。一个表只能有一个主键。
- `NOT NULL` —— 非空约束 = "这一列**必须填**"。
- `DECIMAL(6,2)` —— 小数类型，括号 = （总位数，小数位数）。6,2 = 最多 `9999.99`。钱、价格都用 DECIMAL，不用 FLOAT（浮点会丢精度）。
- `DEFAULT 0` —— 默认值约束 = "不填就自动填 0"。

一句话记忆：**每列 = 列名 + 类型 +（可选）约束**。约束就是"给这列立的规矩"。

### 3.3 插数据

```sql
INSERT INTO 图书 VALUES
  ('B001','数据库系统概论','王珊',59.00,120),
  ('B002','SQL必知必会','福塔',39.50,0);
```

逐词：`INSERT INTO 图书 VALUES (...)` = 固定句式"往图书表里塞一行，VALUES 括号里按**建表时的列顺序**依次给值"。
细节：**文字用单引号包起来**，数字不用；一行插多条时，每行一个括号、中间逗号。

### 3.4 查数据（范例：查库存 ≥ 100 的书，按价格从高到低）

```sql
SELECT 书名, 价格 FROM 图书 WHERE 库存 >= 100 ORDER BY 价格 DESC;
```

逐词：
- `SELECT 书名, 价格` —— "挑选出这两列"（`*` 表示全部列）
- `FROM 图书` —— "从图书表里取"
- `WHERE 库存 >= 100` —— "只要库存大于等于 100 的行"（**筛行**的关卡）
- `ORDER BY 价格 DESC` —— "结果按价格**降序**排"（`DESC`=descend 降；`ASC`=ascend 升，默认升序）

⚠️ 最该记住的是**执行顺序**（考试会考，写复杂查询也靠它）：
**FROM（取哪张表）→ WHERE（筛掉哪些行）→ SELECT（挑哪些列）→ ORDER BY（排序）**
就像：**先抱来整箱货 → 挑出合格的 → 贴上标签 → 按标签排好**。
