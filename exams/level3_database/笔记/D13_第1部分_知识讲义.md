## 单元二：ER 模型三要素

ER 模型用三种图形描述世界：

| 要素 | 图形 | 是什么 | 图书馆例子 |
|---|---|---|---|
| **实体** | **矩形** | 一类"东西" | 读者、图书、出版社 |
| **属性** | **椭圆** | 实体的特征 | 读者的"读者编号、姓名" |
| **联系** | **菱形** | 实体之间的关联 | 读者 **借阅** 图书 |

**画图约定（考试会考）**：

- 主键属性在椭圆里**画下划线**（`<u>读者编号</u>`）
- 联系的**属性**也画成椭圆，用线连到**菱形**上（不是连到实体）
- 一个实体可以有多条线连不同联系

**注意区分**："实体"和"属性"别搞反——**实体是"名词性的东西"，属性是"描述这个东西的信息"**。读者是实体，"姓名"是属性；图书是实体，"书名"是属性。

## 单元三：联系的三种类型（1:1 / 1:N / M:N）

这是 ER 图**最重要**的分类，直接决定 9b 怎么转换。

### 怎么判断：**拿一端的一个实体，去数另一端能对上几个**

### ① 1:1（一对一）

> 一个读者 ↔ 一张借书证。

拿"一个读者"去数：只能有 1 张借书证；反过来，一张借书证也只属于 1 个读者 → **1:1**。

### ② 1:N（一对多）

> 一个出版社 ↔ 多本图书；一本书 ↔ 1 个出版社。

拿"一个出版社"去数：能出 N 本书；拿"一本书"去数：只属于 1 个出版社 → **1:N**。

⚠️ **方向很重要**：是"**出版社 1 : N 图书**"，不是反过来。写在箭头/标记上时，**"1"在出版社那头，"N"在图书那头**。

### ③ M:N（多对多）

> 一个读者 ↔ 多本书；一本书 ↔ 多个读者（可以被很多人借）。

两边都是"多" → **M:N**。

### 判断题速判表

| 场景 | 左边数右边 | 右边数左边 | 结论 |
|---|---|---|---|
| 读者—借书证 | 1 个读者 1 张证 | 1 张证 1 个读者 | **1:1** |
| 出版社—图书 | 1 个社 N 本书 | 1 本书 1 个社 | **1:N** |
| 读者—图书(借阅) | 1 个读者 N 本书 | 1 本书 N 个读者 | **M:N** |
| 学生—课程(选课) | 1 个学生 N 门课 | 1 门课 N 个学生 | **M:N** |
| 班级—学生 | 1 个班 N 个学生 | 1 个学生 1 个班 | **1:N** |

**记忆**：**看"一个"能不能对上"一个"**——两边都只对 1 个是 1:1；只有一边能对多个是 1:N；两边都能对多个是 M:N。

## 单元四：参与度与弱实体（客观题考点）

### 参与度（min, max）——"至少几次、至多几次"

在联系线旁标 `(min, max)`：

| 例子 | 参与度 | 含义 |
|---|---|---|
| 读者 —借阅— | **(0, N)** | 一个读者可以**一次都不借**（0），也可以借很多本（N） |
| 借书证 —属于— | **(1, 1)** | 每个读者**必须有且只有**一张借书证 |
| 图书 —被借— | **(0, N)** | 一本书可以一直没人借，也可以被借很多次 |

**考点**：`min = 0` 表示"**可以不参与**"（可选参与）；`min ≥ 1` 表示"**必须参与**"（全部参与 / 强制参与）。

### 弱实体——"没有自己的完整身份证"

**弱实体**：没有自己的主键，**必须依赖另一个实体（强实体）才能存在**。

- 图形：**双矩形**（实体）、**双菱形**（联系）
- 键：由"**强实体的键 + 自己的部分键**"组合而成
- 经典例子：**职工—家属**。家属没有独立编号，只能靠"哪个职工的哪个家属"来标识。
- 你库里的例子：如果把"借阅记录"当成弱实体，它靠"读者编号 + 借阅序号"才能唯一标识。

**判据**：**这个实体能不能脱离对方单独存在？** 能 → 普通实体；不能 → 弱实体。

## 单元五：ER → 关系模式转换（9b，今天的核心）

**四条规则，必须背熟**：

### 规则 1：每个**实体** → 一张表

实体的属性 → 表的列；实体的键 → 表的主键。

```
读者(读者编号, 姓名)          →  CREATE TABLE 读者(读者编号, 姓名)
出版社(出版社编号, 出版社名)   →  CREATE TABLE 出版社(出版社编号, 出版社名)
```

### 规则 2：**1:N 联系** → **不单独建表**，把"1"端的键放进"N"端

**例**：出版社 1 : N 图书

```
图书(图书编号, 书名, 出版社编号)   ← 把"1"端（出版社）的键，放进"N"端（图书）
```

**为什么**：一本书只属于一个出版社，所以"出版社编号"放进图书表**不会重复、不会冲突**。反过来把"图书编号"放进出版社表就不行了——一个出版社有多本书，放不进去。

### 规则 3：**M:N 联系** → **必须单独建一张表**

- 表的属性 = **两端实体的键** + **联系自己的属性**
- 主键 = **两端实体键的组合**

**例**：读者 M : N 图书（借阅）

```
借阅(读者编号, 图书编号, 借阅日期, 应还日期)
主键 = (读者编号, 图书编号)
```

**为什么必须单独建表**：一个读者借多本、一本书被多人借，任何一端都塞不下对方——只能单开一张"配对表"。

### 规则 4：**1:1 联系** → 可以**合并**，也可以**单独建表**

- 合并：把一端的键放到另一端（哪边都可以，看语义）
- 单独建表：键 = 两端的键

**例**：读者 1 : 1 借书证

```
方案 A（合并）：读者(读者编号, 姓名, 借书证号)
方案 B（单独）：借书证(读者编号, 借书证号)
```

**考试建议**：题目没说时，**1:1 用合并更常见**（少一张表）；但如果联系有较多自己的属性、或参与是"可选"的，单独建表更合理。

### 规则 5（补充）：**三元联系**（三个实体一起参与）

**单独建表**，键 = **三个实体键的组合**，加上联系属性。

## 单元六：完整转换例子（图书馆）

### 需求（ER 图）

- **实体**：
  - 读者(读者编号, 姓名)
  - 图书(图书编号, 书名)
  - 出版社(出版社编号, 出版社名)
- **联系**：
  - **出版**：图书 N — 1 出版社
  - **借阅**：读者 M — N 图书，联系属性：借阅日期、应还日期

### 转换过程（对着规则走）

| 步骤 | 用哪条规则 | 结果 |
|---|---|---|
| 读者实体 | 规则 1 | `读者(读者编号, 姓名)` |
| 图书实体 | 规则 1 | `图书(图书编号, 书名, **出版社编号**)` ← 规则 2 把 1 端键放进来 |
| 出版社实体 | 规则 1 | `出版社(出版社编号, 出版社名)` |
| 借阅联系 | 规则 3 | `借阅(**读者编号, 图书编号**, 借阅日期, 应还日期)` |

### 最终关系模式

```
读者( 读者编号, 姓名 )
图书( 图书编号, 书名, 出版社编号 )      ← 外键：出版社编号 → 出版社
出版社( 出版社编号, 出版社名 )
借阅( 读者编号, 图书编号, 借阅日期, 应还日期 )   ← 主键：(读者编号, 图书编号)
```

**对照你库里的真实表**：

| 转换结果 | 你库里实际的表 | 差别 |
|---|---|---|
| 借阅(读者编号, 图书编号, 借阅日期, 应还日期) | 借阅(借阅号, 读者编号, 图书编号, 借阅日期, 应还日期, 归还日期) | 实际多了一个**代理主键借阅号**（做法合理，但**ER 转换的标准答案**用组合键） |

> ⚠️ 考试写 ER 转换时，**按标准答案用组合键**（读者编号, 图书编号），别自作主张加自增代理键——除非题目要求。

## 单元七：转换口诀 + 今日自查

### 四句口诀（背下来）

> **一实体一张表，实体属性变列、实体键变主键。**
> **1:N 不建表，1 的键放进 N。**
> **M:N 必建表，两键拼成键。**
> **1:1 可合可拆，合了就放键。**

### 自查

- [ ] ER 三要素：实体=矩形、属性=椭圆、联系=菱形
- [ ] 1:1 / 1:N / M:N 的判法：拿"一个"去数"几个"
- [ ] 参与度 `(min,max)`：min=0 可选、min≥1 强制
- [ ] 弱实体：双矩形、无独立主键、靠"强实体键+部分键"标识
- [ ] 转换四规则：实体→表、1:N→键放 N 端、M:N→单独建表、1:1→可合可拆
- [ ] M:N 建表的主键 = **两端键的组合**
- [ ] 考试写转换用**组合键**，不擅自加自增代理键
