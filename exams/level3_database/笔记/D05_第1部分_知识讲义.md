## 单元一：ORDER BY——给查询结果"排队"

### 为什么需要排序

`SELECT * FROM 读者` 查出来的行，**顺序没有任何保证**——MySQL 想怎么吐就怎么吐。想让结果"从高到低""从 A 到 Z"，必须用 `ORDER BY` 明确说。

### 语法逐词拆

```sql
SELECT * FROM 读者 ORDER BY 借阅次数 DESC;    -- 按借阅次数从高到低
SELECT * FROM 读者 ORDER BY 借阅次数;          -- 不写就是 ASC 升序，从低到高
```

- **ORDER BY 列**：按哪一列排队。
- **ASC / DESC**：升序（从小到大）/ 降序（从大到小）。**不写默认 ASC**（判断题考点）。
- 数字列按大小、字符串列按字符顺序、日期列按时间先后。

### 多列排序（今天实操的主角）

```sql
SELECT * FROM 借阅 ORDER BY 读者编号, 应还日期 DESC;
```

读法：**先按读者编号升序排；读者编号相同的行，再按应还日期降序排**。

- 多个排序键用**逗号**隔开，**排在前面的键优先级高**。
- ⚠️ 关键考点：**DESC 只管紧挨着它的那一列**——上面这句里，`读者编号` 是升序、`应还日期` 是降序。想要两列都降序得写 `ORDER BY 读者编号 DESC, 应还日期 DESC`。

### 两个小技巧（选择题爱考）

- **按列序号排**：`ORDER BY 3` = 按 SELECT 列表的**第 3 列**排。
- **按别名排**：`SELECT 借阅次数 AS 次数 FROM 读者 ORDER BY 次数` —— ORDER BY 里能用 SELECT 里起的别名。

### 中文怎么排？（实操题 11 的预告）

MySQL 的 utf8 排序按**字符编码**排，不是拼音：`人民邮电出版社`（人=编码 U+4EBA）会排在 `高等教育出版社`（高=编码 U+9AD8）**前面**。所以**以实际输出为准**，别按拼音直觉猜。

### 执行顺序小剧透（完整版在明天）

一条查询的执行顺序：**FROM（拿表）→ WHERE（过滤行）→ SELECT（挑列）→ ORDER BY（排队）**——排序是**最后**做的。这解释了为什么 WHERE 里不能用别名、ORDER BY 里可以。

## 单元二：聚合函数——把一列"压"成一个数

### 五兄弟

| 函数 | 干什么 | 例（读者表借阅次数 5/8/3/2） |
|---|---|---|
| COUNT | 数个数 | 见下 |
| SUM | 求和 | SUM(借阅次数) = 18 |
| AVG | 平均 | AVG(借阅次数) = 4.5 |
| MAX | 最大 | MAX(借阅次数) = 8 |
| MIN | 最小 | MIN(借阅次数) = 2 |

**聚合查询的结果永远是"一行一个数"**——一张 1000 万行的表，`SELECT SUM(馆藏量) FROM 图书` 出来只有一行（判断题考点）。

### COUNT 的两个面孔（今天最重要的考点）

```sql
SELECT COUNT(*) FROM 借阅;          -- 数"行数"：5 行 → 5
SELECT COUNT(归还日期) FROM 借阅;   -- 数"这一列里不是 NULL 的值"：归还日期全是 NULL → 0！
```

- **COUNT(*)**：数**行**，NULL 也算。
- **COUNT(列)**：数这一列里**非 NULL** 的个数。
- 借阅表的 `归还日期` 列现在全是 NULL（还没人还书）——你可以现场跑这两条，亲眼看 `5` 和 `0` 的差距。

### NULL 的规矩

**所有聚合函数都忽略 NULL 行**：SUM/AVG/MAX/MIN 遇到 NULL 就当这行不存在。所以"AVG 会把 NULL 当 0 算"是**错**的——AVG 直接跳过 NULL 行（理论题 8 考）。

### 别名 AS（让输出列名好看）

```sql
SELECT SUM(馆藏量) AS 藏书总量, AVG(馆藏量) AS 平均馆藏 FROM 图书;   -- 藏书总量=14，平均=3.5
```

不加 AS 时输出列名是难看的 `SUM(馆藏量)`，加了别名列名变成你要的字。中文别名也可以。

### DISTINCT 去重（今天正式"转正"）

D3 回炉时你见过 `SELECT DISTINCT 出版社 FROM 图书`——把重复行合并。今天它作为模块 5b 的正式成员归队：**DISTINCT 要紧跟 SELECT**，写在所有列名前面。

### 聚合 + WHERE：先过滤再算

```sql
SELECT COUNT(*) FROM 读者 WHERE 借阅次数 > 3;   -- 先筛出张三5、李四8 → 再数：2
```

执行顺序：**WHERE 先过滤 → 聚合再算**。所以"借阅次数大于 3 的读者有几位"不是先 COUNT 再加条件。

## 今日自查（上半场，学完讲义后过一遍）

- [ ] ORDER BY：默认升序、DESC 只管紧挨它的列、多列排序优先级
- [ ] 聚合结果永远一行；五兄弟各干什么
- [ ] COUNT(*) 与 COUNT(列) 的区别能说清（借阅表的 5 vs 0 你亲眼跑过）
- [ ] 聚合函数忽略 NULL；DISTINCT 紧跟 SELECT
- [ ] 执行顺序：FROM → WHERE → SELECT → ORDER BY
