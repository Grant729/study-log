## 题 1【判断】内连接的结果集

内连接的结果集是两个表的**交集**。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 内连接 = INNER JOIN，只保留两边都有匹配的行（交集）。

MySQL 中，内连接使用的关键字是（ ）。

<details><summary>👉 点开对照答案与解析</summary>

## 题 3【判断】左连接的结果集比内连接大

左连接的结果集**一定**比内连接大。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**错。** 左连接的结果集是"**不小于**"内连接，**不等于"一定大于"**——两者可以**相等**。

- 左连接 = 内连接的结果 **+** 左表里没匹配上的行（那些行右边补 NULL）。
- 如果**左表每一行都能在右表找到匹配**，"左表独有的行"就是 **0 行** → 两个结果**一模一样**。

**用你自己的库验证**（实测都是 5 行）：

```sql
SELECT COUNT(*) FROM 读者 INNER JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号;  -- 5
SELECT COUNT(*) FROM 读者 LEFT  JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号;  -- 5
```

**判断题技巧**：看到"**一定**""**必然**"，先去找反例。这道题的反例就是"没有落单行"——你库里恰好就是。

**若想考"对"，题干得这么写**：左连接的结果集**不小于**内连接（即 ≥）。→ 对。

</details>

## 题 4【单选】查三个表需要写几个 ON 条件

要连接三个表（A JOIN B ON 条件1 JOIN C ON 条件2），需要写（ ）个 ON 条件。

A. 1
B. 2
C. 3
D. 4

<details><summary>👉 点开对照答案与解析</summary>

**B。** 每增加一个表，加一个 ON 条件。FROM A JOIN B → 1 个；JOIN C → 再加 1 个，共 2 个。

</details>

## 题 5【判断】自连接需要起别名吗

自连接（同表连接）必须给表起别名。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 同一张表在 FROM 和 JOIN 后面各出现一次，MySQL 分不清你说的是哪一份。不起别名会直接报 `Not unique table/alias`。

</details>

## 题 6【判断】WHERE 在 SELECT 之前执行

一条 SELECT 查询中，WHERE 子句在 SELECT 子句之前执行。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 执行顺序：FROM → JOIN → ON → WHERE → SELECT → ORDER BY（LIMIT 在最后）。

</details>

在 ORDER BY 子句里，可以用 SELECT 中定义的列别名。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

## 题 8【单选】MySQL 用什么限制行数

MySQL 中，用来限制查询返回行数的关键字是（ ）。

A. `TOP`
B. `LIMIT`
C. `ROWNUM`
D. `FETCH FIRST`

<details><summary>👉 点开对照答案与解析</summary>

**B。** 四个里只有 `LIMIT` 是 MySQL 的写法。下面这张表在你本机 **MySQL 8.0.23 上全部实测过**：

| 写法 | 出自哪个数据库 | 你本机实测结果 |
|---|---|---|
| `LIMIT 2` | **MySQL** | ✅ 正常返回 002 李四 / 001 张三 |
| `TOP 2` | SQL Server | ❌ 报 1064 语法错误 |
| `ROWNUM <= 2` | Oracle | ❌ 报 1054 未知列 |
| `FETCH FIRST 2 ROWS ONLY` | SQL 标准（Oracle / DB2 等） | ❌ 报 1064 语法错误 |

⚠️ 一句话记牢：**MySQL 用 `LIMIT`，`TOP` 是 SQL Server 的**。很多教材和网上的例子是 SQL Server 写的，**别直接抄进 MySQL**。

> 📌 这道题原来的问法是"MySQL 没有以下哪种指令"、答案 B/C/D——那是个"单选却有三个答案"的坏题。现在改成单选了，考点更集中。

</details>

## 题 9【判断】内连接会自动过滤掉 NULL

内连接会自动过滤掉值为 NULL 的行。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** NULL 不等于任何值（包括另一个 NULL），所以 ON 条件永远不匹配，这种行会被丢掉。

</details>

## 题 10【判断】自连接可以用于查上下级关系

用自连接可以查"员工和上级的关系"。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 把"员工表"当成"员工"和"上级"两张表，连接条件是"员工.上级编号 = 上级.员工编号"。判据：**连接条件里出现"本表的普通列 = 本表的主键"，就是自连接**。

</details>

# ③ 代码实操（换汤不换药）

## 实操题 1：查所有借阅记录

**要求**：查出所有借阅记录（读者编号、读者姓名、图书编号、应还日期），按应还日期从旧到新排序。

**预期输出**：
```
读者编号 | 读者姓名 | 图书编号 | 应还日期
--------|---------|----------|----------
001     | 张三    | B001     | 2026-11-15
002     | 李四    | B002     | 2026-11-15
003     | 王五    | B003     | 2026-11-20
004     | 赵六    | B004     | 2026-11-20
004     | 赵六    | B001     | 2026-11-25
```
（应还日期相同的行，谁在前谁在后不固定，属正常。）

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者.读者编号, 读者.读者姓名, 借阅.图书编号, 借阅.应还日期
FROM 读者
INNER JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号
ORDER BY 借阅.应还日期 ASC;
```

</details>

## 实操题 2：查"借阅次数大于 3 的读者"

**要求**：查出借阅次数大于 3 的读者，显示读者编号、读者姓名、借阅次数，按借阅次数从高到低排序。

**预期输出**：
```
读者编号 | 读者姓名 | 借阅次数
--------|---------|----------
002     | 李四    | 8
001     | 张三    | 5
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者编号, 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 > 3
ORDER BY 借阅次数 DESC;
```

</details>

## 实操题 3：查"谁没借过书"

**要求**：分两步走。
① 先用 **LEFT JOIN** 列出所有读者及其借阅号（读者编号、读者姓名、借阅号），看左连接怎么"保住了所有人"；
② 再用 `WHERE ... IS NULL` 筛出没借过书的读者（读者编号、读者姓名）。

**预期输出**：
① 5 行
```
读者编号 | 读者姓名 | 借阅号
--------|---------|-------
001     | 张三    | 1
002     | 李四    | 2
003     | 王五    | 3
004     | 赵六    | 7
004     | 赵六    | 8
```
② **空表，0 行** ⚠️

> **②空是对的，不是你写错了。** 你库里 4 个读者**都借过书**，所以"没借过书的读者"确实一个都没有。
> 想亲眼看到"真能筛出人来"，可以先临时加一个：`INSERT INTO 读者 VALUES ('005','钱七',0);` → 再跑 ② 应出 1 行 → 看完删掉：`DELETE FROM 读者 WHERE 读者编号='005';`

<details><summary>👉 点开折叠答案</summary>

① 左连接保住所有读者：
```sql
SELECT 读者.读者编号, 读者.读者姓名, 借阅.借阅号
FROM 读者
LEFT JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号;
```

② 筛出没匹配上的：
```sql
SELECT 读者.读者编号, 读者.读者姓名
FROM 读者
LEFT JOIN 借阅 ON 读者.读者编号 = 借阅.读者编号
WHERE 借阅.借阅号 IS NULL;
```

**要点**：①里 004 赵六出现了两次（他借了两本）；如果某个读者没借过书，他的`借阅号`就是 **NULL**，②就是把这些 NULL 行捞出来。

</details>

## 实操题 4：查"借阅次数第二多的读者"

**要求**：查出借阅次数等于第二多的读者（**不要写死数值**，用子查询）。

**预期输出**：
```
读者编号 | 读者姓名 | 借阅次数
--------|---------|----------
001     | 张三    | 5
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者编号, 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 = (
    SELECT MAX(借阅次数) FROM 读者
    WHERE 借阅次数 < (SELECT MAX(借阅次数) FROM 读者)
);
```

**从里往外读**：里层取到最大值 8 → 中层"在比 8 小的里面"再取最大，得到 5 → 外层捞出借阅次数 = 5 的人：张三。

⚠️ **不要写 `MAX(借阅次数) - 1`**。它假设"第二名正好比第一名少 1"，你库里 8 − 1 = 7，**一个读者都查不到（空结果）**。真实数据里第一名 8、第二名 5，差距是 3。

</details>

## 实操题 5：查"借阅次数前两名的读者"

**要求**：查出借阅次数前两名的读者，显示读者编号、读者姓名、借阅次数（使用 `LIMIT`）。

**预期输出**：
```
读者编号 | 读者姓名 | 借阅次数
--------|---------|----------
002     | 李四    | 8
001     | 张三    | 5
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 读者编号, 读者姓名, 借阅次数
FROM 读者
ORDER BY 借阅次数 DESC
LIMIT 2;
```

⚠️ MySQL **没有 `TOP`**，`SELECT TOP 2 ...` 是 SQL Server 的写法。`LIMIT` 必须写在 `ORDER BY` **后面**、整条语句的**最末尾**。

</details>

## 回炉题 3【单选】NoSQL 配对（哪项是错的）

下列"**数据模型 —— 代表产品**"的配对中，**错误**的是（ ）。

A. 键值模型 —— Redis
B. 文档模型 —— MongoDB
C. 列族模型 —— Neo4j
D. 图模型 —— JanusGraph

<details><summary>👉 点开折叠答案</summary>

**C。** Neo4j 是**图模型**的代表产品，不是列族模型。列族模型的代表是 **HBase、Cassandra**。

**NoSQL 四类 + 代表产品（必背，客观题高频）**：

| 数据模型 | 代表产品 | 存什么 | 一句话 |
|---|---|---|---|
| **键值** | **Redis**、Memcached | 一个键 → 一个值 | 查询飞快，常当缓存 |
| **文档** | **MongoDB**、CouchDB | JSON 式文档 | 结构灵活，不用预先定表结构 |
| **列族** | **HBase**、Cassandra | 按列存储 | 海量稀疏数据、大数据场景 |
| **图** | **Neo4j**、JanusGraph | 节点 + 边 | 社交网络、知识图谱 |

口诀：**键 Redis、文 Mongo、列 HBase、图 Neo**。

⚠️ 两个高频干扰项：
- **Hadoop 不是 NoSQL 数据库**——它是一套大数据处理框架（HDFS 存文件 + MapReduce 算），跟数据库不是一回事。
- **MySQL 不是 NoSQL**——它是关系型数据库，常被塞进选项当错配（比如冒充"图模型"）。

> 📌 本题原来写成"MongoDB - HBase 算不算正确配对"、答案列 A、B 都对——那题**本身没有意义**（NoSQL 产品之间不存在"配对"关系）。考点只有一个：**每个数据模型有哪些代表产品**。已重写成标准问法。

</details>

## 回炉题 6【判断】自然连接 vs 等值连接

自然连接会自动匹配所有同名列。对还是错？

<details><summary>👉 点开折叠答案</summary>

**对。** 自然连接要求两个表有**相同名称的列**，MySQL 会自动用这些列做连接条件。等值连接需要手动写 ON 条件。

</details>
