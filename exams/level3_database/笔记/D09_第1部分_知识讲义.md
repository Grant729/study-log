## 单元一：先分清 SQL 的三大家族

到目前为止你写过的 SQL，其实分属两个家族。今天学第三个：

| 家族 | 缩写 | 关键字 | 管什么 | 你已学过 |
|---|---|---|---|---|
| **数据定义语言** | DDL | `CREATE` `ALTER` `DROP` | 管"表**长什么样**"（结构） | D3、D4 ✅ |
| **数据操纵语言** | DML | `INSERT` `UPDATE` `DELETE` | 管"表里**有什么**"（数据行） | **今天** |
| 数据控制语言 | DCL | `GRANT` `REVOKE` | 管"谁**能做什么**"（权限） | D17 学 |

**一句话记死**：**DDL 装修房子（墙、门、格局），DML 搬家具（往里放、挪、扔）。** 今天只讲搬家具。

> 你前面其实已经偷偷用过 DML 了——D3 题 13 你 `DELETE FROM 读者 WHERE 读者编号='004'` 删赵六、又 `INSERT` 恢复，那就是 DML。

## 单元二：INSERT——往表里放数据

### 语法两种写法

```sql
-- 写法一：按建表时的列顺序给全所有列
INSERT INTO 读者 VALUES ('005','钱七',0);

-- 写法二：只给指定列（其余列用默认值/自增）
INSERT INTO 读者 (读者编号, 读者姓名) VALUES ('006','孙八');
```

**逐词**：
- `INSERT INTO 表` —— 往哪张表塞
- `VALUES (...)` —— 要塞的值，括号里**顺序必须和列顺序一致**
- 写法二更安全：列名写清楚，不怕表结构列顺序变

### 一次插多行

```sql
INSERT INTO 读者 VALUES
('005','钱七',0),
('006','孙八',1);
```

多个括号、中间逗号——一次插两行（D1 就见过这招）。

### ⚠️ 三个会报错的地方

- **NOT NULL 列没给值** → 报 1048（D3 亲手见过）
- **主键重复** → 报 1062
- **外键引用不存在的值**（比如借阅表插个 999 号读者）→ 报 1452

这三条家规，DDL 建表时立下的，DML 插数据时被执法——**结构（DDL）约束数据（DML）**。

## 单元三：UPDATE——改数据

### 语法

```sql
UPDATE 读者
SET 借阅次数 = 6
WHERE 读者编号 = '001';
```

**逐词**：
- `UPDATE 表` —— 改哪张表
- `SET 列 = 新值` —— 把哪列改成什么
- `WHERE 条件` —— **改哪些行**。这是灵魂：没 WHERE，就是改全表！

### 三个常用变体

**① 改多列**（逗号隔开）：

```sql
UPDATE 读者 SET 借阅次数 = 9, 读者姓名 = '李四改' WHERE 读者编号 = '002';
```

**② 用表达式改**（在原值基础上算）：

```sql
UPDATE 图书 SET 馆藏量 = 馆藏量 + 1 WHERE 出版社 = '人民邮电出版社';
```

`馆藏量 = 馆藏量 + 1` 不是循环，是"把每行的馆藏量在原值上加 1"。**人邮所有书**一起 +1——因为 WHERE 命中了 2 行。

**③ WHERE 一次命中多行**：上面那句就是——`WHERE 出版社='人民邮电出版社'` 命中 B002、B003 两行，两行一起改。**UPDATE 不是一次只改一行，是改"所有满足 WHERE 的行"**。

### ⚠️ 最危险的坑：漏写 WHERE

```sql
UPDATE 读者 SET 借阅次数 = 0;   -- 没有 WHERE！4 个读者的借阅次数全清零
```

**这条别真跑**。它会把**全表每一行**都改成 0。DML 的杀伤力在"范围"——`WHERE` 就是那个"圈定范围"的护栏，漏写 = 全表遭殃。

## 单元四：DELETE——删数据

### 语法

```sql
DELETE FROM 借阅 WHERE 借阅号 = 8;
```

**逐词**：`DELETE FROM 表` 删**行**；`WHERE` 圈定删哪几行。

### ⚠️ 同样：漏写 WHERE = 删光

```sql
DELETE FROM 读者;   -- 没有 WHERE！读者表清空（表还在，数据没了）
```

### DELETE 和 DROP 别混（高频考点）

| 语句 | 删什么 | 表还在吗 | 属于 |
|---|---|---|---|
| `DELETE FROM 表` | 删**数据行** | ✅ 还在（空表） | DML |
| `DROP TABLE 表` | 删**整个表**（连结构） | ❌ 没了 | DDL |

**口诀**：**DELETE 清空抽屉里的东西，DROP 把抽屉整个砸了。** 所以"删光数据"用 DELETE、"删表"用 DROP——D4 学的三个 DROP 口诀接上了。

## 单元五：DML 会触发"家规"（呼应 D3）

D3 你学过外键的 `ON DELETE CASCADE`，还亲手做过"删赵六、借阅自动蒸发"。**那其实就是 DML 触发参照完整性**：

```sql
DELETE FROM 读者 WHERE 读者编号 = '004';
-- 借阅表里 004 的两行，被 CASCADE 自动删掉了
```

**理解这层因果**：`DELETE` 是 DML（删数据），外键的 CASCADE 是 DDL 建表时立的家规——**DML 一动父表数据，DDL 立的家规就自动执法**。这就是 D3 说的"参照完整性"在真实场景的样子。

> 同理，`UPDATE` 也能触发：比如把父表主键改了，子表外键可能跟着变（视 ON UPDATE 设置，考试一般只考 DELETE 的 CASCADE）。

## 单元六：三句话总结 + 今日自查

**DML 三兄弟 + 各自的灵魂**：

| 语句 | 干什么 | 灵魂 | 漏写灵魂的后果 |
|---|---|---|---|
| `INSERT INTO` | 放数据 | 列顺序对 | 报错（1048/1062/1452） |
| `UPDATE ... SET` | 改数据 | `WHERE` 圈范围 | 全表被改 |
| `DELETE FROM` | 删数据 | `WHERE` 圈范围 | 全表被删 |

**记法**：**INSERT 要对齐、UPDATE 要 WHERE、DELETE 要 WHERE**。

- [ ] 三大家族分清：DDL 管结构、DML 管数据、DCL 管权限
- [ ] INSERT 两种写法 + 一次插多行
- [ ] UPDATE 的 SET 能改多列、能用表达式（馆藏量+1）
- [ ] UPDATE/DELETE 漏 WHERE 的后果说得清
- [ ] DELETE 删行 vs DROP 删表，不混
- [ ] DML 触发外键 CASCADE（D3 的因果接上了）
