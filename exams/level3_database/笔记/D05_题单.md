## 题 1【判断】默认排序方向

ORDER BY 后面不写 ASC 或 DESC 时，默认按升序排。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 不写默认 ASC（讲义单元一）。`ORDER BY 借阅次数` 就是 `ORDER BY 借阅次数 ASC`。

</details>

## 题 2【单选】降序排序的效果

执行 `SELECT * FROM 读者 ORDER BY 借阅次数 DESC;` 的效果是（ ）。

A. 按借阅次数从低到高　B. 按借阅次数从高到低　C. 随机排列　D. 按读者编号排序

<details><summary>👉 点开对照答案与解析</summary>

**B。** DESC = 降序 = 从大到小。DESC 是 descend（下降）的缩写，ASC 是 ascend（上升）。

</details>

**C。** AVG = average。A 求和、B 数个数、D 最大。

## 题 4【单选】COUNT 的两个面孔

COUNT(*) 与 COUNT(列名) 的区别是（ ）。

A. COUNT(*) 更快
B. COUNT(列名) 忽略该列为 NULL 的行
C. COUNT(*) 只能用于主键表
D. 没有区别

<details><summary>👉 点开对照答案与解析</summary>

**B。** COUNT(*) 数行（NULL 也算）；COUNT(列) 只数非 NULL。你在讲义里亲眼看借阅表跑出 5 和 0 的差距。

</details>

## 题 6【单选】去重

查询借阅表中"出现过哪些读者编号（不重复）"，应使用（ ）。

A. SELECT DISTINCT 读者编号 FROM 借阅
B. SELECT 读者编号 FROM 借阅
C. SELECT UNIQUE 读者编号 FROM 借阅

## 题 8【单选】NULL 与 AVG

某列有 4 行数据，其中 1 行是 NULL、另外 3 行是 3、6、9。AVG(该列) 的结果是（ ）。

A. 4.5　B. 3.6　C. 6　D. 报错

<details><summary>👉 点开对照答案与解析</summary>

**C。** 聚合函数**忽略 NULL 行**：(3+6+9)/3 = 6。若把 NULL 当 0 算会得 4.5（A 是陷阱）。

</details>

<details><summary>👉 点开对照答案与解析</summary>

## 题 10【单选】多列排序

`ORDER BY 列1, 列2 DESC` 的含义是（ ）。

A. 先按列1升序，列1相同的行再按列2降序
B. 先按列2降序，再按列1升序
C. 两列都降序
D. 语法错误

<details><summary>👉 点开对照答案与解析</summary>

**A。** 前面的键优先级高；DESC **只管紧挨它的列2**，列1 仍是默认升序（讲义单元一）。两列都降序要写 `ORDER BY 列1 DESC, 列2 DESC`。

</details>

## 题 11【实操】双列排序

**【目的】** 亲手写多列排序，验证"前面的键优先、DESC 只管紧挨它的列"。
**【前置】** 图书表数据现状：B001 数据库系统概论/高等教育出版社/5，B002 R语言实战/人民邮电出版社/3，B003 Python编程/人民邮电出版社/4，B004 信息检索导论/高等教育出版社/2。
**【要求】** 查出**全部图书**，按**出版社升序**排列；**同一出版社**的，按**馆藏量从高到低**排列。
**【预期输出】**（注意：中文按字符编码排序，人民邮电出版社排在高等教育出版社前面——以本输出为准，别按拼音猜）：

```
B003  Python编程     人民邮电出版社  4
B002  R语言实战     人民邮电出版社  3
B001  数据库系统概论  高等教育出版社  5
B004  信息检索导论   高等教育出版社  2
```

**【提示】** 排序关键词 ORDER BY；两个排序键用逗号隔开；降序缩写 DESC。

<details><summary>👉 点开对照答案与解析</summary>

```sql
%%sql
SELECT * FROM 图书 ORDER BY 出版社 ASC, 馆藏量 DESC;
```

解析：`出版社 ASC` 是第一个键（人民邮电 < 高等教育，按字符编码）；同一出版社内，第二个键 `馆藏量 DESC` 生效（人民邮电：4 在 3 前；高等教育：5 在 2 前）。`ASC` 可省略（默认升序），写上更清楚。

</details>

## 题 12【实操】聚合五连

**【目的】** 一条查询同时用五个聚合函数，体会"一列压成一行"。
**【前置】** 读者表数据现状：张三5、李四8、王五3、赵六2（4 人）。
**【要求】** 用**一条**查询算出读者表的五个数：**读者总数、借阅次数总和、平均借阅次数、最高、最低**。给每列起中文别名。
**【预期输出】**（顺序：总数 / 总和 / 平均 / 最高 / 最低）：

```
4  |  18  |  4.5000  |  8  |  2
```

**【提示】** 五个函数：COUNT(*) / SUM / AVG / MAX / MIN；起别名用 AS；多个结果写在同一行 SELECT 后、用逗号隔开。

<details><summary>👉 点开对照答案与解析</summary>

```sql
%%sql
SELECT COUNT(*) AS 读者总数,
       SUM(借阅次数) AS 借阅总和,
       AVG(借阅次数) AS 平均,
       MAX(借阅次数) AS 最高,
       MIN(借阅次数) AS 最低
FROM 读者;
```

解析：五个函数作用在同一列上，一条查询输出一行五列。AVG 结果是 4.5000（18/4，MySQL 保留 4 位小数）——别把它误当成"4.5 错了"。

</details>

## 题 14【实操】先过滤再聚合

**【目的】** 验证执行顺序"WHERE 先过滤 → 聚合再算"。
**【前置】** 读者表数据现状：张三5、李四8、王五3、赵六2。
**【要求】** 查出**借阅次数大于 3 的读者有几位**（结果是一个数，并起别名"人数"）。
**【预期输出】**：

```
2
```

**【提示】** 过滤用 WHERE；数个数用 COUNT(*)。想清楚：WHERE 写在聚合前还是后？

<details><summary>👉 点开对照答案与解析</summary>

```sql
%%sql
SELECT COUNT(*) AS 人数 FROM 读者 WHERE 借阅次数 > 3;
```

解析：执行顺序 FROM 读者 → WHERE 借阅次数>3（筛出张三5、李四8 两行）→ COUNT(*) 数出 2。**WHERE 在前、聚合在后**——先过滤再算，这是"借阅次数大于 3 的人数"的正确思路。

</details>

## 回 6【实操】索引换汤（D4 题 14 在图书/读者表，今天换借阅表）

**【目的】** 把 D4 的"建索引 → 查索引 → 删索引"三步曲用在借阅表上，并发现一个新知识点。
**【前置】** 借阅表数据现状：5 行（借阅号 1/2/3/7/8）。
**【要求】** 三步：
1. 给借阅表的**应还日期**列建普通索引（索引名自拟，如 idx_应还）
2. 查看借阅表上有哪些索引
3. 把刚建的索引删掉（恢复现场）
**【预期输出】** 第 2 步应看到 **4 个索引**：PRIMARY（主键自带）、读者编号、图书编号（**两个外键列自动带的索引**）、你刚建的 idx_应还。
**【提示】** 索引建/删的关键词开头都是 CREATE/DROP INDEX；删索引要写 ON 表名。

<details><summary>👉 点开对照答案与解析</summary>

```sql
%%sql
CREATE INDEX idx_应还 ON 借阅(应还日期);
SHOW INDEX FROM 借阅;
DROP INDEX idx_应还 ON 借阅;
```

真实输出（本机已实测，SHOW INDEX 关键列）：

```
Key_name: PRIMARY     Column_name: 借阅号   ← 主键自带
Key_name: 读者编号    Column_name: 读者编号 ← 外键自动带的
Key_name: 图书编号    Column_name: 图书编号 ← 外键自动带的
Key_name: idx_应还    Column_name: 应还日期 ← 你建的
```

解析：三步曲与 D4 题 14 同构（换汤：借阅表）。**新知识点**：MySQL 给外键列**自动建索引**（保证"认亲"查得快）——所以借阅表上有 4 个索引而不是 2 个。

</details>
