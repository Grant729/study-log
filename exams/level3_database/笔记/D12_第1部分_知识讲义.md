# D12 第①部分 · 知识讲义 —— 模块 8 模式分解与规范化

> 学习方式：**先通读**（纯理论）。D11 学的是"**诊断**"（这张表是第几范式），今天学"**动手术**"（怎么把它拆成合格的表，以及怎么验证拆对了）。
> 标准量：理论 10 题 + 纸面应用 5 题 + 回炉 6 题。

---

## 单元一：拆表是"手术"，不是"随便切两半"

D11 你学会了怎么**判断**一张表有病（部分依赖 → 不是 2NF；传递依赖 → 不是 3NF）。

今天要回答的是：**有病怎么治？**

治疗手段叫**模式分解**——把一张大表 R 拆成几张小子表 R1、R2……。但拆表**不能随便切**：

> 切得不好，拆开的表**"接回去"就对不上原表了**——原来 4 行数据，接回来变成 8 行，凭空多出一堆假的借阅记录。

所以拆表有**硬性验收标准**，这是今天的全部内容。

---

## 单元二：一条铁律——拆完必须过两关

**合格的分解，必须同时满足两个条件**：

| 条件 | 含义 | 一句话 |
|---|---|---|
| **① 无损连接性** | 拆完后**自然连接**回去，能**原样还原**原表（不多不少） | 接得回去 |
| **② 保持函数依赖** | 原来表里的 FD，拆完后**全都还在**（合起来能推出原来的每条 FD） | 规则不丢 |

**两个都要**才算合格。而且**"无损"是底线**——一个分解哪怕丢了依赖，也绝不允许"接不回去"（那数据就错了）。

⚠️ **判断题高频**：说某个分解"保持无损连接和函数依赖"，两个都得满足才算对；只满足一个，说法就是错的。

## 单元三：怎么判"无损连接"——两个表的情形

### 定理（考试最常用的一条）

> R 分解成 **R1、R2** 两张表时，如果满足下面**任意一条**，这个分解就是**无损连接**的：
> - **R1 ∩ R2 → R1 − R2**，或
> - **R1 ∩ R2 → R2 − R1**

**怎么读这条定理**：

- `R1 ∩ R2` = 两张表的**公共属性**
- `R1 − R2` = R1 里**独有**的属性（R2 没有的）
- 整句意思：**公共属性必须能决定其中一张表的"独有部分"**——也就是**公共属性得是其中某张表的键**

**直觉**：两段管子接起来要靠一个"接口"。接口（公共属性）必须是**能唯一对上号**的（键），否则接的时候会"一对多"地乱配，凭空多出行。

### 例子：R(学号, 系名, 系主任)，FD：学号 → 系名、系名 → 系主任

**分解 A**：`R1(学号, 系名)` + `R2(系名, 系主任)`

- R1 ∩ R2 = {系名}
- R2 − R1 = {系主任}
- 检查：`系名 → 系主任` ✓（FD 里就有）
- → **无损** ✅

**分解 B**：`R1(学号, 系名)` + `R2(学号, 系主任)`

- R1 ∩ R2 = {学号}
- R1 − R2 = {系名}
- 检查：`学号 → 系名` ✓
- → **也是无损** ✅

> ⚠️ 注意：**分解 B 就是你在 D11 应用 2 写的那一版**。它**无损没问题**——问题出在下一单元（依赖丢了）。这也是为什么两个条件要**分开判**。

### "有损"长什么样

**R(学号, 姓名, 班级)**，FD：学号 → 姓名、学号 → 班级。拆成 `R1(学号, 姓名)` + `R2(姓名, 班级)`：

- 公共属性 = {姓名}
- 检查：`姓名 → 学号`？✗（会重名）；`姓名 → 班级`？✗（不成立）
- 两条都不满足 → **有损** ❌

**看看连接后发生了什么**（假设有两个同名的"张三"）：

```
R1                    R2
学号   姓名           姓名   班级
S01   张三            张三   一班
S02   张三            张三   二班
```

按"姓名"连接 → S01 会跟"一班"和"二班"**都**连上，S02 也一样 → 出来 **4 行**，可原表只有 **2 行**。**凭空多出来的两行是假数据** ❌

**这就是"有损"**：连接回去 ≠ 原表。**判据永远是"接回去能不能原样还原"。**

### 三张表及以上：用"逐步合并"

上面的定理只说了**两表**的情形。拆成三张表怎么判？——**连锁验证**（一步一步合）：

> 先把 R1、R2 合成 R12；再拿 **R12** 和 R3 判"两表无损"。每一步都无损 → 整体无损。

**例子**（应用 5 的三表分解 `R1(借阅号,读者编号,图书编号)` + `R2(读者编号,读者姓名)` + `R3(图书编号,图书名)`）：

- **第一步**：`R1 ∩ R2 = {读者编号}`，`R2 − R1 = {读者姓名}`，检查 `读者编号 → 读者姓名` ✓ → R1+R2 无损
- **第二步**：`R12 = R1 ⋈ R2 = (借阅号, 读者编号, 图书编号, 读者姓名)`，`R12 ∩ R3 = {图书编号}`，检查 `图书编号 → 图书名` ✓ → **整体无损** ✅

⚠️ **别用"每张表都跟主表单独验一遍"来代替**。看这个反例：

> `ρ = {R1(A,B), R2(B,C), R3(C,D)}`，FD：`A→B`、`B→C`、`C→D`

`R1 ∩ R3 = 空集`——你**没法**验 R1 和 R3 之间的无损（它俩直接连接会变成笛卡儿积）。但按连锁法：`R1∩R2={B} → C` ✓、`R12∩R3={C} → D` ✓，**整体无损** ✅。

**为什么必须按顺序合**：合并后**属性集变大了**，要检查的"公共属性 → 差"的对象也跟着变。拿原表两两硬比，会得出错误结论。

⚠️ **两张表没有公共属性会怎样**：它们的自然连接 = **笛卡儿积**（行数相乘、爆炸）。所以没有公共属性的两张表**本来就不该直接连**，必须**借中间表搭桥**——这正是"R2 和 R3 之间不用管无损"的底层原因。

## 单元四：怎么判"保持函数依赖"

**方法**：把拆完后**每张表上还能写出来的 FD** 收集起来，看**原来的每条 FD 是不是都还能推出来**。

### 回到分解 B：R1(学号, 系名) + R2(学号, 系主任)

| 原 FD | 拆完后还在吗 |
|---|---|
| `学号 → 系名` | ✅ 在 R1 里（R1 有学号、系名两列） |
| `系名 → 系主任` | ❌ **丢了**——R1 里没有"系主任"这一列，R2 里没有"系名"这一列，两个属性凑不到一张表里 |

→ 分解 B **不保持函数依赖** ❌

**丢了这条规则有什么后果**：以后要改"某系的系主任是谁"，你手里只有 `(学号, 系主任)` 这张表——得**一个一个学生地改**；而原来的设计里，"系主任"只在"系"这一层存一份，改一次就行。**规则丢了，冗余和更新异常就全回来了**——等于白拆。

### 对比分解 A：R1(学号, 系名) + R2(系名, 系主任)

| 原 FD | 拆完后还在吗 |
|---|---|
| `学号 → 系名` | ✅ 在 R1 里 |
| `系名 → 系主任` | ✅ 在 R2 里 |

→ **保持函数依赖** ✅

### 口诀（也是你 D11 错题 #6 的正解）

> **拆表要搬走的是"中间属性 + 它直接决定的东西"这一对** —— 即 `系名 → 系主任`
> **不要搬"起点 + 终点"** —— `学号 → 系主任` 是绕了一层得来的，拿它当表结构，中间那层规则就断了

**对照记**：

| 场合 | 用哪个属性 |
|---|---|
| 问"谁**传递依赖**于谁"（D10） | **起点**（学号） |
| **拆表**消除传递依赖（D12） | **中间属性**（系名） |

## 单元五：规范化的完整流程——拆表三步曲

拆表到底搬哪几列？**照着病来**：

### 第 1 步 · 治 1NF：处理"打包"的格子

有属性不是原子（一格塞了电话+邮箱）→ 拆成原子列，或拆成多行。

### 第 2 步 · 治 2NF：搬走"半个键"

发现**非主属性的部分依赖** → 把"**只靠半个键**"的属性，连同**它依赖的那个键部分**，一起搬出去。

**例**：`SC(学号, 课程号, 成绩, 姓名)`，已知 `学号 → 姓名`（部分依赖）

```
学生( 学号, 姓名 )          ← 搬走"学号 + 它决定的姓名"
选课( 学号, 课程号, 成绩 )   ← 留在原地
```

### 第 3 步 · 治 3NF：搬走"中间人"

发现**非主属性的传递依赖** → 把"**中间属性 + 它直接决定的东西**"搬出去。

**例**：`R(学号, 系名, 系主任)`，已知 `学号 → 系名 → 系主任`（传递依赖）

```
学生( 学号, 系名 )          ← 留在原地
系( 系名, 系主任 )          ← 搬走"中间属性系名 + 它决定的系主任"
```

### 三步对照表

| 步 | 针对的病 | 搬走的"一对" | 例子 |
|---|---|---|---|
| 1NF | 属性非原子 | —（拆列/拆行） | 联系方式 → 电话、邮箱 |
| **2NF** | 部分依赖 | **半个键** + 该部分决定的属性 | `(学号, 姓名)` |
| **3NF** | 传递依赖 | **中间属性** + 它直接决定的属性 | `(系名, 系主任)` |

**一句话记**：**2NF 搬"半个键"，3NF 搬"中间人"——搬的都是"决定者 + 被决定者"这一对。**

## 单元六：总结 + 今日自查

**今天三件事**：

1. 拆表**两个验收标准**：**无损连接** + **保持函数依赖**
2. **判无损（两表）**：公共属性必须是其中一张表的**键**（`R1∩R2 → R1−R2` 或 `→ R2−R1`）
3. **判保持依赖**：原来的每条 FD 是不是都还留在某张表里

**自查**：
- [ ] 无损连接 = 自然连接回去能**原样还原**原表（不多不少）
- [ ] 保持函数依赖 = 原 FD 拆完**都还在**
- [ ] 两表无损判据：`R1∩R2 → R1−R2` 或 `R1∩R2 → R2−R1`
- [ ] "有损"长什么样——两个同名的人被错误交叉连接，行数变多
- [ ] 拆表三步曲：2NF 搬"半个键+它的属性"、3NF 搬"中间人+它决定的属性"
- [ ] 接上错题 #6：**拆表用"直接依赖"那一对，不用"起点+终点"**
