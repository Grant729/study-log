## 单元一：范式是什么——D10 的病，今天的药

### 先回顾 D10 说的两种"病"

| 病 | 症状 | 后果 |
|---|---|---|
| **部分依赖** | 非主属性只靠候选键的**一部分**就能定 | 数据冗余（同一姓名重复存很多遍） |
| **传递依赖** | 非主属性靠**中间属性**间接定出来 | 冗余更深、改一处漏一处 |

**范式就是"表的健康等级"**，一级级往上治：

```
1NF  →  2NF  →  3NF  →  BCNF
（及格）（除部分）（除传递）（连主属性也管）
```

**关键**：等级是**递进**的——满足 2NF 的表**一定**满足 1NF；满足 3NF 的**一定**满足 2NF。反过来不成立。可以记成：

> **1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF**（越往后越严格，符合条件的表越少）

⚠️ **常见判断题**："一个表如果满足 3NF，它一定满足 BCNF" → **错**（3NF 比 BCNF 宽松）。反过来"满足 BCNF 一定满足 3NF" → **对**。

## 单元二：1NF——一格一个值（原子性）

### 定义

**每个属性都是原子的**：一格只能放一个不可再分的值。

### 反例（长这样就不合格）

**反例 A：一格塞两个值**

| 学号 | 姓名 | 联系方式 |
|---|---|---|
| 001 | 张三 | 13800001111 / zs@qq.com |

"联系方式"这一格里塞了电话和邮箱——**不是原子**。"电话号码"和"邮箱"是两个独立的属性，挤在一格就没法单独查"谁的邮箱是 zs@qq.com"。

**反例 B：一格塞一长串**

| 借阅号 | 读者 | 借的书 |
|---|---|---|
| 1 | 张三 | B001, B002, B003 |

"借的书"一格塞了三本书——**一对多的关系被硬塞进一格**。

### 怎么治

**拆！** 反例 A 拆成两列（电话、邮箱）；反例 B 拆成多行（一张借阅记录一行）。

**口诀**：**1NF = 一格一个值，不许"打包"。**

> 你这个库里的表**全都是 1NF**（每列都原子）。1NF 是"及格线"，绝大多数考试题的表都天然满足——题目真正要判的是 2NF 以上。

## 单元三：2NF——非主属性不许"只靠半个键"

### 定义

在 1NF 基础上：**消除非主属性对候选键的部分依赖**。

### 前提认知：只有"组合候选键"的表才谈得上 2NF

"部分依赖"说的是"只靠候选键的**一部分**"——如果候选键就一个属性，哪有"一部分"？所以**候选键是单属性的表，天然满足 2NF**（它想违反都违反不了）。这是判断题的送分点。

### 反例

```
SC( 学号, 课程号, 成绩, 姓名 )
候选键 = (学号, 课程号)
非主属性 = 成绩、姓名
```

逐个查非主属性有没有**部分依赖**：

- **成绩**：`(学号,课程号) → 成绩` 完全依赖 ✅ 合格
- **姓名**：`学号 → 姓名`，学号是候选键的**真子集** → **部分依赖** ❌

→ 只要有一个非主属性是部分依赖，**这张表就不是 2NF**。

### 怎么治

**把"只靠半个键"的属性拆出去，跟它依赖的那个属性组成新表**：

```
学生( 学号, 姓名 )          ← 姓名只靠学号，单独成表
选课( 学号, 课程号, 成绩 )   ← 成绩要两个键一起，留在原表
```

拆完后：选课表里成绩完全依赖 `(学号,课程号)` ✅；学生表里 姓名完全依赖 学号 ✅。两张都是 2NF。

**口诀**：**2NF = 非主属性必须靠"整个键"才能定，不能只靠键的一部分。**

## 单元四：3NF——非主属性不许"借道中转"

### 定义

在 2NF 基础上：**消除非主属性对候选键的传递依赖**。

### 反例

```
R( 学号, 系名, 系主任 )
候选键 = 学号（单属性）
非主属性 = 系名、系主任
```

候选键是单属性 → 天然没有部分依赖 → 是 2NF。再看**传递依赖**：

- `学号 → 系名` 直接 ✅
- `学号 → 系名 → 系主任`：借道**系名**中转 → **传递依赖** ❌

→ 有传递依赖，**不是 3NF**。

**病在哪**：同一个系的 100 个学生，"系主任"要重复存 100 遍；系主任一换，得改 100 行，漏一行就不一致。

### 怎么治

**把"中转属性 + 被它决定的属性"整体拆出去**：

```
学生( 学号, 系名 )      ← 只留直接依赖
系( 系名, 系主任 )      ← 中转关系和它的"下游"独立成表
```

**口诀**：**3NF = 非主属性不能被"另一个非主属性"带出来。**

> 🔗 **接上 D10 的错点**：你昨天在"系主任传递依赖于谁"上写成了"系名"（中间人），正确答案是"**学号**"（链条起点）。今天正好用得上——判断 3NF 时，你要找的是"**有没有哪个非主属性是传递依赖出来的**"，而定位传递依赖的第一步就是**认准起点**。记住：**顺着箭头往左看，最左边那个是起点。**

## 单元五：BCNF——连主属性也不放过

### 定义

在 3NF 基础上，再加一条：**每个决定因素都必须包含候选键**（即每个非平凡函数依赖的左边都是超键）。

翻译成人话：**3NF 只管"非主属性"，BCNF 连"主属性"也管**——主属性之间也不许有部分/传递依赖。

### 反例（经典考点，请慢慢读）

**规则**：每个教师只教一门课；每门课由多个教师教。

```
R( 学生, 课程, 教师 )
FD1: (学生, 课程) → 教师     （学生选某课，由某教师教）
FD2: 教师 → 课程             （每个教师只教一门课）
```

**第一步：找候选键**

- `(学生, 课程)` → 能定教师 ✅ 是候选键
- `(学生, 教师)` → 由 FD2 教师→课程，能推出课程 ✅ 也是候选键

→ **两个候选键**：`(学生,课程)` 和 `(学生,教师)`

**第二步：分主属性**

出现在任一候选键里的都算主属性 → **学生、课程、教师三个全是主属性**，**非主属性一个都没有**。

**第三步：判范式**

- 没有非主属性 → 谈不上"非主属性的部分/传递依赖" → **是 2NF，也是 3NF** ✅
- 但看 FD2：`教师 → 课程`，决定因素**教师**——它不是候选键（候选键是那两个组合）→ **违反 BCNF** ❌

**结论**：这张表**是 3NF，但不是 BCNF**。

**这个例子的价值**：它证明了"3NF ⇏ BCNF"。考试最爱用这类"全是主属性"的表来考你——看到"没有非主属性"，就要立刻警觉：**它必然满足 3NF，但 BCNF 还得单独查**。

**口诀**：**BCNF = 决定因素必须是键**（谁决定别人，谁自己就得是键）。

## 单元六：判断流程 + 对比总表

### 标准判断六步（照着走就不会乱）

```
第1步  找候选键（能唯一确定全表 + 最精简）
第2步  分主属性 / 非主属性（候选键里的 / 不在任何候选键里的）
第3步  1NF？所有属性原子吗        → 有"打包"的格子就不是
第4步  2NF？非主属性有部分依赖吗   → 有就不是
第5步  3NF？非主属性有传递依赖吗   → 有就不是
第6步  BCNF？每个决定因素都是超键吗 → 有不是的就不是
```

**简化口诀（考试速判）**：
- **候选键是单属性** → 天然满足 2NF，直接从 3NF 开始查
- **没有非主属性** → 天然满足 3NF，直接查 BCNF

### 对比总表（背这张表就够）

| 范式 | 消除什么 | 管谁 | 一句话 |
|---|---|---|---|
| **1NF** | 属性非原子 | — | 一格一个值，不许打包 |
| **2NF** | 非主属性对候选键的**部分**依赖 | 非主属性 | 别只靠半个键 |
| **3NF** | 非主属性对候选键的**传递**依赖 | 非主属性 | 别借道中转 |
| **BCNF** | 主属性对候选键的部分/传递依赖 | **主属性也管** | 决定因素必须是键 |

**递进关系**：`1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF`

**记法**：
- **2 除部分、3 除传递**（D10 学过这句）
- **BCNF 是 3NF 的加强版**，多管了主属性
