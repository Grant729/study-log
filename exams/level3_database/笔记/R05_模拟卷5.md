# 一、判断题（10 题 × 1 分 = 10 分）

## 题 1

表 A 有 10 行，表 B 有 **0 行**。`SELECT * FROM A LEFT JOIN B ON ...` 的结果是 **0 行**。

<details><summary>👉 答案与解析</summary>

**错。** 左连接保留**左表全部行**。B 是空表，A 的 10 行照样输出，右边补 NULL → **10 行**。

</details>

---

## 题 2

`COUNT(*)` 与 `COUNT(1)` 的结果相同。

<details><summary>👉 答案与解析</summary>

**对。** 两者都数**行数**（NULL 也算）。只有 `COUNT(列)` 只数非 NULL。

</details>

---

## 题 3

`WHERE 列 NOT IN (子查询)`，如果子查询的结果里包含 `NULL`，整个条件**可能一行都筛不出来**。

<details><summary>👉 答案与解析</summary>

**对。** 三值逻辑：`x <> NULL` 的结果是 **UNKNOWN**，`NOT IN` 因此对每一行都不成立 → 返回 0 行。这是 NULL 最阴的陷阱之一。

</details>

---

## 题 4

含 `GROUP BY` 的视图可以执行 `UPDATE`。

<details><summary>👉 答案与解析</summary>

**错。** 含聚合/GROUP BY 的复杂视图**不可更新**（一行结果对应基表多行，无法定位）。

</details>

---

## 题 5

事务中执行 `ROLLBACK` 后，**触发器**里已经执行过的 `UPDATE` 也会被撤销。

<details><summary>👉 答案与解析</summary>

**对。** 触发器和主体 DML 在**同一个事务**里，回滚会一起撤销。（本卷题 43 会让你亲手验证。）

</details>

---

## 题 6

外键列的值可以为 `NULL`。

<details><summary>👉 答案与解析</summary>

**对。** 参照完整性只约束**非 NULL** 的外键值；NULL 表示"暂未关联"，除非加了 `NOT NULL`。

</details>

---

## 题 7

一张表如果没有非主属性，它一定满足 2NF，但不一定满足 3NF。

<details><summary>👉 答案与解析</summary>

**错。** 没有非主属性 → 谈不上"非主属性的部分/传递依赖" → **必然满足 3NF**（但不一定 BCNF）。

</details>

---

## 题 8

两表分解 `R→R1,R2`，只要 `R1 ∩ R2` **非空**，这个分解就是无损连接。

<details><summary>👉 答案与解析</summary>

**错。** 公共属性非空只是前提；还必须满足 **`R1∩R2 → R1−R2` 或 `R1∩R2 → R2−R1`**。

</details>

## 题 9

HDFS 的 `SecondaryNameNode` 可以在 `NameNode` 故障时接管工作。

<details><summary>👉 答案与解析</summary>

**错。** 它只负责**合并 FsImage 和 EditLog**，**不是热备份**。

</details>

## 题 10

`LEFT JOIN` 后用 `COUNT(*)` 统计右表行数，没有匹配的左表行会被算作 **0**。

<details><summary>👉 答案与解析</summary>

**错。** 算作 **1**——LEFT JOIN 会补一行 NULL，`COUNT(*)` 数的是行。要用 `COUNT(右表列)` 才是 0。

## 题 14【ON vs WHERE · 结果推演】

## 题 15【NOT IN + NULL】

若 `就诊` 表里还有一条 `宠物号 = NULL` 的记录，执行：

```sql
SELECT COUNT(*) FROM 宠物 WHERE 宠物号 NOT IN (SELECT 宠物号 FROM 就诊);
```

结果是（ ）。

A. 1　B. 2　C. 0　D. 3

<details><summary>👉 答案与解析</summary>

**C（0）。** `NOT IN` 里有 NULL → 每行比较都得 UNKNOWN → 一行都筛不出。**空结果不代表没有符合条件的行，而是 NULL 把条件毁了。**

</details>

## 题 16【聚合空集】

`SELECT SUM(费用) FROM 就诊 WHERE 费用 < 0`（没有匹配行）的结果是（ ）。

<details><summary>👉 答案与解析</summary>

**B（NULL）。** 没有行可聚合时，`SUM` 返回 **NULL**，不是 0。要显示 0 需 `IFNULL(SUM(...),0)`。

## 题 23【候选键】

# 三、综合应用题（3 题 × 10 分 = 30 分）

## 题 41（10 分）综合设计（学校教务）

**需求描述**：

> 某学院需要管理教师、课程、部门和办公室。每位**教师**有教师号、姓名和职称；每门**课程**有课程号、课程名和学分；每个**部门**有部门号、部门名和电话；每间**办公室**有办公室号和面积。一个部门可以有多名教师，但一名教师只属于一个部门。一名教师可以讲授多门课程，一门课程也可以由多名教师讲授；每次授课需要记录**授课学期**。每间办公室只分配给一名教师，每名教师最多只有一间办公室。

**要求**：

1. （3 分）找出实体、属性和联系，指出**三个联系**各自的类型及理由
2. （4 分）转换为关系模式，标出主码和外码（1:1 联系请说明你放在哪一端）
3. （3 分）写出创建"**授课**"表的 SQL（复合主键 + 两个外键）

<details><summary>👉 答案与解析</summary>

**1. 实体、属性、联系（3 分）**

- 实体：教师(<u>教师号</u>, 姓名, 职称)、课程(<u>课程号</u>, 课程名, 学分)、部门(<u>部门号</u>, 部门名, 电话)、办公室(<u>办公室号</u>, 面积)
- 联系：
  - **属于**：教师 N — 1 部门（多教师属一部门）
  - **讲授**：教师 M — N 课程（属性：授课学期）
  - **分配**：办公室 1 — 1 教师

**2. 关系模式（4 分）**

```
部门( 部门号, 部门名, 电话 )
教师( 教师号, 姓名, 职称, 部门号 )        ← 属于 1:N，外码：部门号
课程( 课程号, 课程名, 学分 )
办公室( 办公室号, 面积, 教师号 )          ← 分配 1:1，外码：教师号（合并到办公室一端）
授课( 教师号, 课程号, 授课学期 )          ← 讲授 M:N
      主码 = (教师号, 课程号, 授课学期)
      外码：教师号 → 教师；课程号 → 课程
```

> 1:1 也可反过来把"办公室号"放进教师表，两种都算对；但**要把说明写清楚**。

**3. 建表 SQL（3 分）**

```sql
CREATE TABLE 授课 (
  教师号 CHAR(3) NOT NULL,
  课程号 CHAR(5) NOT NULL,
  授课学期 VARCHAR(20) NOT NULL,
  PRIMARY KEY (教师号, 课程号, 授课学期),
  FOREIGN KEY (教师号) REFERENCES 教师(教师号),
  FOREIGN KEY (课程号) REFERENCES 课程(课程号)
);
```

**陷阱点**：同一教师对同一课程可能在多个学期授课，所以主键必须带上"授课学期"，不能只有 `(教师号, 课程号)`。

</details>

## 题 42（10 分）诊断与改写（宠物医院）

**场景**：

- `就诊(就诊号, 宠物号, 费用)`

**数据**：
- 宠物：P01 豆豆、P02 咪咪、P03 旺财（**P03 从未就诊**）
- 就诊：V001/P01/600、V002/P01/300、V003/P02/800

**一位实习生写了两个查询**：

```sql
-- 查询①
SELECT 宠物.宠物名, COUNT(*) AS 就诊次数
FROM 宠物 LEFT JOIN 就诊 ON 宠物.宠物号 = 就诊.宠物号
GROUP BY 宠物.宠物名;

-- 查询②
SELECT 宠物.宠物名, COUNT(*) AS 就诊次数
FROM 宠物 LEFT JOIN 就诊 ON 宠物.宠物号 = 就诊.宠物号
WHERE 就诊.费用 > 500
GROUP BY 宠物.宠物名;
```

**要求**：

1. （4 分）分别指出查询①和查询②**各有什么问题**
2. （3 分）改写查询①：统计每只宠物的就诊次数，**没就诊过的显示 0**
3. （3 分）改写查询②：统计每只宠物**费用 > 500** 的就诊次数，**没有的显示 0**

**预期结果**：
- 改写①：豆豆 2、咪咪 1、旺财 0
- 改写②：豆豆 1、咪咪 1、旺财 0

<details><summary>👉 答案与解析</summary>

**1. 指错（4 分）**

- **查询①**：用了 `COUNT(*)`。LEFT JOIN 会给没就诊的 P03 补一行 NULL，`COUNT(*)` 把这行数进去 → **P03 显示 1（应为 0）**。
- **查询②**：把右表条件 `就诊.费用 > 500` 写在 **`WHERE`** 里。连接后再过滤，**P03 的 NULL 行被刷掉**，整个查询退化成内连接 → **P03 直接消失（应显示 0）**。

**2. 改写①（3 分）**

```sql
SELECT 宠物.宠物名, COUNT(就诊.就诊号) AS 就诊次数
FROM 宠物 LEFT JOIN 就诊 ON 宠物.宠物号 = 就诊.宠物号
GROUP BY 宠物.宠物号, 宠物.宠物名;
```

**3. 改写②（3 分）**

```sql
SELECT 宠物.宠物名, COUNT(就诊.就诊号) AS 就诊次数
FROM 宠物 LEFT JOIN 就诊
  ON 宠物.宠物号 = 就诊.宠物号 AND 就诊.费用 > 500
GROUP BY 宠物.宠物号, 宠物.宠物名;
```

> 也可以写 `SUM(CASE WHEN 就诊.费用 > 500 THEN 1 ELSE 0 END)`，但把条件挪到 `ON` 更简洁。

**评分要点**：① 必须 `COUNT(就诊.就诊号)`；② 条件必须放 `ON`（放 WHERE 会丢行）；两处都别漏。

</details>

## 题 43（10 分）触发器 × 事务（仓库出库）

**场景**：

- `商品(商品号, 库存)`
- `出库记录(记录号, 商品号, 数量)`，记录号自增主键

**要求**：

1. （4 分）建两张表；创建触发器 `trg_出库扣库存`：向出库记录插入时，自动把对应商品的库存**减去 `NEW.数量`**
2. （3 分）插入商品 `('P01', 100)`。然后执行：

   ```sql
   START TRANSACTION;
   INSERT INTO 出库记录(商品号,数量) VALUES ('P01',10);
   ROLLBACK;
   SELECT 库存 FROM 商品 WHERE 商品号='P01';
   ```

   **问：查询到的库存是多少？为什么？**
3. （3 分）再执行：

   ```sql
   START TRANSACTION;
   INSERT INTO 出库记录(商品号,数量) VALUES ('P01',10);
   COMMIT;
   SELECT 库存 FROM 商品 WHERE 商品号='P01';
   ```

   **问：查询到的库存是多少？**

**预期**：第 2 问 **100**；第 3 问 **90**

<details><summary>👉 答案与解析</summary>

**1. 建表 + 触发器（4 分）**

```sql
CREATE TABLE 商品 (
  商品号 CHAR(3) PRIMARY KEY,
  库存 INT NOT NULL
);

CREATE TABLE 出库记录 (
  记录号 INT PRIMARY KEY AUTO_INCREMENT,
  商品号 CHAR(3) NOT NULL,
  数量 INT NOT NULL,
  FOREIGN KEY (商品号) REFERENCES 商品(商品号)
);

CREATE TRIGGER trg_出库扣库存
AFTER INSERT ON 出库记录
FOR EACH ROW
BEGIN
  UPDATE 商品 SET 库存 = 库存 - NEW.数量 WHERE 商品号 = NEW.商品号;
END;
```

**2. ROLLBACK 后（3 分）**

**库存 = 100。**

- 插入出库记录后，触发器把库存改成 90（事务内可见）
- `ROLLBACK` 回滚的是**整个事务**，包括触发器执行的那条 `UPDATE`
- 所以库存恢复为 100

**3. COMMIT 后（3 分）**

**库存 = 90。**

- 插入 + 触发器扣减一起提交，永久生效

**核心认知**：**触发器不是独立事务**，它跟着主体 DML 走——主体回滚，触发器效果也回滚；主体提交，触发器效果也提交。

**清理**：

```sql
DROP TRIGGER IF EXISTS trg_出库扣库存;
```

</details>
