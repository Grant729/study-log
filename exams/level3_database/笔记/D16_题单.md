## 题 1【判断】触发器怎么执行

触发器不需要手动调用，当表上发生 INSERT / UPDATE / DELETE 时会自动执行。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 触发器 = 绑定在表上的"自动反应"（讲义单元一）。存储过程才需要手动 `CALL`。

</details>

## 题 2【单选】触发器绑定在什么上

触发器是绑定在（ ）上的。

A. 数据库　B. 某张表及其 INSERT/UPDATE/DELETE 事件　C. 视图　D. 存储过程

<details><summary>👉 点开对照答案与解析</summary>

**B。** 触发器的三要素：时机（BEFORE/AFTER）+ 事件（INSERT/UPDATE/DELETE）+ 表（讲义单元二）。

</details>

## 题 3【单选】DELETE 触发器中能用谁

在 `DELETE` 触发器里，能引用被删除那一行旧值的是（ ）。

A. `NEW.列`　B. `OLD.列`　C. 两者都能　D. 两者都不能

<details><summary>👉 点开对照答案与解析</summary>

**B（OLD）。** 口诀：**INSERT 只有 NEW、DELETE 只有 OLD、UPDATE 两个都有**（讲义单元二表格）。删除的行没有"新值"。

</details>

## 题 4【判断】BEFORE 里改 NEW

在 `BEFORE INSERT` 触发器里，可以用 `SET NEW.列 = ...` 修改即将写入的值。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** BEFORE 触发器在**写入之前**执行，所以改 NEW 有用（讲义单元三用途 3）。AFTER 里数据已经写进去了，改 NEW 没用。

</details>

## 题 5【单选】FOR EACH ROW

触发器里的 `FOR EACH ROW` 表示（ ）。

A. 只触发一次
B. 每影响一行就触发一次
C. 只对第一行触发
D. 对所有表触发

<details><summary>👉 点开对照答案与解析</summary>

**B。** 行级触发器：一条 SQL 影响几行，触发器就触发几次。MySQL 只支持行级触发器。

</details>

## 题 6【判断】事务的原子性

事务的原子性是指"事务里的操作要么全部成功，要么全部失败（回滚）"。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 原子性 Atomicity = 全做或全不做（讲义单元五）。口诀：**原子全或全不、一致不乱、隔离不扰、持久不丢**。

</details>

## 题 7【单选】ACID 的隔离性

事务的 ACID 中，"并发事务之间互不干扰"指的是（ ）。

A. 原子性　B. 一致性　C. 隔离性　D. 持久性

<details><summary>👉 点开对照答案与解析</summary>

**C（隔离性 Isolation）。** 原子=全或全不、一致=不乱、隔离=不扰、持久=不丢。

</details>

## 题 8【单选】S 锁与 X 锁的兼容性

下列锁的兼容关系，正确的是（ ）。

A. S 锁与 S 锁不兼容
B. S 锁与 X 锁兼容
C. X 锁与 X 锁兼容
D. **只有 S 锁与 S 锁兼容**

<details><summary>👉 点开对照答案与解析</summary>

**D。** 只有"读 + 读"能共存。只要有一个要写（X 锁），就得独占（讲义单元六兼容性表）。

</details>

## 题 9【单选】三级封锁协议

三级封锁协议能防止（ ）。

A. 只防丢失修改
B. 只防读脏数据
C. **丢失修改 + 读脏数据 + 不可重复读**
D. 只防死锁

<details><summary>👉 点开对照答案与解析</summary>

**C。** 三级 = 最严格那一级。递进记：**一级防丢失修改 → 二级再防读脏 → 三级再防不可重复读**（讲义单元六）。

</details>

## 题 10【判断】死锁

死锁是指两个或多个事务互相等待对方持有的锁，导致谁都无法继续。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** A 等 B 的锁、B 等 A 的锁 → 互相卡死。数据库会自动检测，回滚其中一个事务来解开。

</details>

# ③ SQL 实操（触发器 + 事务）

## 实操题 1：AFTER INSERT 审计触发器

**要求**：
① 建日志表 `图书日志(日志号 INT AUTO_INCREMENT PRIMARY KEY, 图书编号 CHAR(4), 书名 VARCHAR(50), 操作 VARCHAR(10), 记录时间 DATETIME)`
② 建触发器 `trg_图书审计`：**AFTER INSERT ON 图书**，每插一行图书，就往日志表写一条（图书编号、书名、操作写 `'新增'`、时间用 `NOW()`）
③ 插入一本 `('B097','审计测试','某社',1)`，查日志表验证

**预期日志**：
```
B097 | 审计测试 | 新增
```

<details><summary>👉 点开折叠答案</summary>

```sql
DROP TABLE IF EXISTS 图书日志;
CREATE TABLE 图书日志 (
  日志号 INT AUTO_INCREMENT PRIMARY KEY,
  图书编号 CHAR(4),
  书名 VARCHAR(50),
  操作 VARCHAR(10),
  记录时间 DATETIME
);
```

```sql
DROP TRIGGER IF EXISTS trg_图书审计;
CREATE TRIGGER trg_图书审计
AFTER INSERT ON 图书
FOR EACH ROW
BEGIN
  INSERT INTO 图书日志(图书编号, 书名, 操作, 记录时间)
  VALUES (NEW.图书编号, NEW.书名, '新增', NOW());
END;
```

```sql
INSERT INTO 图书 VALUES ('B097','审计测试','某社',1);
SELECT 图书编号, 书名, 操作 FROM 图书日志;
```

**要点**：触发器里用 `NEW.列` 拿刚插入那一行的值。

</details>

## 实操题 2：AFTER DELETE 自动维护（用 OLD）

**要求**：
① 建触发器 `trg_删借阅减次数`：**AFTER DELETE ON 借阅**，删除一条借阅记录时，把对应读者的借阅次数 **-1**（注意：删除的行要用 `OLD`）
② 先查 004 的借阅次数（应为 2），再删除 `借阅号 = 9` 的那条记录，再查 004 的次数（应变成 1）

**预期**：004 的次数 2 → 1

<details><summary>👉 点开折叠答案</summary>

```sql
DROP TRIGGER IF EXISTS trg_删借阅减次数;
CREATE TRIGGER trg_删借阅减次数
AFTER DELETE ON 借阅
FOR EACH ROW
BEGIN
  UPDATE 读者 SET 借阅次数 = 借阅次数 - 1
  WHERE 读者编号 = OLD.读者编号;
END;
```

```sql
SELECT 借阅次数 FROM 读者 WHERE 读者编号 = '004';   -- 2
DELETE FROM 借阅 WHERE 借阅号 = 9;
SELECT 借阅次数 FROM 读者 WHERE 读者编号 = '004';   -- 1
```

**要点**：**DELETE 只有 OLD**——被删掉的那一行叫 OLD。

</details>

## 实操题 3：BEFORE UPDATE 兜底

**要求**：
① 建触发器 `trg_馆藏更新兜底`：**BEFORE UPDATE ON 图书**，如果新的馆藏量 < 0，自动改成 0
② 把 B001 的馆藏量改成 -3，再查 B001，确认它变成了 0

**预期**：B001 的馆藏量最终是 **0**（不是 -3）

<details><summary>👉 点开折叠答案</summary>

```sql
DROP TRIGGER IF EXISTS trg_馆藏更新兜底;
CREATE TRIGGER trg_馆藏更新兜底
BEFORE UPDATE ON 图书
FOR EACH ROW
BEGIN
  IF NEW.馆藏量 < 0 THEN
    SET NEW.馆藏量 = 0;
  END IF;
END;
```

```sql
UPDATE 图书 SET 馆藏量 = -3 WHERE 图书编号 = 'B001';
SELECT * FROM 图书 WHERE 图书编号 = 'B001';
```

**要点**：必须用 **BEFORE**——要在写入之前改 `NEW`。UPDATE 触发器里 OLD 和 NEW 都能用，这里改的是 NEW。

</details>

## 实操题 4：事务——ROLLBACK 与 COMMIT 对比

**要求**：
① 开事务 → 插入 `('B098','事务测试','某社',1)` → **ROLLBACK** → 查 B098（应**查不到**）
② 再开事务 → 同样插入 B098 → **COMMIT** → 查 B098（应**查得到**）

**预期**：①空 ②有 B098

<details><summary>👉 点开折叠答案</summary>

```sql
START TRANSACTION;
INSERT INTO 图书 VALUES ('B098','事务测试','某社',1);
ROLLBACK;
```

```sql
SELECT * FROM 图书 WHERE 图书编号 = 'B098';   -- 空
```

```sql
START TRANSACTION;
INSERT INTO 图书 VALUES ('B098','事务测试','某社',1);
COMMIT;
```

```sql
SELECT * FROM 图书 WHERE 图书编号 = 'B098';   -- 有 B098
```

**要点**：ROLLBACK = 撤销未提交的操作；COMMIT = 永久生效。**提交之后就不能回滚了**。

</details>

## 实操题 5：清理现场（必做）

**要求**：
① 删掉今天建的 3 个触发器
② 删掉日志表
③ 恢复数据：
- 删除 B097、B098
- 把 B001 的馆藏量改回 5
- 把借阅号 9 重新插回去（`('004','B001','2026-10-08','2026-11-25')`，注意借阅日期和应还日期）
- 把 004 的借阅次数改回 2
④ 用 `SHOW TRIGGERS;` 确认没有触发器了

**验收**：触发器为空；读者 4 行、借阅 5 行、图书 4 行；B001 馆藏 5、004 次数 2。

<details><summary>👉 点开折叠答案</summary>

```sql
DROP TRIGGER IF EXISTS trg_图书审计;
DROP TRIGGER IF EXISTS trg_删借阅减次数;
DROP TRIGGER IF EXISTS trg_馆藏更新兜底;
DROP TABLE IF EXISTS 图书日志;

DELETE FROM 图书 WHERE 图书编号 IN ('B097','B098');
UPDATE 图书 SET 馆藏量 = 5 WHERE 图书编号 = 'B001';

INSERT INTO 借阅(借阅号,读者编号,图书编号,借阅日期,应还日期)
VALUES (9,'004','B001','2026-10-08','2026-11-25');
UPDATE 读者 SET 借阅次数 = 2 WHERE 读者编号 = '004';

SHOW TRIGGERS;
SELECT COUNT(*) FROM 读者;
SELECT COUNT(*) FROM 借阅;
SELECT COUNT(*) FROM 图书;
```

**要点**：`DROP TRIGGER` 和 `DROP PROCEDURE` 一样，删之前用 `IF EXISTS` 防报错。**恢复借阅次数要手动 UPDATE**——因为恢复用的是 INSERT，而触发器是 DELETE 触发的，不会自动加回来。

</details>

## 回 6【单选】拆成 3NF

`R(A, B, C)`，FD：`A→B`、`B→C`。拆成 3NF 正确的是（ ）。

A. `(A,B)` + `(A,C)`
B. `(A,B)` + `(B,C)`
C. 不拆
D. `(A)` + `(B,C)`

<details><summary>👉 点开对照答案与解析</summary>

**B。** `A→B→C` 是传递依赖，要**把链剪断**：中间属性 B 留在原表，被它决定的 C 跟 B 单独成表 → `(A,B)` + `(B,C)`。A 用"起点+终点"会丢 `B→C`。

</details>
