## 题 3

在 MySQL 中，`LEFT JOIN` 和 `RIGHT JOIN` 的结果一定不同。

<details><summary>👉 答案与解析</summary>

**错。** 如果两张表**每一行都有匹配**，左连接和右连接的结果可以完全相同（D6 你库里实测过，都是 5 行）。

</details>

## 题 4

函数依赖 `X → Y` 中，X 称为决定因素。

<details><summary>👉 答案与解析</summary>

**对。** X 决定 Y，所以 X 是**决定因素**（决定属性），Y 是被决定属性。

</details>

## 题 5

在 SQL 中，`WHERE` 子句可以引用 `SELECT` 中定义的列别名。

<details><summary>👉 答案与解析</summary>

**错。** 执行顺序是 WHERE 在 SELECT **之前**，所以 WHERE 看不到 SELECT 里起的别名。`ORDER BY` 才能用别名。

</details>

## 题 6

事务一旦 `COMMIT`，就不能再用 `ROLLBACK` 撤销。

<details><summary>👉 答案与解析</summary>

**对。** COMMIT 后数据**持久化**（ACID 的 D），不可回滚。只能再写一条反向的 DML 改回来。

</details>

## 题 7

共享锁（S 锁）之间是兼容的。

<details><summary>👉 答案与解析</summary>

**对。** 只有"读 + 读"能共存（S-S 兼容）；只要有一个 X 锁就不兼容。

</details>

## 题 8

在 MapReduce 中，Shuffle 阶段负责把相同 key 的数据送到同一个 Reduce。

<details><summary>👉 答案与解析</summary>

**对。** 流程：Map → **Shuffle（按 key 排序分组）** → Reduce。

</details>

## 题 9

自然连接和等值连接的结果列数一定相同。

<details><summary>👉 答案与解析</summary>

**错。** 自然连接会**去掉重复的同名列**，所以列数比等值连接少（少被去掉的那几列）。

</details>

---

## 题 10

一个表只能有一个主键，但可以有多个候选键。

<details><summary>👉 答案与解析</summary>

**对。** 候选键是"有资格当主键的"；主键从里面**选一个**。所以主键 1 个、候选键可以多个。

</details>

## 题 41（10 分）ER 设计 + 转关系模式（快递物流）

**需求**：

- **快递员**：工号、姓名、电话
- **网点**：网点编号、网点名称
- **包裹**：运单号、重量
- 一个快递员可以负责多个网点；一个网点只能由一个快递员负责
- 一个网点可以收寄多个包裹；一个包裹只属于一个网点
- 一个快递员可以派送多个包裹；一个包裹可能由多个快递员经手派送；派送要记录**派送日期**

**要求**：
1. （4 分）指出三个联系各自的类型，并说明理由
2. （3 分）写出 ER 图三要素
3. （3 分）转成关系模式，标出主键和外键

<details><summary>👉 答案与解析</summary>

**1. 联系类型（4 分）**

- **负责**：快递员 1 — N 网点。一个快递员→多个网点；一个网点→一个快递员 → **1:N**
- **收寄**：网点 1 — N 包裹。一个网点→多个包裹；一个包裹→一个网点 → **1:N**
- **派送**：快递员 M — N 包裹。一个快递员→多个包裹；一个包裹→多个快递员 → **M:N**（属性：派送日期）

**2. ER 三要素（3 分）**

- 实体：快递员(<u>工号</u>, 姓名, 电话)、网点(<u>网点编号</u>, 网点名称)、包裹(<u>运单号</u>, 重量)
- 联系：负责（1:N）、收寄（1:N）、派送（M:N，属性：派送日期）

**3. 关系模式（3 分）**

```
快递员( 工号, 姓名, 电话 )
网点( 网点编号, 网点名称, 工号 )              ← 负责 1:N，1 端键放 N 端；外键：工号
包裹( 运单号, 重量, 网点编号 )                ← 收寄 1:N；外键：网点编号
派送( 工号, 运单号, 派送日期 )                ← 派送 M:N，单独建表
      主键 = (工号, 运单号)
      外键：工号 → 快递员；运单号 → 包裹
```

**评分要点**：两个 1:N 都不建表、键放 N 端（2 分）；M:N 单独建表、组合主键（1 分）。

</details>

## 题 42（10 分）SQL 综合（停车场）

**场景**：

- `车位(车位号, 区域, 类型)`
- `停车记录(记录号, 车位号, 车牌号, 入场时间, 出场时间)`

**数据**：

| 车位号 | 区域 | 类型 |
|---|---|---|
| A01 | A区 | 小型 |
| A02 | A区 | 小型 |
| B01 | B区 | 大型 |

| 记录号 | 车位号 | 车牌号 | 入场时间 | 出场时间 |
|---|---|---|---|---|
| 1 | A01 | 浙A12345 | 2026-10-21 08:00:00 | NULL |
| 2 | A02 | 浙B67890 | 2026-10-21 09:30:00 | 2026-10-21 11:00:00 |
| 3 | B01 | 浙C11111 | 2026-10-21 10:00:00 | NULL |

**要求**：
1. （4 分）建 `车位` 和 `停车记录` 两张表：
   - 车位：车位号主键，区域和类型非空
   - 停车记录：记录号自增主键；车位号**非空外键**；车牌号非空；入场时间非空；出场时间**可空**
2. （2 分）插入上面的数据
3. （4 分）查询：
   - A：**仍在停车**（出场时间为 NULL）的车牌号、车位号、入场时间，按入场时间升序
   - B：每个区域的**车位数**，按车位数降序

**预期输出 A**：
```
浙A12345 | A01 | 2026-10-21 08:00:00
浙C11111 | B01 | 2026-10-21 10:00:00
```

**预期输出 B**：
```
A区 | 2
B区 | 1
```

<details><summary>👉 答案与解析</summary>

**1. 建表（4 分）**

```sql
CREATE TABLE 车位 (
  车位号 CHAR(3) PRIMARY KEY,
  区域 CHAR(2) NOT NULL,
  类型 VARCHAR(10) NOT NULL
);

CREATE TABLE 停车记录 (
  记录号 INT PRIMARY KEY AUTO_INCREMENT,
  车位号 CHAR(3) NOT NULL,
  车牌号 CHAR(10) NOT NULL,
  入场时间 DATETIME NOT NULL,
  出场时间 DATETIME,
  FOREIGN KEY (车位号) REFERENCES 车位(车位号)
);
```

**2. 插入（2 分）**

```sql
INSERT INTO 车位 VALUES
('A01','A区','小型'),('A02','A区','小型'),('B01','B区','大型');

INSERT INTO 停车记录(车位号,车牌号,入场时间,出场时间) VALUES
('A01','浙A12345','2026-10-21 08:00:00',NULL),
('A02','浙B67890','2026-10-21 09:30:00','2026-10-21 11:00:00'),
('B01','浙C11111','2026-10-21 10:00:00',NULL);
```

**3. 查询（4 分）**

A：

```sql
SELECT 车牌号, 车位号, 入场时间
FROM 停车记录
WHERE 出场时间 IS NULL
ORDER BY 入场时间;
```

B：

```sql
SELECT 区域, COUNT(*) AS 车位数
FROM 车位
GROUP BY 区域
ORDER BY 车位数 DESC;
```

**评分要点**：A 用 `IS NULL`（不是 `= NULL`）；B 用 GROUP BY。日期时间用单引号。

</details>

## 题 43（10 分）存储过程 + 触发器（在线教育）

**场景**：

- `学员(学员号, 姓名, 报名数)`
- `报名(学员号, 课程号)`，主键 `(学员号, 课程号)`

**要求**：
1. （3 分）建 `学员` 和 `报名` 两张表（报名表的学员号为外键）
2. （2 分）插入学员 `('S01','小明',0)`、`('S02','小红',0)`
3. （3 分）创建存储过程 `p_报名数`：输入学员号（IN），输出该学员的报名课程数（OUT），并调用验证
4. （2 分）创建触发器 `trg_报名加一`：向报名表插入记录时，自动把对应学员的报名数 +1
5. 测试：插入 `('S01','C001')`、`('S01','C002')`、`('S02','C001')`，查 `学员` 表验证报名数（注意顺序：**先建触发器，再插报名**）

**预期**：S01 报名数 2、S02 报名数 1

<details><summary>👉 答案与解析</summary>

**1. 建表（3 分）**

```sql
CREATE TABLE 学员 (
  学员号 CHAR(3) PRIMARY KEY,
  姓名 VARCHAR(20) NOT NULL,
  报名数 INT DEFAULT 0
);

CREATE TABLE 报名 (
  学员号 CHAR(3),
  课程号 CHAR(4),
  PRIMARY KEY (学员号, 课程号),
  FOREIGN KEY (学员号) REFERENCES 学员(学员号)
);
```

**2. 插学员（2 分）**

```sql
INSERT INTO 学员 VALUES ('S01','小明',0),('S02','小红',0);
```

**3. 存储过程（3 分）**

```sql
CREATE PROCEDURE p_报名数(IN p_学员号 CHAR(3), OUT p_数 INT)
BEGIN
  SELECT COUNT(*) INTO p_数 FROM 报名 WHERE 学员号 = p_学员号;
END;

CALL p_报名数('S01', @数);
SELECT @数 AS 报名数;
```

**4. 触发器（2 分）**

```sql
CREATE TRIGGER trg_报名加一
AFTER INSERT ON 报名
FOR EACH ROW
BEGIN
  UPDATE 学员 SET 报名数 = 报名数 + 1
  WHERE 学员号 = NEW.学员号;
END;
```

**5. 测试**

```sql
INSERT INTO 报名 VALUES ('S01','C001'),('S01','C002'),('S02','C001');
SELECT * FROM 学员;
-- S01 小明 2 / S02 小红 1
```

⚠️ **顺序很重要**：触发器只对**创建之后**的插入生效。如果先插报名、后建触发器，那几条记录不会自动计数——这是常见坑，也是理解触发器"事件驱动"的好例子。

**清理**：

```sql
DROP TRIGGER IF EXISTS trg_报名加一;
DROP PROCEDURE IF EXISTS p_报名数;
DROP TABLE IF EXISTS 报名;
DROP TABLE IF EXISTS 学员;
```

</details>
