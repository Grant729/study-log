# 一、判断题（10 题 × 1 分 = 10 分）

## 题 1

视图可以更新，因此**任何**视图都可以执行 `UPDATE`。

<details><summary>👉 答案与解析</summary>

**错。** 只有**简单单表视图**可更新；含连接、聚合、`GROUP BY`、`DISTINCT` 的复杂视图**不可更新**。"任何"是陷阱词。

</details>

---

## 题 2

MySQL 中，加了 `UNIQUE` 约束的列**不允许**出现 `NULL`。

<details><summary>👉 答案与解析</summary>

**错。** MySQL 的 UNIQUE 只管"非 NULL 值不重复"，**允许多个 NULL**（NULL 彼此不算相等）。这是 MySQL 与部分数据库的差异，常考。

</details>

---

## 题 3

聚合函数遇到 `NULL` 会把它当作 `0` 参与计算。

<details><summary>👉 答案与解析</summary>

**错。** 聚合函数**忽略 NULL**：`AVG` 只对非 NULL 求平均，`COUNT(列)` 只数非 NULL。把 NULL 当 0 是常见错误。

</details>

---

## 题 4

在 `LEFT JOIN` 中，把右表的过滤条件写在 `ON` 后面和写在 `WHERE` 后面，结果**完全相同**。

<details><summary>👉 答案与解析</summary>

**错。** **经典陷阱**：
- 条件写在 `ON`：先连接（保留左表全部行），只影响"能不能匹配上"
- 条件写在 `WHERE`：连接后再过滤，**会把右表为 NULL 的行（即左表独有行）过滤掉**，退化成内连接语义

</details>

---

## 题 5

`DELETE FROM 表` 和 `DROP TABLE 表` 都会删除表结构。

<details><summary>👉 答案与解析</summary>

**错。** `DELETE` 只删**数据行**，表结构还在（空表）；`DROP TABLE` 才删整张表。

</details>

---

## 题 6

一个表只能有一个主键，但可以有多个候选键。

<details><summary>👉 答案与解析</summary>

**对。** 候选键 = 有资格当主键的（可多个）；主键 = 从里面选 **1 个**。

</details>

---

## 题 7

`COUNT(*)` 和 `COUNT(1)` 的结果相同。

<details><summary>👉 答案与解析</summary>

**对。** 两者都数**行数**（NULL 也算）。区别只在 `COUNT(列)`——它只数该列非 NULL 的值。

</details>

---

## 题 8

外键列的值可以为 `NULL`。

<details><summary>👉 答案与解析</summary>

**对。** 参照完整性允许外键为 NULL（表示"暂未关联"），除非你额外加了 `NOT NULL`。

</details>

---

## 题 9

一个关系模式如果满足 3NF，那么它一定满足 BCNF。

<details><summary>👉 答案与解析</summary>

**错。** 方向反了：**BCNF 比 3NF 严格**。满足 BCNF ⇒ 满足 3NF；反过来不成立。

</details>

---

## 题 10

自然连接要求两个表有同名列，并自动去掉结果中重复的同名列。

<details><summary>👉 答案与解析</summary>

**对。** 自然连接 = 用同名列做连接条件 + 删掉重复列。

</details>

## 题 11【NULL 陷阱】

查询`出场时间`为空的停车记录，正确写法是（ ）。

A. `WHERE 出场时间 = NULL`
B. `WHERE 出场时间 IS NULL`
C. `WHERE 出场时间 == NULL`
D. `WHERE 出场时间 NOT = NULL`

<details><summary>👉 答案与解析</summary>

**B（`IS NULL`）。** NULL 不能用 `=` 比较（`= NULL` 永远不成立），必须用 `IS NULL` / `IS NOT NULL`。

</details>

---

## 题 12【大数据 · 计算模式】

某支付平台要求对每笔交易**实时**风控，最适合的计算模式是（ ）。

A. 批处理　B. 流计算　C. 图计算　D. 查询分析计算

<details><summary>👉 答案与解析</summary>

**B（流计算）。** "实时 + 持续到达" → 流计算（Storm/Flink）。

</details>

## 题 13【LEFT JOIN 条件位置 · 陷阱】

`A LEFT JOIN B ON A.id=B.id AND B.状态='完成'` 与 `A LEFT JOIN B ON A.id=B.id WHERE B.状态='完成'` 相比（ ）。

A. 结果完全相同
B. 前者保留 A 的全部行，后者只保留有匹配的行
C. 后者保留 A 的全部行
D. 两者都报错

<details><summary>👉 答案与解析</summary>

**B。** 写在 `ON` 里：左表全保留；写在 `WHERE` 里：连接后再过滤，右表为 NULL 的行被刷掉，**退化为内连接**。这是最经典的 JOIN 陷阱。

</details>

---

## 题 14【COUNT 陷阱】

`A LEFT JOIN B` 后，用 `COUNT(*)` 统计"每个 A 对应的 B 数量"，对于**没有 B 的 A**，结果是（ ）。

A. 1　B. 0　C. NULL　D. 报错

<details><summary>👉 答案与解析</summary>

**A（1）。** LEFT JOIN 会给没匹配的 A 补一行（右边全 NULL），`COUNT(*)` 数**行**，所以是 1。要得到 0，必须用 **`COUNT(B.某列)`**（数非 NULL）。这是你错题本 #4。

</details>

---

## 题 15【LIMIT 偏移 · 陷阱】

`LIMIT 3, 2` 取到的是（ ）。

A. 前 3 行　B. 第 4、5 行　C. 第 3、4 行　D. 第 5、6 行

<details><summary>👉 答案与解析</summary>

**B（第 4、5 行）。** `LIMIT 偏移量, 行数`；偏移从 0 数，3 = 跳过前 3 行。

</details>

---

## 题 16【聚合位置 · 陷阱】

下列写法**正确**的是（ ）。

A. `SELECT 城市 FROM 订单 WHERE COUNT(*) > 3 GROUP BY 城市`
B. `SELECT 城市 FROM 订单 GROUP BY 城市 HAVING COUNT(*) > 3`
C. `SELECT 城市 FROM 订单 HAVING COUNT(*) > 3`
D. `SELECT 城市, COUNT(*) FROM 订单 WHERE COUNT(*) > 3`

<details><summary>👉 答案与解析</summary>

**B。** "筛组"必须用 HAVING，且 HAVING 在 GROUP BY 之后。A/D 在 WHERE 里写聚合函数会报 1111；C 缺 GROUP BY（且语义不对）。

</details>

A. `ORDER BY`　B. `WHERE`　C. 两者都能　D. 两者都不能

**B（WHERE）。** WHERE 在 SELECT 之前执行，看不到别名。

## 题 18【候选键 · 陷阱】

关系 `R(A, B, C)`，FD：`A→B`、`B→C`，候选键是（ ）。

## 题 41（10 分）综合设计（影视制作）

**需求描述**：

> 某影视制作公司需要管理演员、影片和制片公司。每位**演员**有演员号、姓名和国籍；每部**影片**有影片号、片名、上映年份和宣传语；每家**制片公司**有公司号、公司名和地址。一部影片只由一家制片公司出品，但一家制片公司可以出品多部影片。一位演员可以出演多部影片，一部影片也可以有多位演员出演；每次出演需要记录**角色名**。
>
> （公司市场部另外保存了一些行业调研报告，本系统暂不涉及。）

**要求**：

1. （4 分）从上述描述中找出**实体、属性、联系**，并指出各联系的类型及理由
2. （3 分）转换为关系模式，标出**主码和外码**
3. （3 分）写出创建"**出演**"表的 SQL（含复合主键和两个外键）

<details><summary>👉 答案与解析</summary>

**1. 实体、属性、联系（4 分）**

- 实体：
  - 演员(<u>演员号</u>, 姓名, 国籍)
  - 影片(<u>影片号</u>, 片名, 上映年份, 宣传语)
  - 制片公司(<u>公司号</u>, 公司名, 地址)
- 联系：
  - **出品**：影片 N — 1 制片公司（一部影片只由一家公司出品；一家公司可出品多部）
  - **出演**：演员 M — N 影片（一位演员出演多部；一部影片多位演员），属性：角色名
- ⚠️ "行业调研报告"是**干扰信息**，本系统不涉及，不应建模。

**2. 关系模式（3 分）**

```
制片公司( 公司号, 公司名, 地址 )
影片( 影片号, 片名, 上映年份, 宣传语, 公司号 )   ← 出品 1:N；外码：公司号
演员( 演员号, 姓名, 国籍 )
出演( 演员号, 影片号, 角色名 )                  ← 出演 M:N
      主码 = (演员号, 影片号)
      外码：演员号 → 演员；影片号 → 影片
```

**3. 建表 SQL（3 分）**

```sql
CREATE TABLE 出演 (
  演员号 CHAR(3) NOT NULL,
  影片号 CHAR(4) NOT NULL,
  角色名 VARCHAR(30),
  PRIMARY KEY (演员号, 影片号),
  FOREIGN KEY (演员号) REFERENCES 演员(演员号),
  FOREIGN KEY (影片号) REFERENCES 影片(影片号)
);
```

**评分要点**：复合主键（1 分）、两个外键（1 分）、`NOT NULL`/类型（1 分）。

</details>

| S01 | P01 | 2 | 2026-10-24 |
| S01 | P03 | 10 | 2026-10-24 |
| S02 | P04 | 1 | 2026-10-24 |

**要求**：
1. （3 分）建 `商品`、`销售明细` 两张表（商品号主键；销售明细复合主键 + 商品号外键）
2. （2 分）插入上面的数据
3. （2 分）查询 A：每个商品的**销售额**（单价 × 数量求和），按销售额降序
4. （3 分）查询 B：**库存为 0 或未知（NULL）**的商品号、商品名、库存

**预期输出 A**：
```
洗衣液 | 79.80
纸巾   | 50.00
洗发水 | 45.00
```

**预期输出 B**：
```
P02 | 牙膏 | NULL
P03 | 纸巾 | 0
```

<details><summary>👉 答案与解析</summary>

**1. 建表（3 分）**

```sql
CREATE TABLE 商品 (
  商品号 CHAR(3) PRIMARY KEY,
  商品名 VARCHAR(20) NOT NULL,
  单价 DECIMAL(6,2) NOT NULL,
  库存 INT          -- 允许 NULL
);

CREATE TABLE 销售明细 (
  销售单号 CHAR(4),
  商品号 CHAR(3),
  数量 INT NOT NULL,
  销售日期 DATE NOT NULL,
  PRIMARY KEY (销售单号, 商品号),
  FOREIGN KEY (商品号) REFERENCES 商品(商品号)
);
```

**2. 插入（2 分）**

```sql
INSERT INTO 商品 VALUES
('P01','洗衣液',39.90,50),('P02','牙膏',12.50,NULL),
('P03','纸巾',5.00,0),('P04','洗发水',45.00,20);

INSERT INTO 销售明细 VALUES
('S01','P01',2,'2026-10-24'),
('S01','P03',10,'2026-10-24'),
('S02','P04',1,'2026-10-24');
```

**3. 查询 A（2 分）**

```sql
SELECT 商品.商品名, SUM(商品.单价 * 销售明细.数量) AS 销售额
FROM 商品
INNER JOIN 销售明细 ON 商品.商品号 = 销售明细.商品号
GROUP BY 商品.商品号, 商品.商品名
ORDER BY 销售额 DESC;
```

**4. 查询 B（3 分）**

```sql
SELECT 商品号, 商品名, 库存
FROM 商品
WHERE 库存 IS NULL OR 库存 = 0;
```

**陷阱点**：不能写 `库存 = NULL`（永远不成立），必须 `IS NULL`。

## 题 43（10 分）存储过程 + 触发器（校园一卡通）

**场景**：

- `学生(学号, 姓名, 余额)`
- `消费记录(记录号, 学号, 金额, 消费时间)`，记录号自增主键

**要求**：
1. （3 分）建两张表
2. （2 分）插入：
   - 学生：`('2023001','张三',79.50)`、`('2023002','李四',30.00)`
   - **历史**消费记录：`('2023001',12.50,'2026-10-20 12:00:00')`、`('2023001',8.00,'2026-10-21 08:00:00')`、`('2023002',20.00,'2026-10-21 18:00:00')`
3. （3 分）创建触发器 `trg_消费扣款`：向消费记录插入新记录时，自动把对应学生的余额 **减去** `NEW.金额`
4. （2 分）创建存储过程 `p_消费总额`：输入学号（IN），输出该学生的消费总金额（OUT，用 `SUM`）
5. 测试：先建触发器，再插入一条 `('2023001', 10.00, '2026-10-25 09:00:00')`，查张三余额（应从 79.50 变成 69.50）；调用存储过程算张三消费总额（应为 30.50）

**预期**：张三余额 69.50；消费总额 30.50

<details><summary>👉 答案与解析</summary>

**1. 建表（3 分）**

```sql
CREATE TABLE 学生 (
  学号 CHAR(7) PRIMARY KEY,
  姓名 VARCHAR(20) NOT NULL,
  余额 DECIMAL(8,2) NOT NULL DEFAULT 0
);

CREATE TABLE 消费记录 (
  记录号 INT PRIMARY KEY AUTO_INCREMENT,
  学号 CHAR(7) NOT NULL,
  金额 DECIMAL(8,2) NOT NULL,
  消费时间 DATETIME NOT NULL,
  FOREIGN KEY (学号) REFERENCES 学生(学号)
);
```

**2. 插入（2 分）**

```sql
INSERT INTO 学生 VALUES ('2023001','张三',79.50),('2023002','李四',30.00);

INSERT INTO 消费记录(学号,金额,消费时间) VALUES
('2023001',12.50,'2026-10-20 12:00:00'),
('2023001',8.00,'2026-10-21 08:00:00'),
('2023002',20.00,'2026-10-21 18:00:00');
```

**3. 触发器（3 分）**

```sql
CREATE TRIGGER trg_消费扣款
AFTER INSERT ON 消费记录
FOR EACH ROW
BEGIN
  UPDATE 学生 SET 余额 = 余额 - NEW.金额 WHERE 学号 = NEW.学号;
END;
```

**4. 存储过程（2 分）**

```sql
CREATE PROCEDURE p_消费总额(IN p_学号 CHAR(7), OUT p_总额 DECIMAL(8,2))
BEGIN
  SELECT IFNULL(SUM(金额),0) INTO p_总额
  FROM 消费记录 WHERE 学号 = p_学号;
END;

CALL p_消费总额('2023001', @总额);
SELECT @总额 AS 消费总额;
```

**5. 测试**

```sql
INSERT INTO 消费记录(学号,金额,消费时间) VALUES ('2023001',10.00,'2026-10-25 09:00:00');
SELECT * FROM 学生;
-- 张三 69.50 / 李四 30.00
```

**陷阱点**：
- 存储过程要 **SUM 消费明细**，不要读 `学生.余额`（那是余额，不是消费总额）
- 触发器用 **`NEW.金额`**，不是 OLD（INSERT 没有 OLD）
- `IFNULL(SUM(...),0)`：没有消费记录时 SUM 返回 NULL，用 IFNULL 兜底

**清理**：

```sql
DROP TRIGGER IF EXISTS trg_消费扣款;
DROP PROCEDURE IF EXISTS p_消费总额;
```

</details>
