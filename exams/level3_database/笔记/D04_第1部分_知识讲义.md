## 单元一：DDL 是什么 + 建库（先认识"管结构"的语言）

SQL 语句按"管什么"分两大类，先分清再往下学：

| 类别 | 全称 | 管什么 | 你已见过的语句 |
|---|---|---|---|
| **DDL** | Data Definition Language 数据定义语言 | 管**结构**：库、表、视图、索引的建/改/删 | CREATE TABLE（D3） |
| **DML** | Data Manipulation Language 数据操纵语言 | 管**数据**：行记录的增删改 | INSERT/UPDATE/DELETE（D3） |

比喻：DDL 是**盖房子、改户型**（墙、门、房间布局）；DML 是**往里搬家具、换家具**（具体的东西）。今天全讲 DDL。

### 建库语句逐词拆

```sql
CREATE DATABASE IF NOT EXISTS 考试练习库;   -- 建库
SHOW DATABASES LIKE '考试练习库';           -- 查库（验证建没建成）
DROP DATABASE 考试练习库;                   -- 删库
```

- **CREATE DATABASE 库名**：建一个数据库。库 = **文件柜**，表 = 文件柜里的抽屉。
- **IF NOT EXISTS**：保险丝——库已存在时**跳过而不是报错**。考试爱考"重复建库不报错靠什么"。
- **SHOW DATABASES LIKE '…'**：列出现有的库。LIKE 是模糊匹配（`'%练习%'` 表示名字里含"练习"的库）。
- **DROP DATABASE**：**连柜子带抽屉全部删除，无法撤销**——所以实操题最后一步才删。
- **USE 库名**：切换当前工作的库（我们的笔记本一直连在 `exam_practice`，不需要 USE，知道有这个语句就行）。

## 单元二：ALTER TABLE——给建好的表"改户型"（D3 伏笔兑现）

D3 的题 14 你已经用过 `ALTER TABLE` 的两个招式：`ADD COLUMN`（加列）和 `ADD CONSTRAINT`（加约束）。今天补齐剩下三招，凑成**装修五连**：

| 招式 | 语法 | 干什么 | 房子比喻 |
|---|---|---|---|
| 加列 | `ALTER TABLE 表 ADD COLUMN 列 类型 [约束];` | 加一列 | 加盖一个房间 |
| 改类型 | `ALTER TABLE 表 MODIFY 列 新类型;` | 只改列的**类型** | 把房间改大 |
| 改名+改类型 | `ALTER TABLE 表 CHANGE 旧列名 新列名 新类型;` | **改名**（类型必须照写） | 换门牌顺便改大 |
| 删列 | `ALTER TABLE 表 DROP COLUMN 列;` | 删一列 | 拆掉一个房间 |
| 加约束 | `ALTER TABLE 表 ADD CONSTRAINT 名 CHECK (条件);` | 补家规（D3 学过） | 补一条家规 |

⚠️ 两个考点：

1. **MODIFY 与 CHANGE 的区别**：MODIFY 只改类型、不能改名；CHANGE 能改名，但**类型必须原样重写**（哪怕不改类型也要写一遍）——这是选择题爱考的差异。
2. **改类型有风险**：改成更小的类型可能装不下旧数据（比如 `VARCHAR(30)` 改成 `CHAR(3)` 会报错或截断），MySQL 对放不下的会报错。

范例（今天实操题 12 的"原汤"版本）：

```sql
ALTER TABLE 课程 ADD COLUMN 授课教师 VARCHAR(20) DEFAULT '待定';  -- 加列，旧行自动填"待定"
ALTER TABLE 课程 MODIFY 学分 DECIMAL(3,1);                        -- 学分从 INT 改成 3 位小数、1 位小数的 DECIMAL
ALTER TABLE 课程 CHANGE 授课教师 教师姓名 VARCHAR(20);            -- 授课教师 改名成 教师姓名
ALTER TABLE 课程 DROP COLUMN 教师姓名;                            -- 收尾：删掉它
```

还有两个"整表级"的 DDL，顺手记：

- `RENAME TABLE 旧名 TO 新名;` —— 给表改名
- `DROP TABLE IF EXISTS 表名;` —— 删表（D1 起你每个实操都在用，IF EXISTS = 不存在就跳过不报错）

## 单元三：视图 VIEW——"预设菜单"

### 场景

借阅表只存编号（读者编号、图书编号），你每次想"看谁借了什么书"都要把三张表拼起来查一遍——这条查询又长又常用。**视图就是给这条查询起个名字**：查的时候直接查名字。

### 语法逐词拆

```sql
CREATE VIEW 到期提醒 AS
SELECT 借阅号, 读者编号, 图书编号, 应还日期
FROM 借阅
WHERE 应还日期 < '2026-11-01';    -- 只保留快到期/已到期的行

SELECT * FROM 到期提醒;            -- 以后查这个"名字"就行，当表用
DROP VIEW 到期提醒;                -- 删视图（表是 DROP TABLE，视图是 DROP VIEW）
```

- **CREATE VIEW 视图名 AS 查询**：给一段查询**起名、存起来**。
- **视图是虚拟表**：**不存数据，只存那句查询**。每次查视图，MySQL 现场执行背后的 SELECT——所以基表数据变了，视图结果自动跟着变（判断题考点）。
- 两个用途：**简化**（长查询一句话复用）+ **安全**（只暴露部分列，比如视图里不出现工资列）。
- **可更新吗？**：**简单的单表视图可以 UPDATE**，改动会**落到基表**（今天实操题 13 你亲眼见）；含**多表连接、聚合函数**（SUM/COUNT 那种，D5 学）的视图**不可更新**。
- 删视图用 `DROP VIEW`，不是 DROP TABLE。

### 一个直觉

视图 = 餐厅的**预设菜单**：菜单本身不是菜（不存数据），你点"套餐 A"，后厨每次现场做（执行查询）。改菜单就改的是"做菜步骤"，客人点单看到的就是新的。

## 单元四：索引 INDEX——书的"目录"

### 场景

读者表有 4 行时，查"张三"扫 4 行只要一瞬间。当读者表有 **1000 万行**，每次按姓名查人都要从头扫到尾——这就是没有索引的痛。

**索引 = 书的目录**：想找"第三章"不翻全书，查目录直接翻到那一页。数据库里给 `读者(读者姓名)` 建索引后，按姓名查人直接走"姓名目录"，快几个数量级。

### 语法逐词拆

```sql
CREATE INDEX idx_姓名 ON 读者(读者姓名);          -- 普通索引：允许重复值
CREATE UNIQUE INDEX uq_编号 ON 图书(图书编号);     -- 唯一索引：列内不许重复
SHOW INDEX FROM 图书;                             -- 查看这张表上有哪些索引
DROP INDEX idx_姓名 ON 读者;                      -- 删索引（注意要写 ON 表名）
```

- **UNIQUE 索引与 UNIQUE 约束同源**：D3 学的"列定义加 UNIQUE"，MySQL 内部就是自动建了个唯一索引——两者效果等价（理论题 10 考这个）。
- **主键自带索引**：D3 建表时讲过，主键会自动建索引。你 `SHOW INDEX FROM 图书` 会看到两个：主键自带的 PRIMARY + 你新建的。
- **代价**（判断题最爱考）：**索引不是越多越好**——① 建索引占磁盘空间；② 每次 INSERT/UPDATE/DELETE 都要**同步维护目录**，写变慢。所以只有**经常用来查的列**（WHERE 后面常出现的）才值得建索引。
- 唯一索引的"执法"：往唯一索引列插重复值 → 报 **1062**（和主键重复一个错误码，因为底层都是唯一性检查）。今天实操题 14 你亲手触发它。

### 三件东西的删除口诀

**删表 DROP TABLE、删视图 DROP VIEW、删索引 DROP INDEX 索引名 ON 表名**——三个 DROP 三种写法，别混。
