## 题 1【判断】三级模式

数据库系统采用三级模式结构：**外模式**（用户看到的局部视图）、**模式**（全体数据的逻辑结构，也叫逻辑模式）、**内模式**（数据在存储介质上的物理结构，也叫存储模式）。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。**
- 外模式 = 子模式 = 用户模式：每个用户/应用看到的局部数据视图，**可以有多个**
- 模式 = 逻辑模式：全体数据的逻辑结构和特征描述，**只有一个**
- 内模式 = 存储模式：数据实际怎么存（文件、索引方式），**只有一个**
- 记忆口诀：**外多个、内一个、中间模式独一个**。考试爱在"模式的个数"上出陷阱。

</details>

## 题 2【单选】逻辑独立性

当数据库的**逻辑结构**（模式）改变时，比如给表加一列，**应用程序不用改**，这靠的是什么？

A. 外模式/模式映像
B. 模式/内模式映像
C. DBMS 自动重写应用程序
D. 数据字典

<details><summary>👉 点开对照答案与解析</summary>

**A。**
两级映像对应两种独立性，**方向别记反**：
- **逻辑独立性**：模式变 → 外模式不变 → 应用不变。靠**外模式/模式映像**（"外模"对着"逻辑"）
- **物理独立性**：内模式（存储）变 → 模式不变。靠**模式/内模式映像**
- 口诀：**改逻辑靠外模，改存储靠内模**。这是每年必考概念。

</details>

## 题 3【单选】系统组成

以下哪个**不是**数据库系统的组成部分？

A. 数据库（DB）
B. 数据库管理系统（DBMS）
C. 数据库管理员（DBA）
D. 操作系统内核源代码

<details><summary>👉 点开对照答案与解析</summary>

**D。**
数据库系统 = DB（数据）+ DBMS（管理软件）+ 应用程序 + 数据库管理员 DBA + 用户。
DBA 的工作：设计、监控、维护、备份恢复——**DBA 是"人"这个角色**，题目常把它和软件混着考。
操作系统只是运行环境，不是 DB 系统的组成部分。

</details>

## 题 4【判断】关系模型的数据结构

关系模型用**二维表**表示实体及实体间的联系，一行叫**元组**（记录），一列叫**属性**（字段），列的取值范围叫**域**。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。**
关系模型的核心术语（必背）：
- 关系 = 二维表；元组 = 行；属性 = 列；域 = 属性的取值范围；候选码 = 能唯一标识一行的最小属性集；主键 = 选定的候选码
- 关系模型三要素：**数据结构（二维表）、数据操作（关系代数）、完整性约束（实体/参照/用户定义）**
- 对比记忆：层次模型的数据结构是**树**（代表：IMS），网状模型是**图**（代表：DBTG/IDMS）

</details>

## 题 5【单选】数据模型三要素

数据模型的三要素是？

A. 数据结构、数据操作、完整性约束
B. 实体、属性、联系
C. 外模式、模式、内模式
D. 数据库、DBMS、DBA

<details><summary>👉 点开对照答案与解析</summary>

**A。**
- B 是 ER 模型（概念模型）的三要素——别和"数据模型三要素"混，这是经典干扰项
- C 是三级模式结构；D 是系统组成
- 三要素中**数据结构是最核心**的，它决定了模型的类型（树→层次、图→网状、表→关系）

</details>

## 题 6【单选】数据模型类别

把「数据模型：典型产品」配对，**错误的是**：

A. 层次模型：IMS
B. 网状模型：DBTG 报告
C. 关系模型：Oracle
D. NoSQL：MySQL

<details><summary>👉 点开对照答案与解析</summary>

**D。** MySQL 是**关系型**数据库，不是 NoSQL。
常考配对（必背）：
- 层次模型 → **IMS**（IBM，最早的商用 DBMS）
- 网状模型 → **DBTG 报告 / IDMS**
- 关系模型 → Oracle、MySQL、SQL Server、DB2、PostgreSQL
- **NoSQL 四大类**（题 7 展开）：键值 Redis、文档 MongoDB、列族 HBase、图 Neo4j
- 面向对象数据库：ObjectStore、Versant 等（了解名字即可）

</details>

## 题 7【单选】NoSQL 分类

按「数据模型：代表产品」配对，**正确的是**：

A. 键值模型：MongoDB
B. 文档模型：Redis
C. 列族模型：HBase
D. 图模型：MySQL

<details><summary>👉 点开对照答案与解析</summary>

**C。**
NoSQL 四大类与代表产品（必背，客观题高频）：
| 类型 | 代表产品 | 特点 |
|---|---|---|
| 键值 | **Redis**、Memcached | 查询快，适合缓存 |
| 文档 | **MongoDB**、CouchDB | 存 JSON 式文档，结构灵活 |
| 列族 | **HBase**、Cassandra | 按列存储，适合海量稀疏数据 |
| 图 | **Neo4j**、JanusGraph | 存节点和边，适合关系网络（我们项目里知识图谱就用的这类） |
- 口诀：**键 Redis、文 Mongo、列 HBase、图 Neo**——A 和 B 就是最常见的互换陷阱。

</details>

## 题 8【判断】数据独立性的目的

数据独立性是指**应用程序与数据的存储结构和逻辑结构相互独立**，由 DBMS 的两级映像保证，目的是让"数据变了不用改程序、程序变了不用动数据"。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。**
一句话版本：**逻辑独立性 = 改逻辑结构不改应用；物理独立性 = 改存储结构不改逻辑结构**。
判断题的常见篡改点：把两级映像的对应关系写反（如"模式/内模式映像保证逻辑独立性"就是错的）。

</details>

## 题 9【实操 · MySQL】热身：建库建表插数据

**【目的】** 让手指记起 MySQL 环境——考试平台就是 MySQL，你本机已装好 8.0，从今天起所有实操都在本机 MySQL 上做。

**【要求】** 在 Navicat 的查询窗口（或 VS Code 的 `%%sql` 格）里依次执行：建 `exam_practice` 库 → 建 `读者` 表（含主键、NOT NULL、默认值）→ 插 4 行数据。跑完 `SHOW TABLES` 能看到表。

**【提示】** 步骤：`CREATE DATABASE` → `USE` → `CREATE TABLE`（注意主键 `PRIMARY KEY`、`NOT NULL`、`DEFAULT` 三个约束的写法）→ `INSERT`。中文表名列名直接用。

<details><summary>👉 点开对照答案与解析</summary>

```sql
DROP DATABASE IF EXISTS exam_practice;   -- 练习库可重建，这句防重复报错
CREATE DATABASE exam_practice;
USE exam_practice;

CREATE TABLE 读者(
  读者编号 CHAR(8) PRIMARY KEY,          -- 主键约束
  姓名 VARCHAR(20) NOT NULL,             -- 非空约束
  年级 VARCHAR(8),
  借阅量 INT DEFAULT 0                   -- 默认值约束
);

INSERT INTO 读者 VALUES
  ('R001','张三','大一',12),
  ('R002','李四','大二',5),
  ('R003','王五','大一',0),
  ('R004','赵六','大三',30);
```
（这段代码已在本机 MySQL 8.0.23 实测通过。MySQL 的 `VALUES` 可以一行插多条。）

</details>

## 题 10【实操 · MySQL】条件查询 + 排序

**【目的】** 大纲 SQL 查询的起手式：`WHERE` 筛选 + `ORDER BY` 排序。

**【要求】** 接着题 9，查出**借阅量 ≥ 5** 的读者，按借阅量**从高到低**排。

**【提示】** 条件用 `WHERE 借阅量 >= 5`；降序用 `ORDER BY ... DESC`（升序是 ASC，默认）。

<details><summary>👉 点开对照答案与解析</summary>

```sql
SELECT * FROM 读者 WHERE 借阅量 >= 5 ORDER BY 借阅量 DESC;
```

真实输出（本机实测）：

```
R004  赵六  大三  30
R001  张三  大一  12
R002  李四  大二  5
```

解析：`WHERE` 在取行时过滤（借阅量 0 的王五被挡掉），`ORDER BY` 在最后排序——**执行顺序是 FROM → WHERE → SELECT → ORDER BY**，这个顺序是后面写复杂查询的骨架。`DESC` = descend（降），`ASC` = ascend（升）。

</details>
