## 单元一：数据库的三条家规——三类完整性

### 先讲个事故（为什么需要"家规"）

想象你是图书馆管理员，管两本名册：

- 《读者名册》——每个办证读者一行：读者编号、姓名、借阅次数
- 《借阅记录册》——每次借书一行：谁借了哪本书、什么时候还

如果名册随便乱填，会发生三场灾难：

1. **同一个读者证号登记了两次**（张三办了两张 001 号证）→ 问"001 是谁"永远说不清 → 数据**重复**
2. **借阅记录里出现了没办过证的编号 999** → 书借给了不存在的人 → 数据**悬空**
3. **馆藏量写成 -3、借阅日期空着** → 负数藏书、没日期的借书记录 → 数据**荒谬**

数据库要能自己拦住这些垃圾数据，靠的就是**完整性约束（Integrity Constraints）**——简称"家规"。考试大纲把家规分三类：

| 家规 | 关键字 | 管什么 | 图书馆类比 |
|---|---|---|---|
| **实体完整性** | PRIMARY KEY 主键 | 每行必须有唯一"身份证号"：**不空 + 不重** | 每个读者证号唯一、人人有证 |
| **参照完整性** | FOREIGN KEY 外键 | 引用的数据**必须真有其人** | 借阅记录里的读者编号，必须能在读者名册里查到 |
| **用户定义完整性** | NOT NULL / UNIQUE / CHECK / DEFAULT | 馆里**自己定的规矩** | 馆藏量不许为负、出版社没填用默认值 |

记忆钩子：**"实体"认人（主键）、"参照"认亲（外键）、"用户定义"认规矩（自己定）**。

### 三条家规的精确版表述（判断题爱考原文）

- **实体完整性**：主属性（组成主键的属性）取值**非空且唯一**。
- **参照完整性**：外键的取值**要么为空（NULL），要么等于被参照表中某个主键值**——不存在"中间状态"。
- **用户定义完整性**：除了上面两条，业务自己提出的约束，比如 `馆藏量 >= 0`、`性别 IN ('男','女')`。

## 单元二：六大约束逐个拆——今天的主角

下面两条建表语句是今天所有练习的地基，**每一行都有讲究**。先完整看一遍，再逐词拆。

```sql
CREATE TABLE 图书 (
  图书编号 CHAR(4) PRIMARY KEY,              -- 实体完整性：主键
  书名     VARCHAR(50) NOT NULL,             -- 用户定义：不许空
  出版社   VARCHAR(30) DEFAULT '未知出版社',  -- 用户定义：有默认值
  馆藏量   INT DEFAULT 1 CHECK (馆藏量 >= 0)  -- 用户定义：CHECK 规矩
);

CREATE TABLE 借阅 (
  借阅号   INT PRIMARY KEY AUTO_INCREMENT,   -- 主键 + 自动编号
  读者编号 CHAR(3) NOT NULL,                 -- 外键：必须真有其人
  图书编号 CHAR(4) NOT NULL,                 -- 外键：必须真有其书
  借阅日期 DATE DEFAULT (CURDATE()),         -- 默认值可以是个函数
  应还日期 DATE NOT NULL,
  FOREIGN KEY (读者编号) REFERENCES 读者(读者编号) ON DELETE CASCADE,
  FOREIGN KEY (图书编号) REFERENCES 图书(图书编号)
);
```

### 逐词拆解

**① PRIMARY KEY（主键）** —— `图书编号 CHAR(4) PRIMARY KEY`

- 作用：给每行发唯一身份证。**= NOT NULL + UNIQUE 的合体**（理论题 9 会考），还会自动建索引加速查找。
- 违反时报错 **1062**（Duplicate entry：重复）——今天题 12 你会亲眼见到。

**② NOT NULL（不许空）** —— `书名 VARCHAR(50) NOT NULL`

- 作用：这一列**必须填**。借阅记录里"不知道哪天还"是不允许的。
- 违反时报错 **1048**（Column cannot be null）。
- 对比：没写 NOT NULL 的列默认允许 NULL。**NULL 不是 0、不是空字符串，是"未知"**——借阅次数 NULL 表示"不知道"，和 0 次是两回事。

**③ UNIQUE（不许重）** —— 今天建表没用到，但考试必考

- 作用：列内取值不重复（如邮箱、身份证号）。
- ⚠️ **MySQL 的陷阱：UNIQUE 列允许出现多个 NULL**（NULL 彼此不算"相等"，所以不算重复）——判断题爱考。SQL Server 只许一个 NULL，MySQL 不管。**本机已实测：同一 UNIQUE 列插两个 NULL 不报错。**
- 与 PRIMARY KEY 的区别：主键 = 唯一 + 非空；UNIQUE 只管"唯一"，不管"空"。

**④ CHECK（自定规矩）** —— `CHECK (馆藏量 >= 0)`

- 作用：每行必须满足括号里的条件。
- ⚠️ **历史考点**：MySQL 直到 **8.0.16** 才开始强制执行 CHECK——**8.0.16 以前的版本"写了也白写"**（能建表但不管事）。你的 8.0.23 会真管，今天题 12 你会亲眼见到它报 **3819**（Check constraint is violated）。
- 例：`CHECK (性别 IN ('男','女'))`、`CHECK (应还日期 >= 借阅日期)`。

**⑤ DEFAULT（默认值）** —— `出版社 VARCHAR(30) DEFAULT '未知出版社'`

- 作用：插入时**没写这一列**，就自动填默认值。
- 两种写法：
  - 固定值：`DEFAULT '未知出版社'`
  - 函数：`DEFAULT (CURDATE())`——注意 MySQL 8.0.13+ 函数默认值**要加括号**。CURDATE() 返回今天日期（本机已实测：插入后借阅日期自动填 `2026-10-08`）。
- 本机还实测了：只给 `图书编号、书名` 插一行，出版社自动变 `未知出版社`、馆藏量自动变 `1`。

**⑥ AUTO_INCREMENT（自动编号）** —— `借阅号 INT PRIMARY KEY AUTO_INCREMENT`

- 作用：插入时不用管这一列，自动从 1 开始 +1 编号。借阅号这种"流水号"最合适。
- ⚠️ **跳号现象**：失败的插入**也可能吃掉一个号码**（InnoDB 的脾气）——所以借阅号偶尔会 1、2、3、7、8 地跳。今天题 13 你会亲眼见到：恢复数据后赵六的两条借阅号不是 4、5，而是接着往后排。**跳号不是错，是正常现象。**

**⑦ FOREIGN KEY ... REFERENCES（外键）** —— `FOREIGN KEY (读者编号) REFERENCES 读者(读者编号)`

- 读法："借阅表.读者编号 这列，参照 读者表.读者编号"。
- 作用：插入/修改时 MySQL 自动去"亲戚家"核对——**借阅表里出现的读者编号，必须已经存在于读者表**。这就是参照完整性。
- 违反时报错 **1452**（Cannot add or update a child row: a foreign key constraint fails）——今天题 12 的第一条就是它。
- 两个技术细节：
  1. **被参照的列必须有索引**（主键自带索引，所以外键几乎总是参照别人主键）；
  2. **删表顺序**：先删子表（借阅）再删父表（图书）——先删父表会被外键拦住。今天题 11 的开头两句 `DROP` 就是这个顺序，别搞反。

## 单元三：违约了怎么办——外键的四种"应急方案"

借阅表的外键是"读者编号必须真有其人"。那如果有人要**删掉读者表里的赵六**，赵六的借阅记录怎么办？MySQL 提供四种方案，考试爱考前三种：

| 方案 | 写在建表时 | 删赵六后的借阅记录 |
|---|---|---|
| ① **拒绝**（默认，RESTRICT/NO ACTION） | 什么都不写 | 拒绝删除赵六，报错 1452——"他有借阅记录，不许删" |
| ② **级联 CASCADE** | `ON DELETE CASCADE` | 赵六删了，他的借阅记录**跟着一起消失** |
| ③ **置空 SET NULL** | `ON DELETE SET NULL` | 赵六删了，借阅记录的读者编号变 NULL（需要这列允许 NULL） |
| ④ 置默认值 | `ON DELETE SET DEFAULT` | 很少考，知道有这东西就行 |

今天题 13 就是方案②的实测：借阅表建的时候写了 `ON DELETE CASCADE`，所以删赵六后，他两条借阅记录自动蒸发——**不是魔法，是建表时那句 ON DELETE CASCADE 在替你执法**。

（顺带一提：`ON UPDATE CASCADE` 同理——父表主键改了，子表外键跟着改。考试有可能会提。）

## 单元四：函数依赖入门（为 D9 范式埋个伏笔）

先回忆初中数学：`y = f(x)` 的意思是——**给定 x，y 就被唯一确定了**。x=3，y 就只有一个值。

数据库里也有"函数"：**X → Y（读作"X 决定 Y"）**，意思是**知道 X 的值，就能唯一确定 Y 的值**。

- `读者编号 → 读者姓名`：知道读者编号 001，姓名只能是"张三"——成立 ✅
- `图书编号 → 书名`：知道 B001，书名只能是《数据库系统概论》——成立 ✅
- `姓名 → 读者编号`：知道"张三"，读者编号却不一定唯一（可能两个张三）——**不成立** ❌

术语速记：

- X → Y 里的 **X 叫"决定因素"**
- 箭头**永远从"唯一的东西"指向"被唯一确定的东西"**：编号 → 姓名 ✅，姓名 → 编号 ❌

今天你只要会两件事：**①判断一个"X→Y"成不成立；②能说出谁决定谁**。更深的（完全依赖、部分依赖、传递依赖）D9 再讲——那三个概念是判断第几范式的钥匙，今天先把"决定"这个词说顺。
