# ② 理论题检测（模块 8 · 函数依赖）

## 题 1【判断】函数依赖的含义

`X → Y` 表示"知道 X 的值，就能唯一确定 Y 的值"。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 函数依赖 = 由 X 唯一推出 Y（讲义单元一）。如 `读者编号 → 读者姓名`：知道编号，就知道是谁。

</details>

---

## 题 2【单选】完全函数依赖

`X → Y` 是**完全**函数依赖，指的是（ ）。

A. X 里任何真子集都能决定 Y
B. X 里任何真子集都不能决定 Y
C. Y 也能决定 X
D. X 和 Y 相等

<details><summary>👉 点开对照答案与解析</summary>

**B。** 完全依赖 = X 缺一不可（讲义单元二）。真子集都不能决定 Y，才说明 X 里的每个属性都必要。A 是部分依赖的特征。

</details>

---

## 题 3【单选】部分函数依赖

`X → Y` 是**部分**函数依赖，指的是（ ）。

A. X 里存在某个真子集也能决定 Y
B. X 里任何真子集都不能决定 Y
C. Y 只有一个属性
D. X 只有一个属性

<details><summary>👉 点开对照答案与解析</summary>

**A。** 部分依赖 = X 里有多余属性：某个真子集就能决定 Y（讲义单元二）。如 `(学号,课程号) → 姓名` 是部分依赖，因为学号（真子集）就能定姓名。

</details>

---

## 题 4【判断】成绩的依赖类型

选课表 SC(学号, 课程号, 成绩) 中，`(学号, 课程号) → 成绩` 是**完全**函数依赖。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 单独学号定不了成绩（一人多门课）、单独课程号也定不了（一门课多人选），两个缺一不可 → 完全依赖。

</details>

---

## 题 5【判断】姓名的依赖类型

选课表 SC(学号, 课程号, 成绩, 姓名) 中，已知 `学号 → 姓名`，则 `(学号, 课程号) → 姓名` 是**部分**函数依赖。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** `(学号,课程号)` 的真子集 `学号` 就能决定姓名，课程号是多余的 → 部分依赖（讲义单元二）。

</details>

---

## 题 6【单选】传递函数依赖的三要素

X → Z 是**传递**函数依赖，需要满足（ ）。

A. X → Y、Y → Z、Y → X
B. X → Y、Y → Z、Y ↛ X
C. X → Z、Z → X
D. X → Y、X → Z

<details><summary>👉 点开对照答案与解析</summary>

**B。** 传递依赖三要素：X → Y、Y → Z、且 **Y ↛ X**（Y 不能反过来决定 X，否则 X 和 Y 等价，不算传递）。A 的"Y → X"正好把传递依赖破坏了。

</details>

---

## 题 7【判断】系主任的依赖类型

已知 `学号 → 系号`、`系号 → 系主任`，则 `学号 → 系主任` 是传递函数依赖。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 学号借道系号决定系主任：学号 → 系号 → 系主任，且系号 ↛ 学号（一个系多个学生）→ 传递依赖（讲义单元三）。

</details>

---

## 题 8【单选】候选键

候选键（码）是指（ ）。

A. 表里的第一个属性
B. 能唯一确定一行、且任何真子集都不能唯一确定一行的属性组
C. 主键之外的所有属性
D. 任意一组属性

<details><summary>👉 点开对照答案与解析</summary>

**B。** 候选键 = "能唯一确定全表 + 最精简"（讲义单元四）。选课表的候选键是 `(学号,课程号)`。

</details>

---

## 题 9【判断】主属性

主属性是指出现在候选键里的属性。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 主属性 = 候选键里的属性；非主属性 = 不在任何候选键里的属性（讲义单元四）。选课表里学号、课程号是主属性，成绩、姓名是非主属性。

</details>

---

## 题 10【单选】部分依赖由谁消除

**部分**函数依赖，是在规范化到哪个范式时要消除的？

A. 1NF　B. 2NF　C. 3NF　D. BCNF

<details><summary>👉 点开对照答案与解析</summary>

**B。** 2NF 消除非主属性对候选键的**部分**依赖；3NF 消除**传递**依赖（讲义单元五，D11 详学）。口诀：**2 除部分、3 除传递**。

</details>

# ③ 纸面应用题（不用写 SQL，判断 + 一句话理由）

## 应用 1：判断"成绩"的依赖类型

选课表 SC(学号, 课程号, 成绩)。已知 `(学号, 课程号) → 成绩`。

**问**：这是完全依赖还是部分依赖？为什么？

<details><summary>👉 点开对照答案</summary>

**完全依赖。** 单独"学号"定不了成绩（一个学生选多门课，学号相同但成绩多行）；单独"课程号"也定不了（一门课多人选）。两个属性**缺一不可**，所以是完全依赖。

</details>

---

## 应用 2：判断"姓名"的依赖类型

选课表 SC(学号, 课程号, 成绩, 姓名)。已知 `(学号, 课程号) → 姓名`，且 `学号 → 姓名`。

**问**：`(学号, 课程号) → 姓名` 是完全还是部分依赖？为什么？

<details><summary>👉 点开对照答案</summary>

**部分依赖。** 因为 `(学号,课程号)` 的真子集 `学号` 单独就能决定姓名（学号 → 姓名），"课程号"这个属性是**多余**的。判据：X 的真子集能决定 Y → 部分依赖。

</details>

---

## 应用 3：判断传递依赖

借阅表(借阅号, 读者编号, 读者姓名)。已知 `借阅号 → 读者编号`、`读者编号 → 读者姓名`。

**问**：`借阅号 → 读者姓名` 是什么依赖？请按三要素验证。

<details><summary>👉 点开对照答案</summary>

**传递依赖。** 三要素逐条验证：
1. `借阅号 → 读者编号` ✅（知道借阅号，知道谁借的）
2. `读者编号 → 读者姓名` ✅（知道编号，知道是谁）
3. `读者编号 ↛ 借阅号` ✅（一个读者能借很多次，编号不能唯一确定借阅号）

三要素齐全 → 借阅号**借道**读者编号间接决定读者姓名，是传递依赖。

</details>

---

## 应用 4：找候选键

选课表 SC(学号, 课程号, 成绩)。

**问**：这张表的候选键是什么？为什么是它、而不是学号或课程号单独当键？

<details><summary>👉 点开对照答案</summary>

**候选键是 `(学号, 课程号)`。**

两步验证：
1. **能唯一确定**：学号 + 课程号一起，能锁定唯一一行（也就能定成绩）。
2. **最精简**：去掉学号只剩课程号 → 一门课多人选，定不了；去掉课程号只剩学号 → 一人多门课，也定不了。

所以单独学号、单独课程号都当不了键，必须两个绑一起 → 候选键 `(学号,课程号)`。

</details>

---

## 应用 5：综合判断

关系 R(学号, 课程号, 成绩, 姓名, 系名, 系主任)。

函数依赖：`学号 → 姓名`、`学号 → 系名`、`系名 → 系主任`、`(学号,课程号) → 成绩`。

**问**：
① 候选键是什么？
② 系主任传递依赖于谁？
③ 姓名相对于候选键 `(学号,课程号)` 是什么依赖？

<details><summary>👉 点开对照答案</summary>

**① 候选键 = `(学号, 课程号)`**。它能定全表：学号定姓名、系名，系名再定系主任，学号+课程号定成绩；且最精简（理由同应用 4）。

**② 系主任传递依赖于学号**。链条：`学号 → 系名 → 系主任`，且系名 ↛ 学号（一个系多个学生）。所以系主任也传递依赖于候选键。

**③ 姓名是部分依赖**。因为 `(学号,课程号)` 的真子集 `学号` 单独就能定姓名（学号 → 姓名）。

（这道题把三种依赖 + 候选键全串起来了，是今天最像"真题"的一道。）

</details>

# ④ 回炉题（D6 第2轮：连接 + D9 第1轮：DML）

> D6 第二轮聚焦连接查询；D9 昨天刚学，今天第一次回炉 DML。

## 回 1【判断】内连接的结果

内连接（INNER JOIN）的结果集是两个表的交集。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 内连接只保留两边都有匹配的行。口诀：**内连接 = 找交集**。

</details>

---

## 回 2【判断】左连接一定大于内连接

左连接（LEFT JOIN）的结果集一定比内连接大。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**错。** 左连接是"**不小于**"内连接，不是"一定大于"——左表每行都有匹配时两者相等。这是你 D6 亲手抓出的坑：**看到"一定"先找反例**。

</details>

---

## 回 3【判断】自连接要不要别名

自连接（同一张表连自己）必须给表起别名。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 同一张表出现两次，不起别名 MySQL 分不清，报 `Not unique table/alias`。判据：连接条件里"本表普通列 = 本表主键"。

</details>

---

## 回 4【判断】UPDATE 漏 WHERE

`UPDATE 读者 SET 借阅次数 = 0;` 会把读者表每一行的借阅次数都改成 0。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 没有 WHERE = 改全表。DML 的灵魂在 WHERE——漏写全表遭殃。这条别真跑。

</details>

---

## 回 5【判断】DELETE 与 DROP

`DELETE FROM 表` 删数据行（表结构保留），`DROP TABLE 表` 删整张表（连结构）。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 口诀：**DELETE 清空抽屉里的东西，DROP 把抽屉整个砸了**。前者 DML、后者 DDL。

</details>

---

## 回 6【单选】DML 三兄弟

下列全部属于 DML（数据操纵语言）的是（ ）。

A. `SELECT / INSERT / UPDATE`
B. `INSERT / UPDATE / DELETE`
C. `CREATE / ALTER / DROP`
D. `INSERT / DROP / SELECT`

<details><summary>👉 点开对照答案与解析</summary>

**B。** DML 三兄弟 = INSERT（放）、UPDATE（改）、DELETE（删）。A 的 SELECT 是 DQL（查询）、C 是 DDL、D 的 DROP 是 DDL。口诀：**DDL 装修房子、DML 搬家具**。

</details>
