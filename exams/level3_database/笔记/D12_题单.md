# ② 理论题检测（模块 8 · 模式分解）

## 题 1【判断】无损连接的含义

一个分解是"无损连接"的，指的是把分解后的关系**自然连接**回去，能够得到与原关系**完全相同**的结果。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 无损 = 接回去能**原样还原**（不多不少）。多了行叫"有损"（多出虚假数据），少了行也是错（讲义单元二、三）。

</details>

---

## 题 2【单选】合格分解的两个条件

一个关系模式的分解，合格的验收标准是（ ）。

A. 只要无损连接就行
B. 只要保持函数依赖就行
C. **无损连接**和**保持函数依赖**都要满足
D. 表越多越好

<details><summary>👉 点开对照答案与解析</summary>

**C。** 两个条件都要（讲义单元二）。其中"无损连接"是底线——宁可不保持依赖，也绝不能接不回去。D 错：拆太碎反而更慢更难维护。

</details>

---

## 题 3【判断】两表分解的无损判据

R 分解成 R1、R2 时，若 `R1 ∩ R2 → R1 − R2` 或 `R1 ∩ R2 → R2 − R1` 成立，则该分解是无损的。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 这就是两表分解的无损判据（讲义单元三）。白话：**公共属性必须能决定其中一张表的"独有部分"**，也就是公共属性得是**其中一张表的键**。

</details>

---

## 题 4【单选】判断这个分解是否无损

`R(学号, 系名, 系主任)`，FD：`学号→系名`、`系名→系主任`。分解为 `R1(学号, 系名)` + `R2(学号, 系主任)`。该分解（ ）。

A. 有损　B. 无损　C. 不确定　D. 违反 1NF

<details><summary>👉 点开对照答案与解析</summary>

**B（无损）。** 公共属性 `R1∩R2 = {学号}`，R1 独有部分 `R1−R2 = {系名}`，检查 `学号 → 系名` ✓ 成立 → 无损（讲义单元三"分解 B"）。

⚠️ 注意：**无损 ≠ 合格**！这个分解虽然无损，但**丢了 `系名→系主任`**（见题 5）。

</details>

---

## 题 5【判断】判断这个分解是否保持依赖

承题 4，分解 `R1(学号, 系名)` + `R2(学号, 系主任)` **保持函数依赖**。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**错。** `系名 → 系主任` **丢了**——R1 里没有"系主任"列、R2 里没有"系名"列，这条规则凑不到任何一张表里（讲义单元四）。

**后果**：以后改"某系的系主任"，得按学生一个一个改，冗余回来了。正确拆法是把 `(系名, 系主任)` 放一张表——**搬"中间属性+它决定的东西"**。

</details>

---

## 题 6【单选】有损分解的表现

一个有损的分解，把子表自然连接回去会（ ）。

A. 行数变少　B. 行数变多，出现原表中不存在的虚假行　C. 行数不变但列变少　D. 报语法错误

<details><summary>👉 点开对照答案与解析</summary>

**B。** 有损的典型症状是**多出行**（讲义单元三的"两个张三"例子：2 行变 4 行）。因为公共属性不是键，连接时"一对多"乱配。

</details>

---

## 题 7【单选】2NF 拆表搬哪一对

把 `SC(学号, 课程号, 成绩, 姓名)`（已知 `学号→姓名`）拆到 2NF，应该搬出哪两个属性组成新表（ ）。

A. `(学号, 课程号)`　B. `(学号, 姓名)`　C. `(姓名, 成绩)`　D. `(课程号, 姓名)`

<details><summary>👉 点开对照答案与解析</summary>

**B。** 2NF 搬的是"**半个键**（学号）+ **它决定的属性**（姓名）"（讲义单元五）。搬完：`学生(学号,姓名)` + `选课(学号,课程号,成绩)`。

</details>

---

## 题 8【单选】3NF 拆表搬哪一对

把 `R(学号, 系名, 系主任)`（已知 `学号→系名→系主任`）拆到 3NF，应该搬出哪两个属性组成新表（ ）。

A. `(学号, 系名)`　B. `(学号, 系主任)`　C. `(系名, 系主任)`　D. `(系主任)` 单独

<details><summary>👉 点开对照答案与解析</summary>

**C。** 3NF 搬的是"**中间属性**（系名）+ **它直接决定的属性**（系主任）"。B 是最常见的错答（用"起点+终点"，会丢依赖）——正是你 **D11 错题 #6** 踩过的坑。

</details>

---

## 题 9【判断】规范化后表会变多

规范化的过程通常会把一张表拆成多张表，表的数量变多。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 用"拆"换"健康"——表变多、查询时要多连接，但消除了冗余和更新异常。这是规范化的**代价与收益**（用多一点连接，换数据一致性）。

</details>

---

## 题 10【判断】无损连接与保持依赖的关系

一个分解可能**无损连接**但**不保持函数依赖**。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 这两个条件**互相独立**——题 4/5 的分解就是活例子：无损 ✅ 但不保持依赖 ❌。所以判断时必须**分开判两次**，不能判了一个就下结论。

</details>

# ③ 纸面应用题（写出判断 + 理由）

## 应用 1：判断一个分解是否无损

`R(学号, 姓名, 班级)`，FD：`学号→姓名`、`学号→班级`。分解为 `R1(学号, 姓名)` + `R2(姓名, 班级)`。

**问**：这个分解是无损还是有损？请用定理判断，并说明会造成什么后果。

<details><summary>👉 点开对照答案</summary>

**有损。**

- 公共属性 `R1∩R2 = {姓名}`
- 检查 `姓名 → 学号`？✗（会重名）；`姓名 → 班级`？✗（不成立）
- 两条无损判据都不满足 → **有损**

**后果**：连接回去时，两个同名的学生会被**交叉配对**——假设 S01、S02 都叫"张三"，连接后会变成 4 行（S01×一班、S01×二班、S02×一班、S02×二班），**多出 2 行假数据**。

**为什么**：公共属性"姓名"**不是任何一张表的键**，所以它对不上号。

</details>

---

## 应用 2：判断一个分解是否"合格"（两个条件都判）

`R(学号, 系名, 系主任)`，FD：`学号→系名`、`系名→系主任`。分解为 `R1(学号, 系名)` + `R2(学号, 系主任)`。

**问**：分别判断①是否无损连接 ②是否保持函数依赖，并给出结论。

<details><summary>👉 点开对照答案</summary>

**① 无损 ✅**
- 公共属性 `{学号}`，`R1−R2 = {系名}`，检查 `学号 → 系名` ✓ 成立 → 无损

**② 不保持函数依赖 ❌**
- `学号 → 系名`：在 R1 里 ✅
- `系名 → 系主任`：**丢了** ❌（R1 无"系主任"列、R2 无"系名"列，凑不到一张表）

**结论**：**无损但不合格**（缺了依赖保持）——这是个"半合格"分解。

</details>

---

## 应用 3：拆一个合格的 3NF

承应用 2 的 `R(学号, 系名, 系主任)`，FD：`学号→系名`、`系名→系主任`。

**要求**：把它拆成**既无损连接、又保持函数依赖**的 3NF 分解，并**逐条验证**这两个条件。

<details><summary>👉 点开对照答案</summary>

**正确的分解**：

```
学生( 学号, 系名 )
系( 系名, 系主任 )
```

**搬的是"中间属性（系名）+ 它直接决定的属性（系主任）"**——不是 `(学号, 系主任)`。

**验证①无损连接**：
- 公共属性 `{系名}`，`R2−R1 = {系主任}`，检查 `系名 → 系主任` ✓ 成立 → **无损** ✅

**验证②保持函数依赖**：
- `学号 → 系名`：在学生表里 ✅
- `系名 → 系主任`：在系表里 ✅
- 原 FD 全都还在 → **保持依赖** ✅

**结论**：两个条件都满足 → **合格分解**。

</details>

## 应用 4：拆 2NF 并验证

`R(学号, 课程号, 成绩, 姓名)`，FD：`(学号,课程号)→成绩`、`学号→姓名`。

**要求**：拆成 2NF，并验证无损连接 + 保持函数依赖。

<details><summary>👉 点开对照答案</summary>

**候选键** = `(学号, 课程号)`；非主属性 = 成绩、姓名。其中 `学号 → 姓名` 是**部分依赖** → 不是 2NF。

**拆法**（搬"半个键 + 它决定的属性"）：

```
学生( 学号, 姓名 )
选课( 学号, 课程号, 成绩 )
```

**验证①无损**：公共属性 `{学号}`，`学生−选课 = {姓名}`，检查 `学号 → 姓名` ✓ → **无损** ✅

**验证②保持依赖**：
- `(学号,课程号) → 成绩`：在选课表里 ✅
- `学号 → 姓名`：在学生表里 ✅
- → **保持依赖** ✅

**结论**：合格分解。

</details>

## 应用 5：综合——判范式 + 拆到 3NF（借阅场景）

借阅场景的宽表：`R(借阅号, 读者编号, 读者姓名, 图书编号, 图书名)`

FD：`借阅号→读者编号`、`读者编号→读者姓名`、`借阅号→图书编号`、`图书编号→图书名`

**问**：
① 候选键是什么？非主属性有哪些？
② 这张表最高满足第几范式？说明理由。
③ 把它拆成 3NF（要求无损 + 保持依赖）。

<details><summary>👉 点开对照答案</summary>

**① 候选键 = `借阅号`**（单属性，能定全表）；**非主属性 = 读者编号、读者姓名、图书编号、图书名**（4 个）。

**② 最高 2NF**：
- 1NF ✅（都原子）
- 2NF ✅——候选键是**单属性**，天然没有部分依赖（想违反都违反不了）
- **3NF ❌**——存在传递依赖，而且有**两条**：
  - `借阅号 → 读者编号 → 读者姓名`
  - `借阅号 → 图书编号 → 图书名`

**③ 拆到 3NF**（搬走"中间属性 + 它决定的东西"，共两条链 → 拆两张）：

```
借阅( 借阅号, 读者编号, 图书编号 )   ← 留在原地（只保留直接依赖）
读者( 读者编号, 读者姓名 )          ← 搬走"读者编号 + 读者姓名"
图书( 图书编号, 图书名 )            ← 搬走"图书编号 + 图书名"
```

**验证无损**：
- 借阅 ∩ 读者 = `{读者编号}`，`读者编号 → 读者姓名` ✓ → 无损
- 借阅 ∩ 图书 = `{图书编号}`，`图书编号 → 图书名` ✓ → 无损

**验证保持依赖**：四条原 FD 分别在 `借阅`（两条）、`读者`（一条）、`图书`（一条）里 ✅

**结论**：合格分解，三张表都是 3NF。

</details>

## 回 1【单选】2NF 消除什么

第二范式（2NF）要消除的是（ ）。

A. 属性非原子
B. 非主属性对候选键的**部分**函数依赖
C. 非主属性对候选键的**传递**函数依赖
D. 主属性对候选键的部分依赖

<details><summary>👉 点开对照答案与解析</summary>

**B。** 口诀 **2 除部分、3 除传递**，BCNF 才管主属性。

</details>

## 回 2【判断】没有非主属性的表

如果一张表**没有非主属性**（所有属性都是主属性），它一定满足 3NF。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 3NF 管的是"**非主属性**的部分/传递依赖"——没有非主属性就无从违反。但它**不一定**满足 BCNF（还得看"决定因素是不是键"）。

</details>

## 回 3【单选】拆表搬哪一对 ⭐错点回炉

要把 `R(学号, 系名, 系主任)`（FD：`学号→系名`、`系名→系主任`）拆到 3NF，新表应该是（ ）。

A. `系(学号, 系主任)`　B. `系(系名, 系主任)`　C. `学生(学号, 系主任)`　D. `系(学号, 系名)`

<details><summary>👉 点开对照答案与解析</summary>

**B。** 拆表搬的是"**中间属性（系名）+ 它直接决定的属性（系主任）**"。A/C 用的是"起点+终点"（学号+系主任）——**无损但不保持依赖**，`系名→系主任` 会丢。

这是你 **D11 错题 #6**（当时写成 `(学号, 系主任)`），今天再练一遍。记法：**拆表用"直接依赖"那一对。**

</details>

## 回 4【单选】`> ALL` 的含义

`馆藏量 > ALL (3, 4)` 等价于（ ）。

A. 馆藏量 > 3　B. 馆藏量 > 4　C. 馆藏量 > 3 且 > 4（即 > 4）　D. 馆藏量 ≥ 3

<details><summary>👉 点开对照答案与解析</summary>

**B（也是 C，B 更简洁）。** `> ALL` = 比名单里**全部**都大 = 大于**最大值** = `> 4`。门槛高。对照 `> ANY` = 大于最小值（门槛低）。

</details>

## 回 5【判断】IN 的含义

`读者编号 IN ('001','002','003')` 等价于 `读者编号='001' OR 读者编号='002' OR 读者编号='003'`。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** IN = 一串 OR 的缩写，本质是"在不在名单里"。`NOT IN` 则是取反。

</details>

## 回 6【判断】EXISTS 判断什么

`EXISTS (子查询)` 判断的是"子查询**有没有返回行**"，不关心返回的具体值。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** EXISTS 只看"有没有行"，所以子查询里写 `SELECT 1` 或 `SELECT *` 都行。典型用法是**相关子查询**（内层引用外层表）。

</details>
