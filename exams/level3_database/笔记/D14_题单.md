## 题 1【单选】设计流程的顺序

数据库设计的正确顺序是（ ）。

A. 建表 → ER 图 → 需求分析
B. 需求分析 → 概念设计(ER) → 逻辑设计(关系模式) → 物理设计(建表)
C. ER 图 → 需求分析 → 建表
D. 建表 → 关系模式 → 需求分析

<details><summary>👉 点开对照答案与解析</summary>

**B。** 五步：需求分析 → 概念设计(ER) → 逻辑设计(关系模式) → 规范化检查 → 物理设计(建表)。先想清楚"要什么"，再设计，最后才落地（讲义单元一）。

</details>

做需求分析时，主要从需求文字里抓取（ ）。

A. 只抓实体
B. 实体、属性、联系
C. 只抓表名

## 题 3【单选】建表顺序

建下面四张表，正确的顺序是（ ）。

科室(父) → 医生(引用科室) → 病人(父) → 诊治(引用医生和病人)

A. 科室 → 医生 → 病人 → 诊治
B. 科室 → 病人 → 医生 → 诊治
C. 诊治 → 医生 → 病人 → 科室
D. 随便什么顺序都行

<details><summary>👉 点开对照答案与解析</summary>

**B。** **父表先建、子表后建**：科室、病人都没有外键，先建；医生引用科室、诊治引用医生和病人，后建。A 的错误是**医生比它的父表科室晚建没问题，但医生比诊治早建也没问题**——关键是诊治必须最后；A 其实也能建成功。但标准答法按依赖层次排：**科室、病人 → 医生 → 诊治**。

⚠️ 严格说 A 在本例也能执行成功（医生只依赖科室，而科室已建）。**判题看的是"父表必须在子表之前"**，B 是教科书标准写法。

</details>

## 题 4【单选】复合主键的写法

M:N 联系转出来的 `诊治` 表，主键是 `(医生编号, 病历号)`，正确的建表写法是（ ）。

A. `PRIMARY KEY (医生编号)` 和 `PRIMARY KEY (病历号)` 各写一行
B. `PRIMARY KEY (医生编号, 病历号)` 写在一行
C. `PRIMARY KEY 医生编号, 病历号`
D. 不写主键

<details><summary>👉 点开对照答案与解析</summary>

**B。** 一个表只能有**一个**主键，复合主键写在**同一行括号里**（讲义单元六）。A 写两个主键会报错。

</details>

## 题 5【单选】外键的写法

`医生` 表的 `科室编号` 引用 `科室` 表的主键，正确写法是（ ）。

A. `FOREIGN KEY (科室编号) REFERENCES 科室(科室编号)`
B. `FOREIGN KEY (科室编号) REFERENCES 医生(科室编号)`
C. `REFERENCES 科室(科室编号)` 单独一行
D. `FOREIGN KEY 科室编号`

<details><summary>👉 点开对照答案与解析</summary>

**A。** 固定句式：`FOREIGN KEY (本表列) REFERENCES 父表(父表主键)`。B 引用错表；C 缺 `FOREIGN KEY` 关键字和本表列；D 不完整。

</details>

删这四张表（科室/医生/病人/诊治），正确顺序是（ ）。

A. 科室 → 医生 → 病人 → 诊治
B. 诊治 → 医生 → 病人 → 科室
C. 随便什么顺序

**B。** 和建表**反过来**：**先删子表，再删父表**。先删父表会被外键拦住（讲义单元六）。

## 题 10【单选】候选键（再练一次）

关系 `R(学号, 课程号, 成绩)`，FD：`(学号, 课程号) → 成绩`。候选键是（ ）。

A. 学号　B. 课程号　C. `(学号, 课程号)`　D. `(学号, 课程号, 成绩)`

<details><summary>👉 点开对照答案与解析</summary>

**C。** 候选键 = **能确定全表 + 最精简**。
- 学号、课程号单独都定不了成绩 ❌
- `(学号, 课程号)` 能定成绩 ✅，且去掉任何一个都不行（最精简）✅ → **候选键**
- D 的 `(学号,课程号,成绩)` 虽然能定全表，但**包含冗余属性**（成绩自己不用参与决定）→ 只是**超键**，不是候选键

这是你 **错题 #7** 的第三次练习。识别技巧：**"键 + 多一个属性"的选项，就是拿超键冒充候选键**。

</details>

# ③ 设计 + SQL 实操（酒店场景）

## 题 1【设计】把酒店 ER 转成关系模式

**场景**：

- **实体**：
  - 门店(<u>门店编号</u>, 门店名)
  - 客房(<u>房间号</u>, 类型, 价格)
  - 客人(<u>身份证号</u>, 姓名, 电话)
- **联系**：
  - **所属**：客房 N — 1 门店
  - **预订**：客人 M — N 客房，联系属性：预订日期

**要求**：写出转换后的 **4 个关系模式**（每张表的列 + 主键），并说明每个联系用了哪条规则。

<details><summary>👉 点开折叠答案</summary>

```
门店( 门店编号, 门店名 )
客房( 房间号, 类型, 价格, 门店编号 )      ← 所属是 1:N，把"1"端（门店）的键放进"N"端
客人( 身份证号, 姓名, 电话 )
预订( 身份证号, 房间号, 预订日期 )        ← 预订是 M:N，单独建表
      主键 = (身份证号, 房间号)
```

**一共 4 张表**：3 个实体各一张（3 张），2 个联系里 1:N 不建表、M:N 建 1 张 → 共 4 张。

</details>

## 题 2【SQL】建门店表 + 客房表

**要求**：新建代码格，先 `DROP TABLE IF EXISTS` 清理同名旧表（注意顺序：子表在前），然后建 `门店` 和 `客房` 两张表，`客房.门店编号` 外键引用 `门店`。

**提示**：父表先建、子表后建。

**验收**：`SHOW TABLES` 能看到这两张表。

<details><summary>👉 点开折叠答案</summary>

```sql
DROP TABLE IF EXISTS 预订;
DROP TABLE IF EXISTS 客房;
DROP TABLE IF EXISTS 客人;
DROP TABLE IF EXISTS 门店;

CREATE TABLE 门店 (
  门店编号 CHAR(3) PRIMARY KEY,
  门店名 VARCHAR(20) NOT NULL
);

CREATE TABLE 客房 (
  房间号 CHAR(3) PRIMARY KEY,
  类型 VARCHAR(10) NOT NULL,
  价格 DECIMAL(6,2) NOT NULL,
  门店编号 CHAR(3),
  FOREIGN KEY (门店编号) REFERENCES 门店(门店编号)
);
```

**要点**：DROP 顺序是**子表先**（预订 → 客房 → 客人 → 门店）；建表顺序是**父表先**（门店 → 客房）。

</details>

## 题 3【SQL】建客人表 + 预订表

**要求**：建 `客人` 表；再建 `预订` 表，主键 = `(身份证号, 房间号)`，两个外键分别引用 `客人` 和 `客房`。

**验收**：`DESCRIBE 预订` 能看到复合主键（Key 列两行都是 PRI）。

<details><summary>👉 点开折叠答案</summary>

```sql
CREATE TABLE 客人 (
  身份证号 CHAR(18) PRIMARY KEY,
  姓名 VARCHAR(20) NOT NULL,
  电话 VARCHAR(20)
);

CREATE TABLE 预订 (
  身份证号 CHAR(18),
  房间号 CHAR(3),
  预订日期 DATE NOT NULL,
  PRIMARY KEY (身份证号, 房间号),
  FOREIGN KEY (身份证号) REFERENCES 客人(身份证号),
  FOREIGN KEY (房间号) REFERENCES 客房(房间号)
);
```

**要点**：复合主键 `PRIMARY KEY (身份证号, 房间号)` 写在一行；两个外键分别写两行。

</details>

## 题 4【SQL】插数据 + 两个查询

**要求**：
① 按下面数据插入四张表：
- 门店：`('M01','市中心店')`、`('M02','机场店')`
- 客房：`('101','单人间',200,'M01')`、`('102','双人间',300,'M01')`、`('201','单人间',180,'M02')`
- 客人：`('C001','张三','13800001111')`、`('C002','李四','13800002222')`
- 预订：`('C001','101','2026-11-01')`、`('C001','102','2026-11-05')`、`('C002','201','2026-11-02')`

② 查询 A：每个客人订了几间房（姓名、预订数，按预订数降序）
③ 查询 B：每个门店有几间客房（门店名、客房数）

**预期输出 B**：

```
门店名   | 客房数
--------|------
市中心店 | 2
机场店   | 1
```

<details><summary>👉 点开折叠答案</summary>

```sql
INSERT INTO 门店 VALUES ('M01','市中心店'),('M02','机场店');
INSERT INTO 客房 VALUES ('101','单人间',200,'M01'),
                        ('102','双人间',300,'M01'),
                        ('201','单人间',180,'M02');
INSERT INTO 客人 VALUES ('C001','张三','13800001111'),
                        ('C002','李四','13800002222');
INSERT INTO 预订 VALUES ('C001','101','2026-11-01'),
                        ('C001','102','2026-11-05'),
                        ('C002','201','2026-11-02');

-- 查询 A：每个客人订了几间
SELECT 客人.姓名, COUNT(*) AS 预订数
FROM 客人
INNER JOIN 预订 ON 客人.身份证号 = 预订.身份证号
GROUP BY 客人.身份证号, 客人.姓名
ORDER BY 预订数 DESC;

-- 查询 B：每个门店几间客房
SELECT 门店.门店名, COUNT(客房.房间号) AS 客房数
FROM 门店
LEFT JOIN 客房 ON 门店.门店编号 = 客房.门店编号
GROUP BY 门店.门店编号, 门店.门店名;
```

**查询 A 真实输出**：张三 2、李四 1。
**查询 B 真实输出**：市中心店 2、机场店 1。

**要点**：查询 B 用 `LEFT JOIN`，才能保住"一间客房都没有的门店"（本题恰好都有，但写法要养成习惯）；`COUNT(客房.房间号)` 而不是 `COUNT(*)`（你的老错点 #4）。

</details>

## 题 5【SQL】验证约束 + 收尾

**要求**：
① 故意插一条**复合主键重复**的预订（`('C001','101','2026-11-09')`），记录错误码；
② 故意插一条**外键不存在**的预订（`('C999','101','2026-11-09')`），记录错误码；
③ 按正确顺序把四张练习表删干净。

**验收**：① 报 **1062**；② 报 **1452**；③ `SHOW TABLES` 里只剩 借阅/图书/读者/读者_大一/读者_大二/课程。

<details><summary>👉 点开折叠答案</summary>

```sql
-- ① 复合主键重复
INSERT INTO 预订 VALUES ('C001','101','2026-11-09');
-- → (1062, "Duplicate entry 'C001-101' for key '预订.PRIMARY'")

-- ② 外键不存在
INSERT INTO 预订 VALUES ('C999','101','2026-11-09');
-- → (1452, "Cannot add or update a child row: a foreign key constraint fails ...")

-- ③ 收尾：先子后父
DROP TABLE IF EXISTS 预订;
DROP TABLE IF EXISTS 客房;
DROP TABLE IF EXISTS 客人;
DROP TABLE IF EXISTS 门店;
```

**要点**：1062 说明**复合主键在执法**（同一客人不能重复订同一房间）；1452 说明**外键在执法**（不能引用不存在的客人）。删表顺序和建表**反过来**。

</details>

## 回 5【单选】传递依赖的三要素

`X → Z` 是传递函数依赖，需要满足（ ）。

A. `X→Y`、`Y→Z`、`Y→X`
B. `X→Y`、`Y→Z`、`Y ↛ X`

D. `X→Y`、`X→Z`

## 回 6【判断】部分依赖的判据

`X → Y` 是部分函数依赖，当且仅当 X 的某个真子集也能决定 Y。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 部分依赖 = X 里有多余属性（某个真子集就能决定 Y）。完全依赖则相反：任何真子集都不能决定 Y。

</details>
