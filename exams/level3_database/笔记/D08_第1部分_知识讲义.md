## 单元一：为什么要子查询——一个查询答不了的问题

### 先看一个问题卡在哪

馆长问：**"借阅次数最多的读者叫什么？"**

用你 D5~D7 学过的招，得走两步：

1. 先算最大值：`SELECT MAX(借阅次数) FROM 读者;` → 得到 **8**
2. 再查谁等于 8：`SELECT 读者姓名 FROM 读者 WHERE 借阅次数 = 8;` → 李四

**问题**：第 2 步里的 `8` 是"算出来的中间结果"，不是我们能提前知道的数。两步之间，你手动把 8 抄进第 2 步——**又慢又容易错**（万一数据变了，8 就过时了）。

### 子查询 = 把第 1 步直接嵌进第 2 步

```sql
SELECT 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 = (SELECT MAX(借阅次数) FROM 读者);
```

真实输出：

```
读者姓名 | 借阅次数
--------|----------
李四    | 8
```

**读法**：MySQL 先执行括号里的 `(SELECT MAX(借阅次数) FROM 读者)` 算出 8，再用这个 8 去跑外层。**括号里的就是"子查询"**（也叫内层查询），包着它的是**外层查询**。

**一句话**：**子查询 = 查询里再套一个查询，内层的先算，结果交给外层用。**

## 单元二：标量子查询——返回"一个值"

**标量 = 单个值**。子查询返回**一行一列**（就是一个数）时，配比较运算符 `= > < >= <= <>` 用。

### 例 1：借阅次数最多的读者

```sql
SELECT 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 = (SELECT MAX(借阅次数) FROM 读者);
```

→ 李四 8

### 例 2：借阅次数高于平均的读者

```sql
SELECT 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 > (SELECT AVG(借阅次数) FROM 读者);
```

真实输出（平均 = (5+8+3+2)/4 = 4.5）：

```
读者姓名 | 借阅次数
--------|----------
张三    | 5
李四    | 8
```

**读法**：内层 `AVG(借阅次数)` 算出一个数 4.5，外层 `> 4.5` 筛出张三、李四。

⚠️ **标量子查询的坑**：它必须**只返回一个值**。如果子查询返回多行（比如误写成返回一列），MySQL 报 `1242: Subquery returns more than 1 row`。所以配 `=` 的子查询，内层一定得是 `MAX` / `AVG` / `COUNT` 这类"压成一个数"的。

## 单元三：IN / NOT IN——判断"在不在名单里"

标量子查询只返回一个值；但更多时候子查询返回的是**一列多个值**（一个"名单"）。这时用 `IN`。

### 例：借过书的读者

```sql
SELECT 读者姓名
FROM 读者
WHERE 读者编号 IN (SELECT 读者编号 FROM 借阅);
```

真实输出（4 人——他们都借过书）：

```
张三  李四  王五  赵六
```

**读法**：
1. 内层 `SELECT 读者编号 FROM 借阅` 先跑，得到名单 `001, 002, 003, 004`
2. 外层 `读者编号 IN (名单)` = "读者编号**在这个名单里**吗？"在就留下。

**`IN` 就是"一串 OR"的缩写**：`读者编号 IN ('001','002','003','004')` 等价于 `读者编号='001' OR 读者编号='002' OR 读者编号='003' OR 读者编号='004'`。

### NOT IN = 不在名单里

```sql
SELECT 读者姓名 FROM 读者 WHERE 读者编号 NOT IN (SELECT 读者编号 FROM 借阅);
```

真实输出：**空表**（4 个读者都借过书，没人"不在名单里"）。

> 空结果**是正确答案**——它验证了你的查询逻辑没错，只是数据恰好没满足。想看到"真能筛出人"，临时 `INSERT INTO 读者 VALUES ('005','钱七',0);` 再跑，应出"钱七"，看完 `DELETE`。

## 单元四：ANY / ALL——一列值配比较运算符（高频考点）

`IN` 只能判断"**等于名单里的某个**"。想判断"**比名单里的都大/比任意一个大**"，用 `ANY` / `ALL`，它们必须**跟比较运算符**（`> < >= <= = <>`）连用。

### 场景：查出"借阅次数比王五和赵六都高的人"

王五 3 次、赵六 2 次，子查询返回名单 `(3, 2)`。

**用 ALL（全部满足）——门槛高**：

```sql
SELECT 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 > ALL (SELECT 借阅次数 FROM 读者 WHERE 读者编号 IN ('003','004'));
```

真实输出：

```
张三 5
李四 8
```

**读法**：`> ALL (3,2)` = "要比 3 和 2 **都**大" → 即 >3 → 张三 5、李四 8 通过；王五 3 不大于 3，出局。

**用 ANY（任意一个满足）——门槛低**：

```sql
SELECT 读者姓名, 借阅次数
FROM 读者
WHERE 借阅次数 > ANY (SELECT 借阅次数 FROM 读者 WHERE 读者编号 IN ('003','004'));
```

真实输出：

```
张三 5
李四 8
王五 3
```

**读法**：`> ANY (3,2)` = "只要比其中**任意一个**大就行" → 比 2 大就通过 → 王五 3 > 2 也通过了。

### 一张表记死 ANY vs ALL

| 写法 | 等价于 | 门槛 | 口诀 |
|---|---|---|---|
| `> ANY (名单)` | **大于名单里的最小值** | 低 | 过任意一个就行 |
| `> ALL (名单)` | **大于名单里的最大值** | 高 | 过全部才行 |

> 注意只对 `>` 成立时是这个"最小值/最大值"说法；换 `<` 就反过来（`< ANY` = 小于最大值，`< ALL` = 小于最小值）。**最稳的办法别背公式，直接翻译**：`> ANY` = 存在一个名单值比我小；`> ALL` = 名单值全都比我小。

## 单元五：EXISTS / NOT EXISTS——判断"有没有行"（相关子查询）

前三种（标量、IN、ANY/ALL）的子查询都能**独立跑**（内层不依赖外层）。EXISTS 则是**相关子查询**：**内层引用外层表**，MySQL 每拿到外层一行，就用这行去跑一遍内层。

### 例：借过书的读者（EXISTS 写法）

```sql
SELECT 读者姓名
FROM 读者
WHERE EXISTS (SELECT 1 FROM 借阅 WHERE 借阅.读者编号 = 读者.读者编号);
```

真实输出：张三、李四、王五、赵六（和 IN 版结果一样）。

**逐词读**：

- `EXISTS (子查询)` = "子查询**有没有返回行**？有 → 这行留下，没有 → 丢掉"。注意它不关心返回**什么**，只关心**有没有**（所以子查询里写 `SELECT 1` 或 `SELECT *` 都行，反正值不用）。
- **关键在 `借阅.读者编号 = 读者.读者编号`**：内层引用外层表 `读者`。MySQL 拿外层"张三"这行（读者编号 001），就跑内层"借阅表里有没有 读者编号=001 的行？"——有，所以张三留下。拿外层每行都这么问一遍。

### NOT EXISTS = 一条都没有

```sql
SELECT 读者姓名 FROM 读者 WHERE NOT EXISTS (SELECT 1 FROM 借阅 WHERE 借阅.读者编号 = 读者.读者编号);
```

→ 空表（都借过书）。

### IN vs EXISTS——什么时候都能用吗？

**本例里两者结果一样，但用法有差别**：

- `IN` 适合：**外层判断"某个值在不在名单里"**，且名单可以独立列出来。
- `EXISTS` 适合：**判断"有没有满足条件的行"**，尤其条件牵扯到内层表的多列时更自然。

考试里"下面哪个能查出借过书的读者"这种题，`IN` 和 `EXISTS` 往往都是对的——**都能选**，别看到 EXISTS 就慌。

## 单元六：四种子查询对比总表

| 子查询 | 返回什么 | 配什么用 | 一句话 |
|---|---|---|---|
| **标量** | 一个值 | `= > < >= <=` | 内层压成一个数 |
| **IN / NOT IN** | 一列值 | `IN (子查询)` | 在不在名单里 |
| **ANY / ALL** | 一列值 | 比较符 + `ANY/ALL` | 比任意一个大 / 比全部都大 |
| **EXISTS / NOT EXISTS** | 有/没有行 | `WHERE EXISTS (子查询)` | 有没有满足条件的行 |

**判断顺序**：先看内层返回"一个值"还是"一列值"还是"要关联外层"——
- 一个值 → 标量 + 比较符
- 一列值、问"在不在" → IN
- 一列值、问"比大小" → ANY / ALL
- 问"有没有"、且要关联外层 → EXISTS
