"读者"是实体，"姓名"是属性。对还是错？

## 题 3【单选】联系类型的判断

一个班级有多名学生，一名学生只属于一个班级。班级与学生的联系类型是（ ）。

A. 1:1　B. 1:N　C. M:N　D. 无法判断

<details><summary>👉 点开对照答案与解析</summary>

**B（班级 1 : N 学生）。** 拿"一个班级"去数 → 多个学生；拿"一名学生"去数 → 只属于一个班级。只有一边能对多个 → 1:N（讲义单元三）。

</details>

## 题 4【单选】M:N 的转换

M:N 联系转换成关系模式时，应该（ ）。

A. 不单独建表，把一端的键放进另一端
B. **单独建一张表**，主键 = 两端实体键的组合
C. 直接删掉这个联系
D. 只把联系的属性建一张表

<details><summary>👉 点开对照答案与解析</summary>

**B。** M:N 必须单独建表，键 = **两端实体键的组合**（讲义单元五规则 3）。A 是 1:N 的做法；D 错——没有两端实体的键，就没法表达"谁和谁"的配对。

</details>

## 题 5【单选】1:N 的转换

1:N 联系转换成关系模式时，通常（ ）。

A. 单独建一张表
B. 把"1"端的键放进"N"端作为外键
C. 把"N"端的键放进"1"端
D. 必须拆成两张表

<details><summary>👉 点开对照答案与解析</summary>

**B。** 1:N 不单独建表，把"1"端的键放进"N"端（讲义单元五规则 2）。C 不行——"1"端一行对应多个"N"端值，放不进去。

</details>

## 题 6【判断】1:1 的转换

1:1 联系既可以合并到某一端的表里，也可以单独建表。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 1:1 两种做法都可以（讲义单元五规则 4）：合并 = 把一端的键放进另一端；单独 = 建一张只有两个键的表。

</details>

## 题 7【判断】M:N 联系表的键

选课联系（学生 M : N 课程）转换成的表，主键应该是 `(学号, 课程号)`。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** M:N 单独建表，主键 = **两端实体键的组合** = `(学号, 课程号)`。成绩等联系属性作为普通列。

</details>

## 题 8【单选】参与度 (min, max)

`读者 —(0, N)— 借阅 —(0, N)— 图书` 中，`min = 0` 表示（ ）。

A. 读者必须至少借 0 次（废话）
B. 一个读者**可以不参与**借阅（一本都不借也能存在）
C. 读者最多借 0 本
D. 图书不能被借

<details><summary>👉 点开对照答案与解析</summary>

**B。** `min = 0` = **可选参与**（可以不参与）；`min ≥ 1` = **强制参与**（必须参与）。讲义单元四。

</details>

## 题 9【判断】弱实体

弱实体没有自己独立的主键，必须依赖强实体才能存在。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 弱实体用双矩形表示，键 = "**强实体的键 + 自己的部分键**"（讲义单元四）。经典例子：职工—家属。

</details>

## 题 10【单选】转换后的表数

有 3 个实体、2 个联系（一个 1:N、一个 M:N），转换后通常有几张表（ ）。

A. 3 张　B. 4 张　C. 5 张　D. 6 张

<details><summary>👉 点开对照答案与解析</summary>

**B（4 张）。** 3 个实体各一张 = 3 张；1:N **不建表**（键放 N 端）；M:N **建一张** → 共 **4 张**（讲义单元五）。这是综合应用题最常见的计数陷阱。

</details>

# ③ 纸面应用题（不用写 SQL，写 ER 要素 + 关系模式）

## 应用 1：判断联系类型

判断下列三组场景各是什么联系类型（1:1 / 1:N / M:N），并说明理由：

- a. **班级 — 学生**：一个班级有多名学生，一名学生只属于一个班级
- b. **医生 — 病人（诊治）**：一名医生可以诊治多名病人，一名病人可以被多名医生诊治
- c. **科室 — 主任**：一个科室只有一名主任，一名主任只负责一个科室

<details><summary>👉 点开对照答案</summary>

- **a. 1:N（班级 1 : N 学生）**。一个班级 → 多个学生；一名学生 → 只属一个班级。只有一边"多"。
- **b. M:N**。一名医生 → 多名病人；一名病人 → 多名医生。两边都"多"。
- **c. 1:1**。一个科室 → 一名主任；一名主任 → 一个科室。两边都只对 1 个。

**判法**：拿"一个"去数另一端能对上几个（讲义单元三）。

</details>

---

## 应用 2：1:N 转换为关系模式

**实体**：班级(<u>班级号</u>, 班级名)；学生(<u>学号</u>, 姓名)
**联系**：属于（班级 1 : N 学生）

**要求**：写出转换后的关系模式，并说明为什么这样放。

<details><summary>👉 点开对照答案</summary>

```
班级( 班级号, 班级名 )
学生( 学号, 姓名, 班级号 )      ← 把"1"端（班级）的键放进"N"端（学生）
```

**为什么**：一名学生只属于一个班级，所以"班级号"放进学生表**每行只有一个值**；反过来把"学号"放进班级表，一个班级有多个学生，**放不进去**（一格只能一个值，违反 1NF）。

</details>

---

## 应用 3：M:N 转换为关系模式

**实体**：医生(<u>医生编号</u>, 姓名)；病人(<u>病历号</u>, 姓名)
**联系**：诊治（医生 M : N 病人），联系属性：诊治日期、诊断结果

**要求**：写出转换后的关系模式，标出主键。

<details><summary>👉 点开对照答案</summary>

```
医生( 医生编号, 姓名 )
病人( 病历号, 姓名 )
诊治( 医生编号, 病历号, 诊治日期, 诊断结果 )
主键 = (医生编号, 病历号)
```

**要点**：
- M:N **必须单独建表**
- 表的列 = 两端实体的键 + 联系自己的属性（诊治日期、诊断结果）
- 主键 = **两端键的组合** `(医生编号, 病历号)`

</details>

---

## 应用 4：1:1 转换的两种方案

**实体**：科室(<u>科室编号</u>, 科室名)；医生(<u>医生编号</u>, 姓名)
**联系**：负责（科室 1 : 1 医生，即"科室主任"）

**要求**：给出 **两种**转换方案，并说明各自的特点。

<details><summary>👉 点开对照答案</summary>

**方案 A：合并（推荐）**

```
科室( 科室编号, 科室名, 主任医生编号 )
医生( 医生编号, 姓名 )
```

把"医生"的键放进"科室"表。**特点**：少一张表，查询方便；但"主任医生编号"允许为 NULL 时（科室暂时没主任）要注意。

**方案 B：单独建表**

```
科室( 科室编号, 科室名 )
医生( 医生编号, 姓名 )
科室主任( 科室编号, 主任医生编号 )
```

**特点**：表多一张，但"谁当主任"这件事单独存，语义更清晰，也方便以后扩展（比如记录任职时间）。

**考试建议**：题目没特别要求时，**1:1 合并更常见**。

</details>

## 应用 5：综合——完整 ER → 关系模式

**场景**（学校）：

- **实体**：
  - 学生(<u>学号</u>, 姓名)
  - 课程(<u>课程号</u>, 课程名)
  - 教师(<u>教师编号</u>, 姓名)
  - 班级(<u>班级号</u>, 班级名)
- **联系**：
  - **属于**：学生 N — 1 班级
  - **选修**：学生 M — N 课程，联系属性：成绩
  - **授课**：教师 M — N 课程（无联系属性）

**要求**：
① 写出最终的关系模式（每张表的列 + 主键）
② 一共有几张表？其中哪几个是"联系"转换来的？

<details><summary>👉 点开对照答案</summary>

**① 最终关系模式**

```
班级( 班级号, 班级名 )
学生( 学号, 姓名, 班级号 )              ← 1:N，1 端（班级）的键放进 N 端
课程( 课程号, 课程名 )
教师( 教师编号, 姓名 )
选修( 学号, 课程号, 成绩 )              ← M:N 单独建表
      主键 = (学号, 课程号)
授课( 教师编号, 课程号 )                ← M:N 单独建表
      主键 = (教师编号, 课程号)
```

**② 表数**：**6 张**

- **实体转来的 4 张**：班级、学生、课程、教师
- **联系转来的 2 张**：选修、授课（两个都是 M:N）
- **"属于"（1:N）不建表**——它的键已经放进学生表了

**易错点**：
- 别给"属于"单独建表（1:N 不建表）
- 别漏掉"授课"的 M:N 表（虽然它没有联系属性，**照样要建表**——表里只有两个键）

</details>

## 回 3【单选】候选键判定 ⭐错点 #7 回炉

关系 `R(A, B, C)`，FD：`A→B`、`B→C`。候选键是（ ）。

A. A　B. B　C. C　D. (A, B)

<details><summary>👉 点开对照答案与解析</summary>

**A。** 判候选键的铁律：**能确定全表所有属性**。
- A → B ✓，B → C ✓，所以 A 能推出 C → A 决定全表 ✅
- B 只能推 C，定不了 A ❌
- C 什么都定不了 ❌

所以候选键只有 **A**。

这是你 **D12 错题 #7**（当时把"只能确定部分属性"的读者编号/图书编号也当成了候选键），今天再练一遍。

</details>

## 回 4【单选】拆成 3NF ⭐错点 #8 回炉

承回 3：`R(A, B, C)`，FD：`A→B`、`B→C`。把它拆成 3NF，正确的是（ ）。

A. `(A, B)` + `(A, C)`
B. `(A, B)` + `(B, C)`
C. `(A, B, C)` 不拆
D. `(A)` + `(B, C)`

<details><summary>👉 点开对照答案与解析</summary>

**B。** `A→B→C` 是传递依赖，要**把链剪断**：中间属性 B 留在原表，被它决定的 C 跟 B 单独成表 → `(A,B)` + `(B,C)`。

- A 是"起点+终点"（`(A,C)`）→ 会丢 `B→C` 这条规则 ❌
- D 的 `(A)` 单独一张表没意义（只有键没有别的属性）
- C 没拆，传递依赖还在 ❌

这是你 **D12 错题 #8**（当时拆成 `(借阅号,读者编号,读者姓名)`，把整条链原样搬走，链没断），今天再练。

</details>

## 回 6【单选】DELETE 与 DROP

`DELETE FROM 表` 与 `DROP TABLE 表` 的区别是（ ）。

A. 没有区别
B. DELETE 删数据行（表还在），DROP 删整张表（连结构）
C. DELETE 删整张表，DROP 删数据行
D. 两者都只删数据

<details><summary>👉 点开对照答案与解析</summary>

**B。** 口诀：**DELETE 清空抽屉里的东西，DROP 把抽屉整个砸了**。前者 DML、后者 DDL（讲义 D9 单元四）。

</details>
