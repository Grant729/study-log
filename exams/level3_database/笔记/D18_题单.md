# ② 理论题检测（模块 10 + 11）

## 题 1【判断】4V 中的 Value

大数据的 4V 中，Value（价值）指的是"数据价值密度**高**"。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**错。** 4V 的 Value 指**价值密度低**——海量数据里有用信息占比小，需要挖掘（讲义单元一）。这是最常见的偷换概念。

</details>

## 题 2【单选】非结构化数据的占比

大数据中，**非结构化数据**大约占（ ）。

A. 20% 以下　B. 50% 左右　C. **80% 以上**　D. 100%

<details><summary>👉 点开对照答案与解析</summary>

**C（80% 以上）。** 结构化数据约占 10~20%，其余绝大部分是非结构化数据（文本、图片、音视频等）。这也是传统关系数据库搞不定大数据的原因。

</details>

## 题 5【判断】Hadoop 的两大核心

Hadoop 的两大核心是 HDFS（分布式文件系统）和 MapReduce（分布式计算）。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** HDFS 负责**存**、MapReduce 负责**算**（讲义单元四）。后来加入 YARN 管资源调度。

</details>

## 题 6【单选】NameNode 的职责

HDFS 中，NameNode 的主要职责是（ ）。

A. 存储实际的数据块
B. **管理命名空间和元数据（文件到数据块的映射等）**
C. 合并 FsImage 和 EditLog
D. 执行 MapReduce 任务

<details><summary>👉 点开对照答案与解析</summary>

**B。** NameNode 管"账本"（元数据），**不存实际数据**；DataNode 才存数据块（A）。C 是 SecondaryNameNode 的活，D 是 MapReduce 的活。

</details>

## 题 7【单选】SecondaryNameNode

关于 SecondaryNameNode，下列说法正确的是（ ）。

A. 它是 NameNode 的热备份，NameNode 挂了由它接替
B. **它辅助合并 FsImage 和 EditLog，减轻 NameNode 启动压力**
C. 它存储实际的数据块
D. 它负责执行 Reduce 任务

<details><summary>👉 点开对照答案与解析</summary>

**B。** ⚠️ **最经典的陷阱**：SecondaryNameNode **不是热备份**，不能接替 NameNode（讲义单元五）。它只做"合并元数据文件"这一件事。

</details>

## 题 8【单选】HDFS 数据块大小

Hadoop 2.x 及以上版本，HDFS 数据块的默认大小是（ ）。

A. 32MB　B. 64MB　C. **128MB**　D. 256MB

<details><summary>👉 点开对照答案与解析</summary>

**C（128MB）。** Hadoop 1.x 默认 64MB，2.x 及以上默认 128MB（讲义单元五）。**两个版本的数字都要认识**。

</details>

## 题 9【判断】MapReduce 的执行流程

MapReduce 的执行流程是：Map → Shuffle → Reduce。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** Map 映射输出键值对 → Shuffle 按 key 排序分组 → Reduce 聚合（讲义单元六）。WordCount 是最经典的例子。

</details>

## 应用 1：4V 匹配

把左边描述和右边的 4V 特征配对：

- a. 某平台每天新增数据量达 PB 级
- b. 用户点击行为要求毫秒级响应
- c. 数据里有表格、JSON、图片、视频
- d. 100 万条日志里真正有用的可能只有几十条

**问**：a/b/c/d 分别对应 Volume / Velocity / Variety / Value 中的哪个？

<details><summary>👉 点开对照答案</summary>

- **a → Volume（大量）**：数据规模大
- **b → Velocity（高速）**：要求处理速度快
- **c → Variety（多样）**：类型多
- **d → Value（价值密度低）**：100 万里只有几十条有用

</details>

## 应用 4：Hadoop 组件职责匹配

把职责和组件配对：

- a. 存储实际数据块
- b. 管理命名空间和元数据
- c. 合并 FsImage 和 EditLog
- d. 把 SQL 翻译成 MapReduce

## 应用 5：综合选型

某电商平台有以下需求：

- ① 存储每天产生的**海量用户行为日志**（PB 级），并做**离线统计报表**
- ② 需要**实时**监控用户下单行为，异常时立刻告警
- ③ 分析用户之间的**社交关系网络**（谁和谁有关注关系）

**问**：①②③ 分别适合用哪种计算模式/产品？说明理由。

<details><summary>👉 点开对照答案</summary>

**① 批处理（Hadoop MapReduce / HDFS）**
- 海量历史日志 + 离线统计 = 典型的**批处理**场景。HDFS 存、MapReduce 算。

**② 流计算（Storm / Flink）**
- "实时监控、立刻告警" = 数据持续到达、要求低延迟 = **流计算**。

**③ 图计算（Pregel / Giraph）**
- "社交关系网络" = 节点（用户）+ 边（关注关系）= **图计算**。

**答题思路**：先看"数据是历史的还是实时的"、"是不是关系网络"，再对到四种计算模式。

</details>
