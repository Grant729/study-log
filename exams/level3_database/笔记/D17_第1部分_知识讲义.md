## 单元一：为什么需要用户与权限

前面 16 天，你一直用 `root`（超级管理员）在操作——想建就建、想删就删。

但真实系统里，**不能让所有人都用 root**：

- 一个只负责查数据的员工，**不该有删表的权限**
- 一个外部系统接入，**只该看到它需要的那几张表**

**权限管理要解决的就是**：**谁能对哪些对象做什么操作。**

对应到 SQL，就是三组命令：

| 命令 | 作用 | 属于 |
|---|---|---|
| `CREATE USER` / `DROP USER` | 建用户 / 删用户 | DCL |
| `GRANT` | **授予**权限 | DCL |
| `REVOKE` | **回收**权限 | DCL |

## 单元二：用户管理——建用户 / 删用户 / 改密码

### 建用户

```sql
CREATE USER 'd17_stu'@'localhost' IDENTIFIED BY 'Test@12345';
```

**逐词**：
- `'d17_stu'@'localhost'` —— **用户名 @ 主机**
  - `localhost` = 只能从**本机**登录
  - `%` = 可以从**任意主机**登录
- `IDENTIFIED BY '密码'` —— 设置密码

⚠️ **MySQL 里"用户"是两个部分**：`用户名@主机`。`'tom'@'localhost'` 和 `'tom'@'%'` 是**两个不同的用户**——这是客观题爱考的细节。

### 改密码

```sql
ALTER USER 'd17_stu'@'localhost' IDENTIFIED BY '新密码';
```

### 删用户

```sql
DROP USER 'd17_stu'@'localhost';
```

⚠️ 删用户要写全 `用户名@主机`。

## 单元三：GRANT——授予权限（今天的主角）

### 基本语法

```sql
GRANT 权限列表 ON 对象 TO 用户;
```

**三段式**：**给谁（TO）· 对什么（ON）· 什么权限（GRANT）**

### 权限有哪些

| 权限 | 能干什么 |
|---|---|
| `SELECT` | 查 |
| `INSERT` | 插 |
| `UPDATE` | 改 |
| `DELETE` | 删 |
| `CREATE` | 建表/建库 |
| `DROP` | 删表/删库 |
| `ALL PRIVILEGES` | **全部权限** |

### "对象"的三个层级（重点）

| 写法 | 范围 | 例子 |
|---|---|---|
| `*.*` | **全局**：所有库所有表 | `GRANT SELECT ON *.* TO ...` |
| `库名.*` | **库级**：某个库的所有表 | `GRANT SELECT ON exam_practice.* TO ...` |
| `库名.表名` | **表级**：某一张表 | `GRANT SELECT ON exam_practice.读者 TO ...` |

**记忆**：**星号从右往左"放大"**——`库.表` 最具体，`库.*` 是整库，`*.*` 是全局。

### 例子

**授予"查读者表"的权限**：

```sql
GRANT SELECT ON exam_practice.读者 TO 'd17_stu'@'localhost';
```

**授予"查 + 插借阅表"**：

```sql
GRANT SELECT, INSERT ON exam_practice.借阅 TO 'd17_stu'@'localhost';
```

多个权限用**逗号**隔开。

**授予整个库的全部权限**：

```sql
GRANT ALL PRIVILEGES ON exam_practice.* TO 'd17_stu'@'localhost';
```

### WITH GRANT OPTION——允许他再转授权

```sql
GRANT SELECT ON exam_practice.读者
TO 'd17_stu'@'localhost'
WITH GRANT OPTION;
```

加了这一句，`d17_stu` 就有权**把 SELECT 权限再授给别人**。

⚠️ **危险性**：转授权链可能失控，生产环境慎用。考试常考"哪个选项允许转授权"。

### 新用户默认只有 USAGE

刚建的用户，`SHOW GRANTS` 会显示：

```
GRANT USAGE ON *.* TO `d17_stu`@`localhost`
```

**`USAGE` = "没有任何实际权限"**，只表示"这个用户存在、能连接"。这是判断题的坑：**"新用户默认拥有所有权限"→ 错**。

## 单元四：REVOKE——回收权限

语法和 GRANT 对称：

```sql
REVOKE 权限列表 ON 对象 FROM 用户;
```

**例**：收回"插借阅表"的权限

```sql
REVOKE INSERT ON exam_practice.借阅 FROM 'd17_stu'@'localhost';
```

### 回收全部权限（注意语法不同！）

```sql
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'd17_stu'@'localhost';
```

⚠️ **这里没有 `ON 对象`**——回收全部权限是 `FROM 用户`，不是 `ON ... FROM ...`。这是最容易写错的一句。

## 单元五：查看权限——SHOW GRANTS

```sql
SHOW GRANTS FOR 'd17_stu'@'localhost';
```

真实输出（本机已实测）：

```
GRANT USAGE ON *.* TO `d17_stu`@`localhost`
GRANT SELECT ON `exam_practice`.`读者` TO `d17_stu`@`localhost`
```

**读法**：第一行是"默认的 USAGE（无实际权限）"，后面每行是一条已授予的权限。

**验证权限是否生效**：用新用户登录后试试越权操作——本机实测：

```sql
-- 新用户只有 读者 的 SELECT，试着插一行：
INSERT INTO 读者 VALUES ('099','测试',0);
-- → 1142: INSERT command denied to user 'd17_stu'@'localhost' for table '读者'
```

**错误码 1142 = 权限不足（command denied）**。记住它，和前面的 1062/1048/1452/3819 凑成一组。

## 单元六：角色（Role，MySQL 8.0 支持）

如果很多人需要同一套权限，一个个授太麻烦。**角色** = "一组权限的打包"：

```sql
CREATE ROLE 'read_role';
GRANT SELECT ON exam_practice.* TO 'read_role';
GRANT 'read_role' TO 'd17_stu'@'localhost';
```

**理解**：角色像"岗位权限包"，发给某个人，他就一次性获得包里所有权限。

**考试定位**：知道角色是"权限的集合"即可，重点仍在 GRANT/REVOKE。
