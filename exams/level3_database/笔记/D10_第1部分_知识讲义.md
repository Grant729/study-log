## 单元一：函数依赖是什么——"知道 X，就能锁定 Y"

### 先接上 D3 学过的

D3 题 6 你见过这个箭头：

> `学号 → 姓名` 读作"学号决定姓名"：**知道学号，就能唯一确定姓名**。

这就是**函数依赖**（Functional Dependency，缩写 FD）。箭头左边是"因"，右边是"果"。

**图书馆里到处都是函数依赖**：

| 依赖 | 含义 |
|---|---|
| `读者编号 → 读者姓名` | 知道读者编号，就知道是谁 |
| `图书编号 → 书名` | 知道图书编号，就知道哪本书 |
| `借阅号 → 读者编号` | 知道借阅号，就知道谁借的 |

**一句话**：**函数依赖 = "由 X 能唯一推出 Y"，写 X → Y。**

⚠️ **箭头方向别搞反**：`读者编号 → 读者姓名` 是"编号决定姓名"，不是"姓名决定编号"（可能重名）。D3 就踩过"姓名 → 编号"的坑——**箭头永远从"唯一的"指向"被确定的"**。

## 单元二：完全 vs 部分函数依赖（今天的核心考点）

前面那些依赖，X 都是**单个属性**（读者编号、图书编号）。但真实世界里，很多表的"唯一标识"是**好几个属性拼在一起**的。这时就分出"完全"和"部分"了。

### 先看一张经典表：选课表

```
选课表 SC( 学号, 课程号, 成绩, 姓名 )
```

想一想：这张表里，**光靠学号能确定一行吗**？不能——一个学生选好几门课。**光靠课程号呢**？也不能——一门课好多人选。所以能唯一确定一行的，是 **`(学号, 课程号)` 两个属性绑在一起**。

这个"绑在一起才能锁定一行"的属性组，就是这张表的**码（键）**。它有两个成员，简称**组合键**。

### 关键问题来了：这张表里，"姓名"到底依赖谁？

看这两个依赖：

- `(学号, 课程号) → 成绩`
- `(学号, 课程号) → 姓名`

箭头右边不一样，但**箭头左边一样**（都是学号+课程号）。问题：**左边的两个属性，是不是都"用得上"？**

**对成绩**：必须**学号 + 课程号两个一起**才能确定成绩——单给学号，不知道是哪门课的成绩；单给课程号，不知道是谁的。→ 左边的每个属性都不可少，这叫**完全函数依赖**。

**对姓名**：其实**只要学号就够了**（`学号 → 姓名`），课程号是"多余的"。→ 左边有个真子集（学号）就能单独决定姓名，这叫**部分函数依赖**。

### 判据（一句话记死）

> **X → Y 里，X 的真子集能不能也决定 Y？**
> - 不能 → **完全依赖**（X 缺一不可）
> - 能 → **部分依赖**（X 里有多余属性）

**比喻**：开门要用一串钥匙。
- **完全依赖** = 每把钥匙都必要，少一把开不了（学号+课程号缺一不可，才能定成绩）。
- **部分依赖** = 钥匙串里有把多余的，其实单靠其中一把就能开（定姓名，课程号那把是多余的）。

**记号**（考试可能出现）：完全依赖记 `X →f→ Y`，部分依赖记 `X →p→ Y`。

### 一道判断题的逻辑

> "(学号, 课程号) → 姓名 是部分依赖" —— **对**，因为学号这个真子集就能决定姓名。
> "(学号, 课程号) → 成绩 是完全依赖" —— **对**，因为学号、课程号单独谁都定不了成绩。

## 单元三：传递函数依赖——依赖的"接力"

### 依赖会"顺着链条"传下去

看借阅表里的一条链：

```
借阅号 → 读者编号     （知道借阅号，知道谁借的）
读者编号 → 读者姓名   （知道读者编号，知道是谁）
```

那么问：**`借阅号 → 读者姓名` 成立吗？** 成立！因为借阅号能定读者编号，读者编号又能定姓名，接力下去，借阅号也能定姓名。

但这条依赖**不是直接来的**，是"**借道**读者编号"传过来的。这就是**传递函数依赖**：

> **X → Y、Y → Z，且 Y 不能反过来决定 X，则 X → Z 是传递依赖**（X 通过 Y 间接决定 Z）。

### 判据三要素

1. X → Y 成立
2. Y → Z 成立
3. **Y ↛ X**（Y 不能反过来决定 X——这是关键，否则 X 和 Y 是"等价"的，不算传递）

**上例检查**：借阅号 → 读者编号 ✅、读者编号 → 读者姓名 ✅、读者编号 ↛ 借阅号（一个读者能借很多次，所以读者编号不能唯一确定借阅号）✅ → **借阅号 → 读者姓名 是传递依赖**。

**再举个经典的**：

```
学号 → 系号      （学号定系）
系号 → 系主任    （系定系主任）
```
学号 → 系主任 就是传递依赖（借道"系号"）。

### 比喻

**传递依赖 = 传话**。A 不认识 C，但 A 认识 B、B 认识 C，于是 A 通过 B 间接联系上 C。信息"借 B 之口"传过去——中间多了一层，就多了一层冗余和风险（B 说错了，A 和 C 就对不上）。

## 单元四：候选键、主属性、非主属性（配套术语）

判断依赖类型时，常要提到这几个词：

| 术语 | 含义 | 例（选课表） |
|---|---|---|
| **候选键（码）** | 能唯一确定一行、且**任何真子集都不能**唯一确定一行的属性组 | `(学号, 课程号)` |
| **主属性** | 出现在某个候选键里的属性 | 学号、课程号 |
| **非主属性** | 不在任何候选键里的属性 | 成绩、姓名 |

**判候选键两步**：
1. 这组属性能唯一确定全表所有属性吗？
2. 去掉其中任何一个，还能唯一确定吗？——能的话就"还不够精简"，不是候选键。

`(学号,课程号)` 是候选键：它能定全表；去掉学号只剩课程号定不了、去掉课程号只剩学号也定不了 → 最精简 → 候选键。

## 单元五：为什么非学函数依赖不可——给范式铺路

函数依赖不是"背概念"用的，它是**诊断表"有没有病"的工具**。三种依赖对应三种病：

| 依赖类型 | 会引起的病 | 谁来治 |
|---|---|---|
| 部分依赖 | 数据冗余、改一处漏一处（更新异常） | **2NF**（D11 学） |
| 传递依赖 | 冗余更深、牵连更广 | **3NF**（D11 学） |
| 完全依赖 | ✅ 健康的，不用治 | — |

**一句话预告**：D11 你学的 1NF/2NF/3NF，就是"怎么把有病的表拆成没病的表"，而**判病靠的就是今天的函数依赖**。所以今天这块是地基——**完全/部分/传递分不清，D11 的范式就无从下手**。
