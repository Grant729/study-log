## 题 2【判断】UNIQUE 与 NULL

MySQL 里给某列加了 UNIQUE 约束后，该列就不允许出现 NULL。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**错。** UNIQUE 只管"取值不重复"，而 NULL 彼此不算"相等"，所以**允许多个 NULL**（本机已实测：同一 UNIQUE 列插两个 NULL 不报错）。SQL Server 只许一个 NULL，MySQL 不管——这是判断题爱挖的坑。

</details>

## 题 4【单选】CHECK 属于哪类

CHECK 约束属于（ ）。

A. 实体完整性　B. 参照完整性　C. 用户定义完整性　D. 以上都不是

<details><summary>👉 点开对照答案与解析</summary>

**C。** CHECK 是业务自定的规矩（馆藏量≥0），属于用户定义完整性。主键管实体、外键管参照，其余（NOT NULL/UNIQUE/CHECK/DEFAULT）都是用户定义。

</details>

## 题 6【单选】函数依赖的含义

"学号 → 姓名"表示（ ）。

A. 知道学号就能唯一确定姓名
B. 知道姓名就能唯一确定学号
C. 学号和姓名一一对应
D. 学号不能为空

<details><summary>👉 点开对照答案与解析</summary>

**A。** X → Y 读作"X 决定 Y"：知道 X 的值，Y 被唯一确定（讲义单元四）。箭头从"唯一的东西"指向"被唯一确定的东西"——姓名→学号不成立（可能重名），C 的"一一对应"是"互相决定"，比题意强了，也不对。

</details>

## 题 8【单选】外键的写法

在选课表中正确定义外键（引用学生表的学号）的语句是（ ）。

A. PRIMARY KEY (学号)
B. FOREIGN KEY (学号) REFERENCES 学生(学号)

D. CHECK (学号 NOT NULL)

<details><summary>👉 点开对照答案与解析</summary>

## 题 10【单选】CHECK 的执行

向图书表插入一行"馆藏量 = -5"的数据（建表时写了 `CHECK (馆藏量 >= 0)`），MySQL 8.0.23 会（ ）。

A. 拒绝执行并报错
B. 允许插入
C. 自动改成 0
D. 视配置而定

<details><summary>👉 点开对照答案与解析</summary>

**A。** MySQL 8.0.16 起才强制执行 CHECK，你的 8.0.23 会真管：拒绝执行并报 3819。B 是 8.0.16 以前老版本的行为（写了也白写）——判断题若说"MySQL 从不执行 CHECK"就是错在"从不"二字（老版本不执行、新版本执行）。C、D 纯编造。

</details>

## 题 11【实操】建两张有家规的表（六大约束全家桶）

**【目的】** 把讲义单元二的建表语句亲手跑一遍，为题 12~14 打地基。
**【前置】** 笔记本前 3 格已跑通（连的是 `exam_practice`）。
**【要求】** 新建**一个**代码格（第一行 `%%sql`），从上到下依次：

1. `DROP TABLE IF EXISTS 借阅;` —— **先删子表**
2. `DROP TABLE IF EXISTS 图书;` —— 再删父表（顺序反了会被外键拦住，见讲义单元二⑦）
3. 建 `图书` 表（主键 / 非空 / 默认 / CHECK）
4. 建 `借阅` 表（自增主键 / 外键×2 / 函数默认值 / CASCADE）
5. 插入图书 4 行、借阅 5 行（数据照抄）
6. 最后 `SELECT * FROM 图书; SELECT * FROM 借阅;`

**数据**（照抄即可）：

- 图书：`('B001','数据库系统概论','高等教育出版社',5)`、`('B002','R语言实战','人民邮电出版社',3)`、`('B003','Python编程','人民邮电出版社',4)`、`('B004','信息检索导论','高等教育出版社',2)`
- 借阅（读者编号,图书编号,应还日期）：`('001','B001','2026-11-15')`、`('002','B002','2026-11-15')`、`('003','B003','2026-11-20')`、`('004','B004','2026-11-20')`、`('004','B001','2026-11-25')`

**【提示】** 建表语句照讲义单元二抄，别抄错顺序；借阅日期不用填——它会自己长出来。
**【验收】** 图书 4 行、借阅 5 行；借阅号 1~5；**借阅日期全部自动填了今天（2026-10-08）**——这就是 `DEFAULT (CURDATE())` 在干活。

<details><summary>👉 点开对照答案与解析</summary>

```sql
%%sql
DROP TABLE IF EXISTS 借阅;
DROP TABLE IF EXISTS 图书;

CREATE TABLE 图书 (
  图书编号 CHAR(4) PRIMARY KEY,
  书名     VARCHAR(50) NOT NULL,
  出版社   VARCHAR(30) DEFAULT '未知出版社',
  馆藏量   INT DEFAULT 1 CHECK (馆藏量 >= 0)
);

CREATE TABLE 借阅 (
  借阅号   INT PRIMARY KEY AUTO_INCREMENT,
  读者编号 CHAR(3) NOT NULL,
  图书编号 CHAR(4) NOT NULL,
  借阅日期 DATE DEFAULT (CURDATE()),
  应还日期 DATE NOT NULL,
  FOREIGN KEY (读者编号) REFERENCES 读者(读者编号) ON DELETE CASCADE,
  FOREIGN KEY (图书编号) REFERENCES 图书(图书编号)
);

INSERT INTO 图书 (图书编号,书名,出版社,馆藏量) VALUES
('B001','数据库系统概论','高等教育出版社',5),
('B002','R语言实战','人民邮电出版社',3),
('B003','Python编程','人民邮电出版社',4),
('B004','信息检索导论','高等教育出版社',2);

INSERT INTO 借阅 (读者编号,图书编号,应还日期) VALUES
('001','B001','2026-11-15'),
('002','B002','2026-11-15'),
('003','B003','2026-11-20'),
('004','B004','2026-11-20'),
('004','B001','2026-11-25');

SELECT * FROM 图书;
SELECT * FROM 借阅;
```

真实输出（本机已实测）：

```
图书：
B001  数据库系统概论  高等教育出版社  5
B002  R语言实战      人民邮电出版社  3
B003  Python编程     人民邮电出版社  4
B004  信息检索导论   高等教育出版社  2

借阅：
1  001  B001  2026-10-08  2026-11-15   ← 借阅日期自动长出来的！
2  002  B002  2026-10-08  2026-11-15
3  003  B003  2026-10-08  2026-11-20
4  004  B004  2026-10-08  2026-11-20
5  004  B001  2026-10-08  2026-11-25
```

解析：一个代码格里 6 件事全做了。顺序是刻意的：**先删子表（借阅）再删父表（图书）**——反过来删，外键会报"有子表引用我，不许删"。插入借阅时没给借阅日期，`DEFAULT (CURDATE())` 自动补上今天。

</details>

## 题 12【实操】故意犯规——亲眼见四个错误码

**【目的】** 完整性不是"说说而已"，MySQL 真的会执法。**记住四个错误码 = 记住四条家规**。
**【前置】** 完成题 11（表和 9 行数据都在）。
**【要求】** **四个代码格、每格一条**（这样一条报错不影响下一条），每条跑完把**错误码**记在答案里：

- a. 插一个不存在的读者：`INSERT INTO 借阅 (读者编号,图书编号,应还日期) VALUES ('999','B001','2026-11-15');`
- b. 插重复主键：`INSERT INTO 图书 VALUES ('B001','重复的书','某出版社',1);`
- c. 插 NULL 读者编号：`INSERT INTO 借阅 (读者编号,图书编号,应还日期) VALUES (NULL,'B001','2026-11-15');`
- d. 插负馆藏量：`INSERT INTO 图书 VALUES ('B009','负馆藏','某出版社',-1);`

**【提示】** 今天的目的**就是看报错**——报错说明家规在上班。
**【验收】** 四条全报错：a = 1452（外键）、b = 1062（主键重复）、c = 1048（非空）、d = 3819（CHECK）。

<details><summary>👉 点开对照答案与解析</summary>

真实报错（本机已实测，中文部分按你的库名显示）：

- a. `IntegrityError: (1452, 'Cannot add or update a child row: a foreign key constraint fails ... FOREIGN KEY (\`读者编号\`) REFERENCES \`读者\` (\`读者编号\`)')`
- b. `IntegrityError: (1062, "Duplicate entry 'B001' for key '图书.PRIMARY'")`
- c. `IntegrityError: (1048, "Column '读者编号' cannot be null")`
- d. `OperationalError: (3819, "Check constraint '图书_chk_1' is violated.")`

解析：四连犯规对应四条家规——a 违反**参照完整性**（999 不在读者表里），b 违反**实体完整性**（主键重复），c 违反**NOT NULL**，d 违反 **CHECK**。注意 a 的报错里点名了是哪个外键（`读者编号` 那个），MySQL 会告诉你"哪个亲戚查无此人"。

</details>

## 题 13【实操】CASCADE 实测——删赵六，借阅记录自动蒸发

**【目的】** 亲眼见 `ON DELETE CASCADE` 执法，理解"参照完整性 + 违约方案"。
**【前置】** 完成题 12（表和 9 行数据都还在，那 4 条失败插入没留下任何东西）。
**【要求】** 新建**一个**代码格，从上到下：

1. `DELETE FROM 读者 WHERE 读者编号='004';`
2. `SELECT * FROM 借阅;` —— 观察：赵六的两条借阅记录（借阅号 4、5 两行）**自动消失了**，你没有手动删借阅表
3. 恢复现场（数据照抄）：
   - `INSERT INTO 读者 VALUES ('004','赵六',2);`
   - `INSERT INTO 借阅 (读者编号,图书编号,应还日期) VALUES ('004','B004','2026-11-20'),('004','B001','2026-11-25');`
4. `SELECT * FROM 借阅; SELECT * FROM 读者;`

**【提示】** 恢复后赵六的借阅号可能不是 4、5——失败的插入会吃掉自增号，**跳号正常**（讲义单元二⑥）。
**【验收】** 删赵六后借阅表只剩 3 行；恢复后借阅表 5 行、读者表 4 人。

<details><summary>👉 点开对照答案与解析</summary>

```sql
%%sql
DELETE FROM 读者 WHERE 读者编号='004';
SELECT * FROM 借阅;
-- 此时只剩 3 行：借阅号 1、2、3（赵六的 4、5 被 CASCADE 自动带走了）

INSERT INTO 读者 VALUES ('004','赵六',2);
INSERT INTO 借阅 (读者编号,图书编号,应还日期) VALUES

```

真实输出（本机已实测）：

```
删赵六后 SELECT * FROM 借阅：
```

## 题 14【实操】ALTER TABLE——表建好了也能补家规

**【目的】** `ALTER TABLE` 加列、加约束是考试常客（D4 的 DDL 还会再见）。
**【前置】** 完成题 13（表和 9 行数据都在）。
**【要求】** **两个代码格**：

**格 1：**

```sql
ALTER TABLE 借阅 ADD COLUMN 归还日期 DATE DEFAULT NULL;
ALTER TABLE 图书 ADD CONSTRAINT chk_馆藏上限 CHECK (馆藏量 BETWEEN 0 AND 50);
DESCRIBE 借阅;
```

观察：借阅表现在有 **6 列**（归还日期在最下面），图书表多了一条"馆藏量不许超过 50"的家规。

**格 2**（故意犯规验证新家规）：

```sql
INSERT INTO 图书 VALUES ('B010','超量书','某出版社',60);
```

**【提示】** 格 1 是建表后"补家规"，格 2 验证新家规真的生效。
**【验收】** `DESCRIBE 借阅` 看到 6 列；格 2 报 **3819**（chk_馆藏上限）。

<details><summary>👉 点开对照答案与解析</summary>

真实输出（本机已实测）：

`DESCRIBE 借阅` 显示 6 列（Field/Type/Null/Key/Default/Extra 表头下）：

```
借阅号   int       NO   PRI  (自增)     ← auto_increment
读者编号 char(3)   NO   MUL
图书编号 char(4)   NO   MUL
借阅日期 date      YES       curdate()  ← DEFAULT_GENERATED
应还日期 date      NO
归还日期 date      YES       NULL       ← 新加的列
```

格 2 报错：`OperationalError: (3819, "Check constraint 'chk_馆藏上限' is violated.")`——60 > 50，新家规上班了。

解析：`ALTER TABLE 表名 ADD COLUMN 列名 类型 约束` 是补列的句式；`ALTER TABLE 表名 ADD CONSTRAINT 约束名 CHECK (条件)` 是补约束的句式。补完立刻犯规验证——这条 CHECK 和建表时写的 `馆藏量 >= 0` 同时生效（馆藏量现在被两条家规管着：0~50）。

</details>

## 回 10【实操】投影去重的 SQL 实现（DISTINCT）

**【目的】** D2 学了"投影会去重"的概念，今天给它 SQL 实现——`SELECT DISTINCT`。
**【前置】** 完成题 11（图书表的 4 行数据在；B001/B004 同出版社、B002/B003 同出版社——故意设计的重复）。
**【要求】** 新代码格：查出图书表里**出现过哪些出版社（不重复）**。
**【提示】** 挑列 = SELECT，去重 = 加个关键词 `DISTINCT`。
**【验收】** 结果 2 行：高等教育出版社、人民邮电出版社（4 行压成 2 行）。

<details><summary>👉 点开对照答案与解析</summary>

```sql
%%sql
SELECT DISTINCT 出版社 FROM 图书;
```

真实输出（本机已实测）：

```
高等教育出版社
人民邮电出版社
```

解析：`SELECT 出版社` = 投影 π（竖着切下出版社列，4 行）；加 `DISTINCT` 后重复行合并，只剩 2 行——**这就是"投影去重"在 SQL 里的样子**。呼应回 8：行数变少不是出错，是去重。

</details>
