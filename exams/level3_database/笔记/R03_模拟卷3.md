# 一、判断题（10 题 × 1 分 = 10 分）

## 题 1

事务一旦 `COMMIT`，就不能再用 `ROLLBACK` 撤销。

<details><summary>👉 答案与解析</summary>

**对。** COMMIT 后数据持久化（ACID 的 D），只能再写反向 DML 改回来。

</details>

---

## 题 2

在 SQL 中，`WHERE` 子句可以引用 `SELECT` 中定义的列别名。

<details><summary>👉 答案与解析</summary>

**错。** WHERE 在 SELECT **之前**执行，看不到别名；ORDER BY 才能用。

</details>

---

## 题 3

一个表可以有多个候选键，但主键只能有一个。

<details><summary>👉 答案与解析</summary>

**对。** 候选键 = 有资格当主键的（可多个）；主键 = 从里面选 **1 个**。

</details>

---

## 题 4

网状模型用"节点和边"来表示记录之间的联系。

<details><summary>👉 答案与解析</summary>

**错。** **网状模型用指针**；"节点和边"是**图模型**。

</details>

---

## 题 5

两个表做笛卡儿积，结果的行数等于两表行数之和。

<details><summary>👉 答案与解析</summary>

**错。** 笛卡儿积**行数相乘**、列数相加。

</details>

---

## 题 6

`LIMIT 3, 2` 表示"跳过前 3 行，再取 2 行"。

<details><summary>👉 答案与解析</summary>

**对。** `LIMIT 偏移量, 行数`，偏移量从 0 数。`LIMIT 3,2` = 第 4、5 行。

</details>

---

## 题 7

统计"某学员报了几门课"，直接读学员表里的"报名数"汇总列即可，不需要去报名表里数。

<details><summary>👉 答案与解析</summary>

</details>

## 题 8

视图在数据库中只保存定义（SELECT 语句），不保存数据。

<details><summary>👉 答案与解析</summary>

</details>

事务的隔离性是指并发执行的事务之间互不干扰。

## 题 41（10 分）综合设计（健身房）

> **2026-10-23 修订**：原题把实体、属性、联系逐条罗列出来了，**太直白**，不像真题。真实试卷是给**一段业务描述**，让考生自己提取信息（参考 2018 浙江真题：田径锦标赛管理系统，ER 12 分 + 关系模式 8 分 + 建表 SQL 4 分）。现改为**纯文字需求**。

**需求描述**：

> 某健身房准备开发一套管理系统。每位**会员**有会员号、姓名和电话；每位**教练**有教练号、姓名和专长；每门**课程**有课程号、课程名和课时费。一名教练可以教授多门课程，但每门课程只由一名教练负责。一名会员可以预约多门课程，同时一门课程也可以被多名会员预约；每次预约都需要记录预约日期。

**要求**：

1. （3 分）从上述描述中找出**实体、属性、联系**，并指出各联系的类型及理由
2. （3 分）转换为关系模式，标出每张表的**主码（主键）和外码（外键）**
3. （2 分）假设有人把预约信息设计成了一张宽表：

   `预约_冗余(会员号, 会员姓名, 课程号, 课程名, 预约日期)`

   已知 FD：`(会员号,课程号) → 预约日期`、`会员号 → 会员姓名`、`课程号 → 课程名`。
   问：**候选键是什么？最高满足第几范式？为什么？**

4. （2 分）把第 3 问的宽表**规范化到 3NF**，写出分解后的关系模式

<details><summary>👉 答案与解析</summary>

**1. ER 三要素（3 分）**

- 实体：会员(<u>会员号</u>, 姓名, 电话)、教练(<u>教练号</u>, 姓名, 专长)、课程(<u>课程号</u>, 课程名, 课时费)
- 联系：
  - **授课**：教练 1 — N 课程（一个教练教多门课；一门课一个教练）
  - **预约**：会员 M — N 课程（一个会员约多门课；一门课被多个会员约），属性：预约日期

**2. 关系模式（3 分）**

```
会员( 会员号, 姓名, 电话 )
教练( 教练号, 姓名, 专长 )
课程( 课程号, 课程名, 课时费, 教练号 )      ← 授课 1:N，1 端键放 N 端；外键：教练号
预约( 会员号, 课程号, 预约日期 )            ← 预约 M:N，单独建表
      主键 = (会员号, 课程号)
      外键：会员号 → 会员；课程号 → 课程
```

**3. 判范式（2 分）**

- **候选键 = `(会员号, 课程号)`**（能确定全表且最精简）
- 非主属性 = 会员姓名、课程名、预约日期
- **会员姓名**：`会员号 → 会员姓名`，会员号是候选键的**真子集** → **部分依赖** ❌
- **课程名**：`课程号 → 课程名`，课程号是真子集 → **部分依赖** ❌
- → 存在部分依赖 → **最高只满足 1NF**

**4. 规范化到 3NF（2 分）**

```
预约( 会员号, 课程号, 预约日期 )   ← 主键 (会员号,课程号)
会员( 会员号, 会员姓名 )
课程( 课程号, 课程名 )
```

拆完：会员姓名只依赖会员号、课程名只依赖课程号、预约日期依赖整个组合键 → 三张表都是 3NF。

</details>

## 题 42（10 分）SQL 综合（餐厅）

**场景**：

- `菜品(菜品号, 菜名, 单价, 分类)`
- `点单(订单号, 菜品号, 数量, 下单时间)`，主键 `(订单号, 菜品号)`

**数据**：

| 菜品号 | 菜名 | 单价 | 分类 |
|---|---|---|---|
| D01 | 宫保鸡丁 | 38.00 | 热菜 |
| D02 | 麻婆豆腐 | 28.00 | 热菜 |
| D03 | 凉拌黄瓜 | 12.00 | 凉菜 |
| D04 | 米饭 | 3.00 | 主食 |

| 订单号 | 菜品号 | 数量 | 下单时间 |
|---|---|---|---|
| O001 | D01 | 2 | 2026-10-22 12:00:00 |
| O001 | D02 | 1 | 2026-10-22 12:00:00 |
| O002 | D01 | 1 | 2026-10-22 18:30:00 |
| O003 | D04 | 3 | 2026-10-22 18:30:00 |

**要求**：
1. （4 分）建 `菜品`、`点单` 两张表（菜品号主键；点单复合主键 + 菜品号外键；数量、下单时间非空）
2. （2 分）插入上面的数据
3. （4 分）查询：
   - A：每个菜品的**销售额**（`单价 × 数量` 求和），按销售额降序
   - B：**没有被点过**的菜品名

**预期输出 A**：
```
宫保鸡丁 | 114.00
麻婆豆腐 | 28.00
米饭     | 9.00
```

**预期输出 B**：
```
凉拌黄瓜
```

<details><summary>👉 答案与解析</summary>

**1. 建表（4 分）**

```sql
CREATE TABLE 菜品 (
  菜品号 CHAR(3) PRIMARY KEY,
  菜名 VARCHAR(20) NOT NULL,
  单价 DECIMAL(6,2) NOT NULL,
  分类 VARCHAR(10)
);

CREATE TABLE 点单 (
  订单号 CHAR(4),
  菜品号 CHAR(3),
  数量 INT NOT NULL,
  下单时间 DATETIME NOT NULL,
  PRIMARY KEY (订单号, 菜品号),
  FOREIGN KEY (菜品号) REFERENCES 菜品(菜品号)
);
```

**2. 插入（2 分）**

```sql
INSERT INTO 菜品 VALUES
('D01','宫保鸡丁',38.00,'热菜'),('D02','麻婆豆腐',28.00,'热菜'),
('D03','凉拌黄瓜',12.00,'凉菜'),('D04','米饭',3.00,'主食');

INSERT INTO 点单 VALUES
('O001','D01',2,'2026-10-22 12:00:00'),
('O001','D02',1,'2026-10-22 12:00:00'),
('O002','D01',1,'2026-10-22 18:30:00'),
('O003','D04',3,'2026-10-22 18:30:00');
```

**3. 查询（4 分）**

A：

```sql
SELECT 菜品.菜名, SUM(菜品.单价 * 点单.数量) AS 销售额
FROM 菜品
INNER JOIN 点单 ON 菜品.菜品号 = 点单.菜品号
GROUP BY 菜品.菜品号, 菜品.菜名
ORDER BY 销售额 DESC;
```

B：

```sql
SELECT 菜名
FROM 菜品
WHERE 菜品号 NOT IN (SELECT 菜品号 FROM 点单);
```

**评分要点**：A 要 JOIN + GROUP BY + `SUM(单价*数量)`；B 用 `NOT IN`（或 `LEFT JOIN ... IS NULL`）。

## 题 43（10 分）存储过程 + 触发器（流媒体）

**场景**：

- `用户(用户号, 昵称, 观看次数)`
- `观看记录(记录号, 用户号, 影片号, 观看日期)`，记录号自增主键，用户号为外键

**要求**：
1. （3 分）建两张表
2. （1 分）插入用户：`('U01','小明',2)`、`('U02','小红',1)`；插入 3 条观看记录：
   `('U01','M001','2026-10-20')`、`('U01','M002','2026-10-21')`、`('U02','M001','2026-10-21')`
3. （3 分）创建触发器 `trg_删观看减次数`：**删除一条观看记录时**，自动把该用户的观看次数 **-1**（用 `OLD`）
4. （3 分）创建存储过程 `p_观看数`：输入用户号（IN），输出该用户的观看记录数（OUT），并调用验证
5. 测试：删除 U01 的一条记录（如影片 M002），查用户表，U01 的观看次数应从 2 变成 1

**预期**：U01 小明 1 / U02 小红 1；`p_观看数('U01')` 返回 1

<details><summary>👉 答案与解析</summary>

**1. 建表（3 分）**

```sql
CREATE TABLE 用户 (
  用户号 CHAR(3) PRIMARY KEY,
  昵称 VARCHAR(20) NOT NULL,
  观看次数 INT DEFAULT 0
);

CREATE TABLE 观看记录 (
  记录号 INT PRIMARY KEY AUTO_INCREMENT,
  用户号 CHAR(3) NOT NULL,
  影片号 CHAR(4) NOT NULL,
  观看日期 DATE,
  FOREIGN KEY (用户号) REFERENCES 用户(用户号)
);
```

**2. 插入（1 分）**

```sql
INSERT INTO 用户 VALUES ('U01','小明',2),('U02','小红',1);

INSERT INTO 观看记录(用户号,影片号,观看日期) VALUES
('U01','M001','2026-10-20'),
('U01','M002','2026-10-21'),
('U02','M001','2026-10-21');
```

**3. 触发器（3 分）**

```sql
CREATE TRIGGER trg_删观看减次数
AFTER DELETE ON 观看记录
FOR EACH ROW
BEGIN
  UPDATE 用户 SET 观看次数 = 观看次数 - 1
  WHERE 用户号 = OLD.用户号;
END;
```

**4. 存储过程（3 分）**

```sql
CREATE PROCEDURE p_观看数(IN p_用户号 CHAR(3), OUT p_数 INT)
BEGIN
  SELECT COUNT(*) INTO p_数 FROM 观看记录 WHERE 用户号 = p_用户号;
END;

CALL p_观看数('U01', @数);
SELECT @数 AS 观看记录数;
```

**5. 测试**

```sql
DELETE FROM 观看记录 WHERE 用户号='U01' AND 影片号='M002';
SELECT * FROM 用户;
-- U01 小明 1 / U02 小红 1
```

⚠️ **注意**：存储过程要 **COUNT 观看记录明细表**，不要读 `用户.观看次数`（汇总列）。这正是 R02 题 43 暴露的错点。

**清理（触发器必删）**：

```sql
DROP TRIGGER IF EXISTS trg_删观看减次数;
DROP PROCEDURE IF EXISTS p_观看数;
```

</details>
