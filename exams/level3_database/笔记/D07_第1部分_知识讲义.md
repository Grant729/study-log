## 单元一：从"整列压成一个数"到"每组压成一个数"

### 先回想 D5 学过的聚合函数

D5 你学了五个聚合函数：`COUNT` `SUM` `AVG` `MAX` `MIN`。它们干的事是——**把一整列压成一个数**：

```sql
SELECT COUNT(*) FROM 图书;      -- 4（一共 4 本书）
SELECT SUM(馆藏量) FROM 图书;   -- 14（所有书的馆藏量加起来）
```

### 但实际问题往往是"每组一个数"

图书馆馆长问你：**每个出版社各有几本书？各有几本馆藏量？**

用上面那招行吗？`SELECT COUNT(*) FROM 图书` 只能告诉你"总共 4 本"，可馆长要的是**分开的**：

- 高等教育出版社：几本？多少馆藏？
- 人民邮电出版社：几本？多少馆藏？

**一句话理解 GROUP BY**：

> `GROUP BY 出版社` = 先按"出版社"这列，把 4 行**分成两堆**（高教堆、人邮堆），再对**每一堆**分别用聚合函数。

就像食堂分餐：先按班级把学生**分好队**，再**每队**数人数、算饭钱。不分组 = 全校一起算；分组 = 每班各算各的。

## 单元二：GROUP BY 语法逐词拆

```sql
SELECT 出版社, COUNT(*), SUM(馆藏量)
FROM 图书
GROUP BY 出版社;
```

真实输出（本机已实测）：

```
出版社        | COUNT(*) | SUM(馆藏量)
-------------|----------|-----------
高等教育出版社 | 2        | 7
人民邮电出版社 | 2        | 7
```

**逐词解析**：

- `GROUP BY 出版社` —— "按出版社分组"。MySQL 会扫一遍图书表，把出版社相同的行归成一堆。
- 分组**之后**，`COUNT(*)` 和 `SUM(馆藏量)` 不再是"整表算一次"，而是**对每一堆算一次**：
  - 高教堆里有 B001（馆藏5）、B004（馆藏2）→ COUNT = 2 本，SUM = 5+2 = 7
  - 人邮堆里有 B002（馆藏3）、B003（馆藏4）→ COUNT = 2 本，SUM = 3+4 = 7
- 结果：**一个出版社一行**，每行是这个出版社自己的小计。

⚠️ **这组数据两行恰好都算出来"2 本、7 馆藏"——纯属数据巧合**，不是分组没生效。分组的效果看"**每个出版社单独出了结果**"，而不是"两个结果一定要不一样"。

### 聚合函数全家都能分组用

```sql
SELECT 出版社,
       COUNT(*) AS 本数,
       SUM(馆藏量) AS 总馆藏,
       AVG(馆藏量) AS 平均馆藏,
       MAX(馆藏量) AS 最多馆藏,
       MIN(馆藏量) AS 最少馆藏
FROM 图书
GROUP BY 出版社;
```

真实输出：

```
出版社        | 本数 | 总馆藏 | 平均馆藏 | 最多馆藏 | 最少馆藏
-------------|------|--------|----------|----------|----------
高等教育出版社 | 2    | 7      | 3.5000   | 5        | 2
人民邮电出版社 | 2    | 7      | 3.5000   | 4        | 3
```

**读法**：D5 的五个函数，套上 `GROUP BY` 就变成"**每个出版社一份小报告**"。

## 单元三：SELECT 里的"安全区"（高频考点，会报错）

**分组之后，`SELECT` 里只能放两类东西**：

1. **`GROUP BY` 里出现过的列**（比如 `出版社`）
2. **聚合函数**（`COUNT` / `SUM` / `AVG` / `MAX` / `MIN`）

除此之外的列，**一放就报错**。因为分组后，每个"组"里其实有好几行——比如高教组里有 B001 和 B004 两本书，那 `书名` 这一列该显示哪本？MySQL 不知道，干脆报错。

亲手试试（**故意犯规**）：

```sql
SELECT 出版社, 书名, COUNT(*)
FROM 图书
GROUP BY 出版社;
```

报错（本机已实测）：

```
1055: Expression #2 of SELECT list is not in GROUP BY clause ...
      incompatible with sql_mode=only_full_group_by
```

**翻译**：`书名` 既不在 `GROUP BY` 里、又不是聚合函数 → 不允许。

> 为什么会报错？因为你的 MySQL 开着 `ONLY_FULL_GROUP_BY` 模式（默认就开）。它是**好事**：逼你写正确的分组查询，而不是猜哪一行会被显示。

**记忆口诀**：**分组之后，SELECT 里只能有"分组的列 + 聚合的函数"，多一个普通列就报 1055。**

## 单元四：WHERE vs HAVING —— 一个筛行，一个筛组（必考）

这是本模块**最爱考**的一对。它们长得像、都带条件，但**管的层级不同**：

| | 什么时候执行 | 筛什么 | 能写聚合函数吗 |
|---|---|---|---|
| **WHERE** | 分组**之前** | 筛**行**（一行行过滤） | ❌ 不能 |
| **HAVING** | 分组**之后** | 筛**组**（一组组过滤） | ✅ 必须/可以 |

### 例 1：WHERE 筛行（先筛再分组）

"**馆藏量大于 2 的书**，按出版社统计有几本"：

```sql
SELECT 出版社, COUNT(*) AS 本数
FROM 图书
WHERE 馆藏量 > 2
GROUP BY 出版社;
```

真实输出：

```
出版社        | 本数
-------------|------
高等教育出版社 | 1
人民邮电出版社 | 2
```

**读法**：先把馆藏量 ≤2 的**行**刷掉（信息检索导论 B004 馆藏2 出局），**再**对剩下的 3 行分组。所以高教组只剩 B001 一本。

### 例 2：HAVING 筛组（先分组再筛）

"**书 ≥ 2 本的出版社**有哪几个"：

```sql
SELECT 出版社, COUNT(*) AS 本数
FROM 图书
GROUP BY 出版社
HAVING COUNT(*) >= 2;
```

真实输出：

```
出版社        | 本数
-------------|------
高等教育出版社 | 2
人民邮电出版社 | 2
```

**读法**：先分组、算出每组本数，**再**把"本数 < 2"的**组**整组刷掉。

### 例 3：HAVING 里用别的聚合函数

"**馆藏量最多的书 ≥ 5 的出版社**"：

```sql
SELECT 出版社, MAX(馆藏量) AS 最多馆藏
FROM 图书
GROUP BY 出版社
HAVING MAX(馆藏量) >= 5;
```

真实输出：

```
出版社        | 最多馆藏
-------------|---------
高等教育出版社 | 5
```

**读法**：高教组里有 B001 馆藏5，MAX = 5 ≥ 5，留下；人邮组 MAX = 4，整组刷掉。**注意 HAVING 里写的是 `MAX(馆藏量)`，不是 `馆藏量`**——因为"筛组"用的条件是"这组的最大值"，得用聚合函数。

### ⚠️ 铁律：WHERE 里写聚合函数 = 报错

```sql
SELECT 出版社 FROM 图书 WHERE COUNT(*) > 2 GROUP BY 出版社;
```

报错（本机已实测）：

```
1111: Invalid use of group function
```

**为什么**：`WHERE` 在分组**之前**执行，那时候"组"还没分出来，`COUNT(*)` 无从算起。所以**聚合函数只能出现在 `SELECT`、`HAVING`、`ORDER BY` 里，绝不能出现在 `WHERE` 里**。

**一句话记牢**：**WHERE 筛行（分组前，不能碰聚合），HAVING 筛组（分组后，专配聚合）。**

## 单元五：执行顺序补全（把 D5/D6 的拼图补上）

D5 你记的是 `FROM → WHERE → SELECT → ORDER BY`，D6 加了个 `LIMIT`。今天补上 `GROUP BY` 和 `HAVING`，完整版：

```
FROM   →  WHERE  →  GROUP BY  →  HAVING  →  SELECT  →  ORDER BY  →  LIMIT
拿表       筛行        分组          筛组         挑列         排序         取前几行
```

**这个顺序能解释今天所有的坑**：

- `WHERE` 在 `GROUP BY` 前 → 所以 WHERE **不能筛组**、**不能写聚合函数**。
- `HAVING` 在 `GROUP BY` 后 → 所以 HAVING **能写聚合函数**。
- `SELECT` 在 `HAVING` 后 → 所以 SELECT 里的别名，HAVING 未必能看见（MySQL 扩展支持，但**别依赖**，直接用聚合函数最稳）。

## 单元六：小彩蛋 —— GROUP BY 也能去重

D5 题单里埋过一个伏笔："GROUP BY 也能去重"。现在兑现：

```sql
SELECT DISTINCT 出版社 FROM 图书;        -- 去重版
SELECT 出版社 FROM 图书 GROUP BY 出版社;   -- 分组版
```

两条结果**一模一样**（都是高教、人邮两行）。原因：分组本身就是"把相同的归一堆、每堆出一条"，等价于去重。

**记法**：想去重，日常用 `DISTINCT`（专词专用）；`GROUP BY` 去重只是它的"副作用"，考试问"下面哪个也能去重"时知道 `GROUP BY` 也算即可。
