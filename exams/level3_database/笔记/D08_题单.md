# ② 理论题检测（模块 5d · 嵌套子查询）

## 题 1【判断】子查询是什么

子查询就是"查询里再套一个查询"，内层先执行，结果交给外层使用。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 子查询 = 查询里套查询（讲义单元一）。括号里的内层先算，结果给外层。

</details>

---

## 题 2【单选】标量子查询返回什么

标量子查询返回的是（ ）。

A. 一列多值　B. 多行多列　C. 单个值　D. 一行多列

<details><summary>👉 点开对照答案与解析</summary>

**C。** 标量 = 单个值（一行一列），配 `= > < >= <=` 用。返回多行会报 1242。

</details>

## 题 3【判断】IN 的含义

`读者编号 IN ('001','002','003')` 等价于 `读者编号='001' OR 读者编号='002' OR 读者编号='003'`。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** IN = 一串 OR 的缩写（讲义单元三）。这也是"判断在不在名单里"的本质。

</details>

---

## 题 4【单选】判断"在不在名单里"

要判断某列的值"是否出现在子查询返回的一列值里"，应使用（ ）。

A. `=`　B. `IN`　C. `EXISTS`　D. `GROUP BY`

<details><summary>👉 点开对照答案与解析</summary>

**B。** IN 专管"在不在名单里"。A 的 `=` 只能配标量子查询（单个值）；C 的 EXISTS 判断"有没有行"；D 是分组，与子查询无关。

</details>

---

## 题 5【单选】`> ANY` 的含义

`借阅次数 > ANY (3, 2)` 等价于（ ）。

A. 借阅次数 > 3　B. 借阅次数 > 2　C. 借阅次数 < 2　D. 借阅次数 = 3 或 2

<details><summary>👉 点开对照答案与解析</summary>

**B。** `> ANY (3,2)` = "比任意一个大就行" = 大于最小的那个 = `> 2`。ANY 门槛低（过任意一个就通过）。

</details>

---

## 题 6【单选】`> ALL` 的含义

`借阅次数 > ALL (3, 2)` 等价于（ ）。

A. 借阅次数 > 3　B. 借阅次数 > 2　C. 借阅次数 > 3 且 > 2　D. 借阅次数 ≥ 3

<details><summary>👉 点开对照答案与解析</summary>

**A。** `> ALL (3,2)` = "比全部都大" = 大于最大的那个 = `> 3`。ALL 门槛高（过全部才通过）。注意 A 和 C 其实一个意思（>3 已经蕴含 >2），A 更简洁。对照题 5：ANY 取最小、ALL 取最大。

</details>

---

## 题 7【判断】EXISTS 判断什么

`EXISTS (子查询)` 判断的是"子查询有没有返回行"，不关心返回的具体值。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** EXISTS 只看"有没有行"（讲义单元五）。所以子查询里写 `SELECT 1` 或 `SELECT *` 都行，值用不上。

</details>

## 题 8【单选】相关子查询的特点

相关子查询（如 EXISTS 那种）的特点，下列正确的是（ ）。

A. 内层先独立执行一次，结果给外层
B. 内层引用外层表的列，外层每行都要跑一遍内层
C. 相关子查询只能配 IN 使用
D. 相关子查询一定比普通子查询慢，禁止使用

<details><summary>👉 点开对照答案与解析</summary>

**B。** 相关子查询的"相关"指**内层引用外层**（如 `借阅.读者编号 = 读者.读者编号`），外层每行都会重新执行内层。A 是普通子查询（标量/IN/ANY·ALL）的行为；C、D 编造。

</details>

## 题 9【判断】标量子查询返回多行

标量子查询如果返回多行，MySQL 会报错（1242）。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 报 1242 "Subquery returns more than 1 row"。所以配 `=` 的子查询，内层一定得是 MAX/AVG/COUNT 这类"压成一个数"的。

</details>

## 题 10【单选】NOT IN 的含义

`读者编号 NOT IN (SELECT 读者编号 FROM 借阅)` 表示（ ）。

A. 读者编号出现在借阅表里
B. 读者编号不在借阅表出现过的编号里
C. 读者编号等于借阅表的某个编号
D. 借阅表里没有读者编号这一列

<details><summary>👉 点开对照答案与解析</summary>

**B。** NOT IN = "不在名单里"（IN 取反）。配合讲义单元三的例子：它查出的是"没借过书的读者"（你库里结果为空，因为 4 人都借过）。

</details>

# ③ 代码实操（换汤不换药：讲义用"借阅次数"，这里换成"馆藏量 / 图书表"）

## 实操题 1：馆藏量最多的书

**要求**：查出馆藏量最多的书名和馆藏量（用标量子查询，不要写死数值）。

**预期输出**：
```
书名         | 馆藏量
------------|------
数据库系统概论 | 5
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 书名, 馆藏量
FROM 图书
WHERE 馆藏量 = (SELECT MAX(馆藏量) FROM 图书);
```

**要点**：标量子查询 `(SELECT MAX(馆藏量) ...)` 算出一个数 5，外层 `馆藏量 = 5` 捞出那本书。

</details>

---

## 实操题 2：馆藏量高于平均的书

**要求**：查出馆藏量高于平均馆藏量的书名和馆藏量。

**预期输出**（平均 = 14/4 = 3.5）：
```
书名         | 馆藏量
------------|------
数据库系统概论 | 5
Python编程   | 4
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 书名, 馆藏量
FROM 图书
WHERE 馆藏量 > (SELECT AVG(馆藏量) FROM 图书);
```

**要点**：内层 `AVG(馆藏量)` = 3.5，外层 `> 3.5` 筛出 5 和 4。仍是标量子查询，换了个聚合函数。

</details>

---

## 实操题 3：借阅次数 ≥ 3 的读者借过的书

**要求**：查出"借阅次数 ≥ 3 的读者"借过的书名（两层子查询嵌套）。

**预期输出**：
```
书名
----------
数据库系统概论
R语言实战
Python编程
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 书名
FROM 图书
WHERE 图书编号 IN (
    SELECT 图书编号 FROM 借阅
    WHERE 读者编号 IN (
        SELECT 读者编号 FROM 读者 WHERE 借阅次数 >= 3
    )
);
```

**要点**：三层结构。从里往外：① 借阅次数≥3 的读者 = 001/002/003；② 这些读者借的书 = B001/B002/B003；③ 查这些书的名。信息检索导论（B004）是赵六（2 次）借的，被挡在外。

</details>

---

## 实操题 4：馆藏量比"人民邮电出版社所有书"都多

**要求**：查出馆藏量比"人民邮电出版社**所有**书"的馆藏量都大的书名和馆藏量（用 ALL）。

**预期输出**：
```
书名         | 馆藏量
------------|------
数据库系统概论 | 5
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 书名, 馆藏量
FROM 图书
WHERE 馆藏量 > ALL (
    SELECT 馆藏量 FROM 图书 WHERE 出版社 = '人民邮电出版社'
);
```

**要点**：人邮的书馆藏是 3、4，`> ALL (3,4)` = 大于最大的 = `> 4` → 只有馆藏 5 的数据库系统概论。想想：如果换成 `> ANY`，结果会多出哪些书？

</details>

## 实操题 5：被借过的书（EXISTS）

**要求**：查出"被借过"的书名（用 EXISTS 相关子查询）。再想想：如果用 `NOT EXISTS` 会查出什么？

**预期输出**：
```
书名
----------
数据库系统概论
R语言实战
Python编程
信息检索导论
```

<details><summary>👉 点开折叠答案</summary>

```sql
SELECT 书名
FROM 图书
WHERE EXISTS (
    SELECT 1 FROM 借阅 WHERE 借阅.图书编号 = 图书.图书编号
);
```

**要点**：相关子查询——内层 `借阅.图书编号 = 图书.图书编号` 引用外层。外层每拿一本书，就查借阅表里"有没有这本书的借阅记录"，有就留下。你库里 4 本书**全都被借过**，所以 4 本都出。

`NOT EXISTS`（把 EXISTS 换成 NOT EXISTS）会查"没被借过的书"——结果是**空表**（没有没被借过的）。空是正确答案。

</details>

# ④ 回炉题（D4 第2轮：视图/DROP + D7 第1轮：分组）

> D4 第二轮聚焦"视图可更新性 + DROP 三口诀"；D7 昨天刚学，今天第一次回炉 GROUP BY/HAVING。

## 回 1【判断】视图的可更新性

对只涉及单个表的简单视图执行 UPDATE，改动会落到基表上。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 简单单表视图可更新（D4 题 8 / 题 13 你亲眼见过——改视图，基表跟着变）。含连接、聚合的复杂视图不可更新。

</details>

---

## 回 2【单选】删视图的语句

删除视图使用（ ）。

A. `DELETE VIEW`　B. `DROP TABLE`　C. `DROP INDEX`　D. `DROP VIEW`

<details><summary>👉 点开对照答案与解析</summary>

**D。** 三个 DROP 口诀：**删表 DROP TABLE、删视图 DROP VIEW、删索引 DROP INDEX 名 ON 表**。A 的 DELETE 只删数据行（DML），不是删对象。

</details>

---

## 回 3【判断】视图存什么

视图不存储数据，只存储定义它的查询语句。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 视图是虚拟表：每次查视图，MySQL 现场执行背后的 SELECT。基表数据变，视图结果自动变。

</details>

---

## 回 4【判断】WHERE 与聚合函数

聚合函数可以出现在 HAVING 里，但不能出现在 WHERE 里。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** WHERE 在分组前执行（组还没分出来），写 `WHERE COUNT(*) > 2` 报 1111；HAVING 在分组后执行，能写聚合函数。D7 讲义单元四的考点。

</details>

---

## 回 5【单选】筛"总馆藏量大于 5 的出版社"

要查出"总馆藏量大于 5 的出版社"，正确写法是（ ）。

A. `WHERE SUM(馆藏量) > 5`
B. `GROUP BY 出版社 HAVING SUM(馆藏量) > 5`
C. `HAVING 馆藏量 > 5`
D. `WHERE 馆藏量 > 5 GROUP BY 出版社`

<details><summary>👉 点开对照答案与解析</summary>

**B。** "总馆藏量"是分组后每组的 SUM，属"筛组"→ HAVING + 聚合函数。A 错在 WHERE 里写聚合函数；C 错在 HAVING 里写普通列；D 的 WHERE 只能筛单行。

</details>

---

## 回 6【判断】分组后 SELECT 放普通列

`SELECT 出版社, 书名, COUNT(*) FROM 图书 GROUP BY 出版社` 在 MySQL 8.0.23 会报错（1055）。对还是错？

<details><summary>👉 点开对照答案与解析</summary>

**对。** 分组后 SELECT 只能放"分组列 + 聚合函数"，`书名` 两者都不是，报 1055（ONLY_FULL_GROUP_BY 在执法）。D7 讲义单元三。

</details>
