## 题 1【判断】内连接的本质

`pd.merge(bor, rdr, on="读者编号")` 默认只保留两张表**都有**的读者编号（内连接），所以借阅表里的"孤儿记录"会在合并时被自动丢弃。对还是错？

<details><summary>答案</summary>

**对。** merge 默认 `how="inner"`：键值必须在两边都存在才保留。孤儿记录是"只在左表"的行，内连接不会留下它们。

</details>

## 题 5【代码·Python】人均借阅排行榜

merge 连接两表 → 按学院算「借阅总量 ÷ 该学院读者数」→ 降序排行。第一名是哪个学院？人均多少？用代码算出来。

<details><summary>答案</summary>

第一名**计算机，人均 426.87**——**但先别信**，这个第一是假的，原因见题 9。

```python
m = bor.merge(rdr_clean, on="读者编号")
r = m.groupby("学院")["借阅量"].agg(["sum", "count"])  # count 是借阅人次，不是读者数
# 正确姿势：读者数用 nunique
per = m.groupby("学院").agg(总量=("借阅量", "sum"), 读者数=("读者编号", "nunique"))
per["人均"] = per["总量"] / per["读者数"]
per.sort_values("人均", ascending=False)
```

</details>

## 题 6【代码·SQL】零借阅读者

用 `to_sql` 把清洗后的 readers 导入 MySQL（新表名 `reader_archive`）→ 用 `%%sql` 写一条 **LEFT JOIN**，找出"**有档案但从没借过书**"的读者有几人。

<details><summary>答案</summary>

**2 人。**

```sql
%%sql
SELECT COUNT(*) AS 零借阅人数
FROM reader_archive r
LEFT JOIN borrow_records b ON r.读者编号 = b.读者编号
WHERE b.读者编号 IS NULL;
```

</details>
