## 题 2 · 体检：先看清手里是什么数据

**目的**：分析前先确认数据长什么样——列名、类型对不对。**不看数据直接下手，等于医生不看片子就开刀**；类型错了（比如数字被读成文字），下一步求和会直接报错。

**要求**：打印 `df` 的结构，确认 5 列 148 行、`学院` 是字符型、`借阅量` 是数值型。用你 D3 学过的 `str()`。

**验收**：输出里有 `148 obs. of 5 variables`，各列类型符合预期。

<details><summary>👉 点开对照答案与解析</summary>

```r
str(df)
```

预期输出（我把你的文件跑过一遍，真实输出就长这样，数字后面的省略号是 R 自动缩略的）：

```
'data.frame':	148 obs. of  5 variables:
 $ 读者编号: chr  "R1000" "R1001" ...
 $ 学院    : chr  "信息管理" "计算机" ...
```

**解析**

## 题 3 · 按学院汇总借阅量

**目的**：本项目的第一个业务问题——"各学院借阅总量谁高谁低"。这一步的产物 `agg` 就是 R 段的核心结果表。

**要求**：用 `aggregate()` 算出每个学院的 `借阅量` 总和，存到变量 `agg`，然后打印它。

**提示**：D4 学过的公式写法 `y ~ x`（读作"y 按 x 分组"），别忘 `data = ` 和 `FUN = `。

**验收**：输出 5 行（5 个学院各一行）。

<details><summary>👉 点开对照答案与解析</summary>

```r
agg <- aggregate(借阅量 ~ 学院, data = df, FUN = sum)
agg
```

预期输出（排序是乱的，下一题解决）：

```
      学院 借阅量
1     法学   3451
2   计算机   2625
3     历史   2461
4     文学  13191
5 信息管理   3958
```

**解析**

- `借阅量 ~ 学院` 读作"借阅量 按 学院 分组"，`FUN = sum` 是每组套用的函数。**公式 + data + FUN，这三件套就是 aggregate 的全部。**
- 和另外两种语言对照——同一个动作，三种说法：SQL 是 `SELECT 学院, SUM(借阅量) ... GROUP BY 学院`；pandas 是 `df.groupby("学院")["借阅量"].sum()`。你 SQL 那一步已经得到过完全相同的数字（文学 13191 那条），**现在两边互相印证**——对上了，说明接力没掉棒。

</details>

## 题 4 · 让结果按总量降序排列

**目的**：结论要一眼可见。报告里没人愿意自己找最大值在哪——**排序本身就是分析表达的一部分**。

**要求**：把 `agg` 按 `借阅量` 降序重排，存回 `agg`（覆盖即可），打印。

**提示**：D3 学的 `order()`；降序加负号 `-`。注意 `order()` 只给你"排好的行号"，还要拿行号去取行。

**验收**：输出第一行是 `文学 13191`。

<details><summary>👉 点开对照答案与解析</summary>

```r
agg <- agg[order(-agg$借阅量), ]
agg
```

**解析**

- `order(-agg$借阅量)` 返回"排好序的行号"，`-` 表示从大到小；再用这个行号去取行，就给 data.frame 重排了。**R 里给数据框排序永远是这两步：order() 出行号 → 用行号取行。** D3 学的知识点，这次在真实数据上用一遍。
- 效果：`文学 13191` 直接怼到第一行——异常的数值自己跳出来了。

</details>

## 题 5 · 画柱状图（基础版）

**目的**：把数字变成图。这是 R 段的最终交付物，也是报告里最抓眼球的部分。

**要求**：用 ggplot2 画柱状图：x 轴是学院，y 轴是借阅总量。**用你汇总好的 `agg` 画**。

**提示**：老朋友三件套——`ggplot(data, aes(x = , y = )) + geom_???()`。柱子用 `geom_col()`（col = column）。`library(ggplot2)` 如果本子前面没加载过就补一句。

**验收**：出现 5 根柱子。

<details><summary>👉 点开对照答案与解析</summary>

```r
library(ggplot2)

ggplot(agg, aes(x = 学院, y = 借阅量)) + geom_col()
```

**解析**

- 为什么是 `geom_col()` 不是 `geom_bar()`？**geom_bar() 是替你数个数**（一行算 1 个），**geom_col() 是直接拿你给的数当柱子高度**。你已经汇总好了数字，所以用 col。
- 关键理解：**画图要用 agg（5 行），不能用 df（148 行）**。要是把 148 行直接丢进去，柱子高度看着也对（每行的柱子叠起来正好是总和），但排序会按"平均值"算，画出一张"看着对、逻辑错"的图——这是 ggplot 最阴的坑之一。走"先汇总、再画图"的正路，就不会踩。
- **最容易踩的坑（我踩过）**：包叫 `ggplot2`（带 2），但**画图的函数叫 `ggplot`（不带 2）**。写成 `ggplot2(...)` 会报 `could not find function "ggplot2"`——这不是"没装包"，是函数名写错了。判断口诀：报错说 `could not find function` 是**名字错**；说 `there is no package called` 才是**真没装**。
- 现在图是灰色的、没标题，下一题美化。

</details>

## 题 6 · 让这张图能进报告（配色 + 排序 + 标题）

**目的**：基础版只是"能看"；报告里的图要"能讲结论"——柱子从高到低排，读者一眼看出差距；有标题和坐标轴名，图就不需要你在旁边解释了。

**要求**（三处修改）：

1. 柱子按总量从高到低排（提示：`reorder()`，D4 见过；降序加 `-`）
2. 换个颜色：`geom_col(fill = "steelblue")`（或你喜欢的英文颜色名）
3. 加标题和坐标轴名：`labs(title = , x = , y = )`

**验收**：5 根柱子从高到低，图上有标题。

<details><summary>👉 点开对照答案与解析</summary>

```r
ggplot(agg, aes(x = reorder(学院, -借阅量), y = 借阅量)) +
  geom_col(fill = "steelblue") +
  labs(title = "各学院借阅总量", x = "学院", y = "借阅量") +
  theme_minimal()
```

**解析**

- `reorder(学院, -借阅量)` = "把'学院'这个分类轴，按借阅量重新排队"，`-` 降序。**注意分工：排序数据框的行用 `order()`，排序图上的轴用 `reorder()`**——两个函数名字像、用途不同，D4 的图里出现过 reorder，这次用真实数据再练一遍。
- `theme_minimal()` 去掉灰色底，报告里更干净。
- 我实测过你这份数据的出图顺序：**文学 13191 › 信息管理 3958 › 法学 3451 › 计算机 2625 › 历史 2461**。你的图应该一模一样。
- 效果对比：把这张和上一题的基础版并排看一下——**同一份数据，表达力完全不同**。这就是"分析表达"值钱的地方。

</details>

## 题 7 · 思考题：这张图在向你报警

**目的**：真正的分析师不是画完图就交差，而是**盯着图问一句"这合理吗"**。

**背景**：图上看，文学的柱子高得离谱——13191，是第二名（信息管理 3958）的 3 倍多。可疑。

**要求**（两步）：

1. 用代码找出 `借阅量` 最大的那一行（提示：`max()` 看最大值；或逻辑筛选 `df[df$借阅量 > 5000, ]` 看有哪些行）
2. 用一句大白话说出你的怀疑（可以写在旁边的 Markdown 格里，也可以直接发我）

<details><summary>👉 点开对照答案与解析</summary>

```r
max(df$借阅量)
df[df$借阅量 > 5000, ]
```

输出告诉你：最大值是 **9999**，而且全校只有 **1 行**超过 5000。

**解析**

- 9999 这种"整数关口"的数字，在真实数据里几乎可以断定是**异常值**（录入时的占位符/测试值），不是真实借阅量。
- 算笔账：文学去掉这一行是 13191 − 9999 = **3192**，排名从第 1 跌到第 3（在信息管理 3958、法学 3451 之后）。**一个脏数据，能把整个结论带偏。**
- 更值得琢磨的是：这个 9999 **是你 Python 清洗那一步放过去的**——四件套里删了负值（-5），但没管异常大的值。这不是批评，这正是下一课要学的：**清洗不只处理"缺"和"错"，还要处理"假"。**
- 所以这张图不只是项目产出——**它本身就是一次数据质量检查。可视化是最好的体检工具。**

</details>
